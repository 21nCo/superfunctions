`getSchema()` in `@billfn/core` currently returns version `4` with fourteen table definitions.

## Tables

| Table | Purpose |
| --- | --- |
| `billingAccounts` | Stable internal owners for user or organization billing state |
| `subscriptions` | Normalized provider subscription snapshots |
| `checkoutSessions` | Checkout lifecycle and provider reference ids |
| `entitlementSnapshots` | Current feature and limit projection for an account |
| `usageMeters` | Current usage per billing account and resource |
| `usageLedger` | Append-only usage deltas |
| `webhookReceipts` | Dedupe and audit trail for provider webhook deliveries |
| `billingEvents` | Internal normalized billing event stream |
| `refunds` | Normalized refund and revoke operations |
| `subscriptionChangeRequests` | Subscription change intent and fallback tracking |
| `reconciliationJobs` | Operational replay and sync jobs |
| `reconciliationCursors` | Provider backfill cursors |
| `unlinkedWebhookEvents` | Verified webhook events waiting for their provider reference to be linked, kept 90 days |
| `replacedProviderReferences` | Provider references a subscription write dropped, so no event naming them bootstraps another subscription |

## Important Indexes

Phase 1 relies on a few critical indexes:

- `subscriptions.provider + providerSubscriptionId` as a unique provider reference
- `subscriptions.provider + providerChargeId`
- `checkoutSessions.provider + providerCheckoutId`
- `checkoutSessions.provider + providerSubscriptionId`
- `checkoutSessions.provider + providerChargeId`
- `entitlementSnapshots.billingAccountId` as a unique current snapshot
- `usageMeters.billingAccountId + resource` as a unique usage meter
- `webhookReceipts.provider + providerEventId` as a unique dedupe key
- `unlinkedWebhookEvents.provider + providerEventId` as a unique dedupe key
- `unlinkedWebhookEvents.provider + providerReference + status` and `provider + providerSecondaryReference + status` for replay on link
- `unlinkedWebhookEvents.expiresAt` for the 90-day retention purge
- `replacedProviderReferences.provider + providerReference` as a unique key

## Example

```ts
import { getSchema } from "@billfn/core";

const schema = getSchema();
console.log(schema.version);
console.log(schema.schemas.map((table) => table.modelName));
```

The Python SDK mirrors schema version `4`. Both helpers expose the same fourteen logical model names and mark record identifiers as unique.

## Migrations

### Schema 3 to 4 (`@billfn/core` 0.2.0)

Version `4` adds two tables, `unlinkedWebhookEvents` and `replacedProviderReferences`, and changes no existing table. Create both with their indexes before deploying `@billfn/core` 0.2.0: webhook processing writes to `unlinkedWebhookEvents` as soon as an event names a provider reference BillFn has not linked, and every subscription write that drops a provider reference writes to `replacedProviderReferences` first. The migration is additive, so rolling back to 0.1.x leaves the tables unused.

| --- | --- | --- |
| `id` | string, unique | yes |
| `provider` | string | yes |
| `providerEventId` | string | yes |

| `providerSecondaryReference` | string | no |
| `eventType` | string | yes |
| `occurredAt` | string | no |
| `reason` | string | yes |
| `metadataBillingAccountId` | string | no |
| `status` | string | yes |
| `event` | json | yes |
| `replayClaimId` | string | no |
| `replayClaimedAt` | string | no |
| `replayedAt` | string | no |
| `subscriptionId` | string | no |
| `error` | string | no |
| `expiresAt` | string | yes |

Indexes: unique `unlinked_webhook_events_provider_event_idx` on `provider, providerEventId`; `unlinked_webhook_events_provider_reference_idx` on `provider, providerReference, status`; `unlinked_webhook_events_provider_secondary_reference_idx` on `provider, providerSecondaryReference, status`; `unlinked_webhook_events_expires_idx` on `expiresAt`.
