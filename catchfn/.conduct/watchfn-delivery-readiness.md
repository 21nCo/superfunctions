# CatchFn canonical WatchFn delivery checkpoint

2026-10-20 UTC. CatchFn now accepts `watch: { endpoint, apiKey, ...transportOptions }` and constructs the shared `@watchfn/browser` client with automatic RUM disabled. Explicit bug capture bypasses sampling and DOM availability, preserving the canonical envelope. Existing injected capture clients remain supported. The endpoint path defaults to 64 KiB and rejects configured limits above WatchFn's per-event ingestion ceiling. Larger attachments require upload references.

Capture awaits shared authenticated delivery. Transient statuses/network failures use the existing bounded retry mechanism; authorization failures reject without automatic retry. Failed reports remain queued for explicit `flush()` recovery. Retrying `captureBug()` creates another report, so flush is the retry operation for an already queued report. Delivery is at least once; a successful insert followed by a lost response produces duplicate arrivals with the same report ID. There is no deduplication claim.

The CatchFn branch includes the WatchFn prerequisite and its current shared DB prerequisite; the CatchFn PR is stacked on the WatchFn branch so those changes are not duplicated in its diff. WatchFn validates canonical bug reports before ingestion and persists the unchanged envelope in its normal datastore. The separate flat-report CatchFn service remains available but is not the storage path used by this transport.

Validation:

- CatchFn SDK build/declarations and typecheck pass. All 83 SDK tests pass, including endpoint/authentication mapping without a DOM and payload ceiling validation.
- `scripts/watchfn-acceptance.mjs` exercises built CatchFn and WatchFn through actual loopback HTTP, bearer authentication and shared Kysely/SQLite persistence. It validates transient retry with an unchanged body, canonical report/query fields, final-hook redaction, nonretryable401, lost response duplicates, close/reopen persistence and dropped-table503 failure. Temporary servers, files and connections are removed.
- The native command used Node20.20.0 and `CATCHFN_WATCH_CORE` pointing to the built WatchFn prerequisite checkout. WatchFn was rebuilt after merging the latest shared DB prerequisites; its147 coretests passed. CatchFn's local full WatchFn build initially lacked optional framework adapter dependencies; the explicit built-prerequisite path avoids implying those framework builds passed in the CatchFn checkout. Browser transport and CatchFn builds ran in the CatchFn checkout itself.
- Native acceptance requires built shared DB, Kysely and a working better-sqlite3 binding. Build WatchFn in a checkout with its framework adapter prerequisites, or set `CATCHFN_WATCH_CORE` to that build's `index.mjs`. Run `node catchfn/typescript/scripts/watchfn-acceptance.mjs` from the repository root. Generated artifacts are excluded; no ignore changes are needed.

Remaining original gates include deduplication/atomic ingestion, application indexes and retention overrides, attachment channel provisioning, BotFn issue linking, Python transport parity/historical Python support, browser-hosted CORS/unload/offline acceptance, performance/accessibility and deployment. This is partial progress, not full readiness or a release.
