# Supervised remote checkout checkpoint

The original 2026-02-05 specification RUN-007 requires checkout at the trigger ref and a clone-root workspace for subsequent steps; PIPE-003 includes checkout among supported step types. Before this change, `executeRemoteShellJob` rejected all `uses` steps before any step transition. The owned regression reproduced that failure (`/tmp/cifn-checkout-baseline.log`). The legacy checkout helper also interpolated repository/ref into a synchronous shell command.

Remote execution now permits checkout alongside shell steps. The existing owned POSIX process supervisor has an argv entry point; shell execution remains its wrapper. Git init, fetch and detached checkout use it, with one 120-second operation budget, existing output bound, cancellation/group termination and uncertain-ownership behavior. Step transitions retain the existing awaited durable journal/transport path. The public synchronous helper preserves its return type with safe argv calls, while Runner uses the asynchronous supervised helper.

Repository/ref/token expressions resolve from the accepted snapshot. Explicit ref wins, then trigger SHA/ref, then pipeline ref, then HEAD. Raw GitHub webhook `after/ref/repository` and normalized manual `github` payloads are supported. Exact safe GitHub owner/repository shorthand becomes HTTPS; other network repositories require HTTPS without URL credentials/query/fragment. Local absolute paths need trusted host opt-in, disabled in the built runner. Option-like/ext/helper/SSH transports and redirect following reject. Full commit IDs, branches, annotated tags and HEAD are exercised. Submodules/LFS are not initialized. Cross-repository overrides should provide an explicit ref.

The helper uses isolated HOME/global/system configuration, disabled hooks/credential helpers and a private askpass script containing no credential. Token values exist only in the owned Git subprocess environment, never URL/argv/remote configuration/log diagnostics; raw Git output is not forwarded. A workspace with an existing `.git` (including dangling symlinks) rejects. Local fixture repositories are explicitly trusted. This is not OS filesystem/process isolation or a physical repository-size quota.

On confirmed normal exit/cancellation, helper resources are removed. On uncertain process-group disappearance, workspace/helper evidence is retained and the existing started-execution protocol refuses automatic replay. An unconfirmed surviving process may retain environment credentials; there is no false hard-erasure claim. This checkpoint does not add arbitrary process killing from persisted IDs.
