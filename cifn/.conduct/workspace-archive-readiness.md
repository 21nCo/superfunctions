# Workspace archive confinement

Source baseline: `cf15a21074f4fec88b0b162b52d543ada17e70fc`. Original 2026-02-05 RUN-005/006 require workspace artifact/cache operations, and INT-002 requires FileFn backing. The original local helpers followed source links/traversal and wrote unvalidated extraction paths. `/tmp/cifn-archive-baseline.log` records all three initial malicious filesystem cases failing their safety assertions: outside source upload, outside extraction overwrite and preexisting symlink overwrite. Fixtures used only private owned files.

The four helpers now share one Ci-specific codec and path implementation, preserving the wire format and valid local behavior. All manifest entries, ranges, paths, aliases, prefix conflicts and existing targets validate before writes. No-follow regular-file descriptors reject hardlinks before truncation. Directory traversal/read/manifest/output counts are bounded by trusted configurable policy; extraction includes distinct parent directories in the entry budget. Zero-progress writes fail rather than spin. Public errors do not copy arbitrary provider error text. Runner passes its host archive policy through all four paths.

Default limits are documented in README as implementation resource policy, not original requirement thresholds. POSIX/no-follow support is explicit; Windows fails closed. This is static malicious archive/preexisting-link hardening, not protection against concurrently hostile workspace mutation. In particular, job-created background processes need an independent isolation strategy. File-level I/O failures may leave partial valid extraction; provider Buffer/network allocation before this helper is not bounded by these caps.
