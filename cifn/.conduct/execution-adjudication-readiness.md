# Explicit execution adjudication checkpoint

Original 2026-02-05 RUNNER-005:325 requires reported/persisted job results; RUN-001:213 forbids reversing terminal states. Neither requirement authorizes interpreting a stale heartbeat as stopped execution or blindly replaying a started job. The existing native remote-log fixture demonstrates the concrete gap: it kills an owned runner, independently releases/observes its orphan shell exit, restarts recovery twice, and still has a running run/step plus a `started` journal without a result. That uncertainty is intentionally safe.

This slice adds host-only `inspectExecution` and `adjudicateExecution`. Inspection projects the exact owner identity, redacted job and step states, and a fingerprint over relevant claim/protocol/terminal/step evidence. It excludes claim credentials, scripts, environment and secrets. Log/telemetry revision churn does not invalidate the fingerprint; changed execution ownership, cancellation and step evidence do.

A decision requires a bounded actor/decision ID, explicit stopped-owner assertion, evidence category/reference/SHA-256 digest/epoch-ms observation time, and exact terminal result. The library does not fetch evidence, validate arbitrary external supervisors or infer exit from time. Trusted operators are responsible for the assertion. There is no HTTP operator route, additional remote command, process kill, reassignment or automatic rerun.

The existing completion validator and actual dependency transition code are shared by runner completion and operator adjudication. One immutable encrypted receipt commits with the job/run changes, notification intent and lifecycle events under the existing shared-adapter CAS. Exact decision replay is idempotent; differing decision metadata, result or identity conflicts. Concurrent runner results, operator decisions and cancellation cannot overwrite each other. An already-cancelled run permits only stopped-owner acknowledgement, with no invented step result or terminal reversal.

Receipt size is bounded by fixed fields and at most 100 canonical step keys/statuses; at most one receipt exists per dispatch. No unbounded notes/evidence bodies are retained. Known configured secrets in attribution fields reject. Global run-history/disk retention remains a host responsibility. Old writers must be drained; no retroactive binary fence is claimed. Local runner evidence remains unchanged after a host decision, and no assertion of autonomous crash result recovery is made.
