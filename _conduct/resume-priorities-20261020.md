3. **RecFn REC-001 valid recording media.** Original requirements `recfn/.conduct/specs/2026-02-28-new-r7k4m2x9-spec/REQUIREMENTS.md:142–151` specify MP4 or WAV/OPUS. `server/src/recording/capture.ts:19–55` concatenates bytes and labels the result wav/mp4 without encoding/muxing; worker `:137–150` supplies an audio stream. Establish actual input encoding, implement bounded container/codec processing and independently decode stored/downloaded outputs to verify codec, duration, channels, sample rate and cleanup. Nonempty arbitrary bytes are not recording acceptance.
4. **CiFn RUNNER-005 remote step logs.** Requirements `cifn/.conduct/specs/2026-02-05-new-c8f2n1xq-spec/REQUIREMENTS.md:323–329,421–428`. `runner/src/remote-runner.ts:24` uses temporary MemoryLogFnClient; completion and persistence keep only statuses; GET logs can return empty success. Add authenticated claim/execution-fenced bounded redacted batches, stable sequence/digest, durable spool and receipts, verified actual LogFn integration and replay without shell reexecution. Log transfer pending/complete/truncated/failed state must be separate from run status. Define retention/expiry, caps/backpressure and confidentiality before persistence, including multiline/chunk-boundary redaction. Accept using actual HTTP/SQLite and lost ACK/restart/concurrent/stale identity cases.
5. **WatchFn configured alert execution.** `watchfn/SPEC.md:1068–1106` requires metric/window conditions and real channels. `typescript/src/alerts/alert-manager.ts` stores in-memory configurations and manual trigger callbacks; acknowledge/addNote are stubs. `core/watch-fn.ts:96` binds that manager, while separate AlertEvaluator is not wired. `alerts/channels/email.ts:39` only prints.
