# HTTP session lifecycle and protocol-error review followup

Candidate source changes address security review D2, D11, D13, D14 and followup F1/F3. This is source qualification; the final rebuilt package/release gate must run against this candidate.

- Numeric error codes alone no longer identify protocol errors. Profile-hook failures require `Error.name === "McpError"` and a safe integer code; independently installed SDK errors retain interoperability. DOMException/backend numeric errors become tool failures.
- Session owner equality includes anonymous ownership and optional verified issuer. A session cannot change from anonymous to authenticated. Authenticated identity still requires stable nonblank subject and nonempty clientId; optional tenant/region values must be strings (matching shared AuthSubject and MCP principal types). Optional issuer must be a nonblank string. Invalid verified identity returns 403, avoiding an SDK reauthentication loop for a verifier configuration error. Multiissuer verifiers must supply their verified issuer or namespace subjects; core does not parse unverified request claims.
- Live IDs are reserved before the asynchronous initialization callback. Live collision failure cannot overwrite or delete another session. Retired ID history is intentionally not retained: secure custom generators must never reuse IDs, including across durable task-store lifetimes.
- Each stateful handler defaults to 1024 total retained sessions/pending initialization reservations and 30-minute idle expiry. Positive integer options are validated; timeout is limited to the portable timer range. Excess initialization receives 503. Reservations precede awaited configuration; failed attempts release them.
- In-flight requests and open SSE responses postpone idle expiry. Stream completion/cancellation releases activity exactly once. Background tasks without active HTTP responses require polling within the idle timeout. The hard capacity still bounds long-held streams and pending configuration hooks.
- Parent close marks handlers closed, clears owned idle timers, and releases sessions before asynchronous close work. Late configuration/initialization callbacks cannot resurrect a session.

Validation on Node 22.13, one Vitest worker: `tests/server.test.ts` and `tests/http-session-limits.test.ts`, 47 tests passed. New lifecycle tests cover anonymous/auth transitions, cross-issuer identity, concurrent duplicate IDs, pending initialization capacity and failure, long-held GET SSE with concurrent ping, initialization-body cancellation, idle expiry freeing capacity, parent close during configuration and during initialization callback, and invalid option values. The foreign SDK error fixture now uses the real SDK's `name: "McpError"` discriminator; two new cases exercise DOMException and database-style numeric codes.

Logs: `/tmp/mcp-session-security-limits-20261028.log` and `/tmp/mcp-session-security-typecheck-20261028.log`. Final core typecheck and scoped whitespace checks passed. The full rebuilt gate remains for the coordinator. No installation, build, publishing, or external resources were used for these focused checks.

Limitations: capacity is per handler; it does not rate-limit requests or cap active request count within an existing session. An application hook that never settles can retain a bounded pending reservation until parent close. Hosts must propagate downstream disconnection by cancelling streaming response bodies. Idle expiry does not remove durable task-store records. Reusing retired IDs remains prohibited by contract, not tracked with an unbounded history set.
