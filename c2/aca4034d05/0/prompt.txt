## 📦 Package Naming Conventions

### Rule A: Shared Packages Format

**Any package shared across superfunctions uses `@superfunctions/{name}` format**

```
packages/http/        → @superfunctions/http
packages/auth/        → @superfunctions/auth
packages/cli/         → @superfunctions/cli
```

### Rule B: Core Function Packages Format

**Single-package functions**: Use simple name without scope

```
authfn/ts-sdk/        → authfn
drawfn/core/          → drawfn
cachefn/typescript/   → cachefn
plugfn/core/         → plugfn
searchfn/             → searchfn
```

**Multi-package functions**: Use `@{functionname}/{sub-package}` format (if needed in future)

```
@authfn/core          (example for future multi-package structure)
@authfn/providers     (example for future multi-package structure)
```

**Current Status**: All core functions currently use single-package structure. The scoped format is reserved for future expansion if a function needs multiple published packages.

### Rule C: Monorepo Structure

**The root `superfunctions` is a Turbo monorepo. Avoid nested monorepos.**

- ✅ Use subfolders to organize functions (e.g., `authfn/python/`, `authfn/ts-sdk/`)
- ❌ Do NOT create nested monorepos (e.g., `authfn/` should NOT be another monorepo)
- ✅ Use Turbo workspaces defined in root `package.json`

## 🚀 Best Practices

### Super functions ecosystem (Very important)

- Reuse shared packages from `packages/` folder like http abstraction, db abstraction, etc.
- Never duplicate shared code like http adapters, db abstractions, etc.
- Don't reexport http-adapters etc - end consumers of the core function package will use the adapters directly. Refer `authfn` implementation for usage of core http router, core db, http adapters and db interface usage.
- Function packages that accept a `@superfunctions/db` `Adapter` must wrap the incoming adapter internally with their own schema, for example `wrapWithSchema(config.database, getSchema(...))`, before passing it to services/storage. Do not require app consumers to pass `adapterSchema` to `drizzleAdapter`, `kyselyAdapter`, `prismaAdapter`, or `memoryAdapter`; `adapterSchema` is a deprecated compatibility escape hatch for direct app-level adapter use.

### Code Organization

- Keep shared code in `packages/`
- Keep function-specific code in `{function}/`
- Use TypeScript for type safety
- Provide Python SDKs for backend-focused functions
- Write comprehensive tests
