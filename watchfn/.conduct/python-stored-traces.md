# Python stored trace integration

`WatchFn.trace` now exposes the existing tracer with `start_span`, `finish_span`, the `trace` context manager, and stored `query`, `get_trace`, and `get_service_map` methods. Query option keys and returned canonical span fields match the TypeScript stored-trace API. Python method names retain normal snake case.

Finishing an owned span records it once under concurrent finish calls. The context manager records successful and failed operations. Recording retains the original start/end timing on a failed callback retry. Identifiers use secure random hexadecimal IDs. Span input tags and recorded properties are copied, and successful recording removes the active span. The WatchFn recorder rejects inactive storage rather than silently treating an unrecorded span as complete. A shared admission fence orders trace enqueue before shutdown closes admission and flushes, without holding the fence across storage or lifecycle callbacks. A held-enqueue/concurrent-stop regression verifies the admitted span reaches storage.

New records include canonical IDs, parent IDs, operation name, start/end times, duration, configured service and boolean error tags. Legacy `trace_id`, `span_id`, `parent_span_id`, `operation` and `status` fields remain alongside canonical fields. Existing records from the disconnected legacy tracer lack start/end timestamps; no timestamps or relationships are invented for them. A custom standalone tracer callback remains responsible for ambiguous failures after its own external side effects.

Queries use stored events only and do not flush or join delivery. Explicitly flush the batcher before querying newly recorded spans. They support operation, trace ID, service, status, duration, event time range, order and limit. Details optionally include copied spans and stored correlated log events. Maps derive cross-service edges only from parent IDs within the same trace. Duplicate IDs and result overflow fail instead of producing partial details/maps. Internal trace detail collection allows the 10,001-row overflow sentinel; the public generic query limit remains 1,000. Generic collection and physical storage scans remain unbounded; these result checks are not a disk/memory quota.

Validation covers memory and real SQLite, concurrent finish calls, callback errors and retries, error traces, result isolation, stored log correlation, cross-trace parent isolation, windows and invalid input, duplicate identity, capacity rejection, database reopen and trace queries inside lifecycle callbacks that write notes. Normal Python CI passes all 218 tests in 25.64 seconds; a fresh six-wheel Python 3.12 installation passes the same 218 tests in 27.30 seconds. Receipts: `/tmp/watch-python-traces-final-ci.log` and `/tmp/watch-python-traces-final-wheel.log`. Both commands exited zero. Deprecation warnings remain, including repeated naive-datetime warnings from the 10,001-row capacity fixture. The earlier 217-test runs preceded the shutdown regression and are not the final evidence.

Automatic distributed-context propagation, historical legacy-span migration, implicit task-local parenting, full trace retention/scan bounds and the broader original readiness requirements remain open. This change does not establish full production readiness.
