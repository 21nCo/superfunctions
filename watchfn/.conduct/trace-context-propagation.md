# Explicit trace context propagation

Original scope: WatchFn SPEC section6, distributed tracing. Both SDKs now connect validated inbound context to real spans and expose outbound headers from the current span. This is a concrete explicit integration path; automatic instrumentation, baggage and sample-rate enforcement remain unfinished.

The implementation follows the [W3C Trace Context level1 recommendation](https://www.w3.org/TR/2021/REC-trace-context-1-20211123/), sections3.2–3.3. Invalid ID lengths/case, zero IDs, invalid version/flags, duplicate parents, newline injection and oversized fields are rejected without parser exceptions. Higher versions use their known prefix and downgrade outbound headers to00. Only the level1 sampled flag is retained. Tracestate supports ordered repeated header fields, bounded grammar and duplicate-key validation; invalid state is dropped without discarding a valid parent. Fields are capped at512 characters and32 state members. Explicit injection validates before mutation and removes stale case variants. IDs are generated with platform cryptographic randomness.

TypeScript `watch.trace.startWithHeaders(name, headers, callback)` creates a real child of a valid inbound parent, or an independent root for invalid input. `injectHeaders` reads the current callback span, with an optional explicit active span. AsyncLocalStorage keeps concurrent callbacks separate. Child spans inherit flags and state. A different explicit trace ID no longer inherits an unrelated ambient parent.

Python `watch.trace.with_headers` and `watch.trace.trace` establish ContextVar scopes, including across awaits. `inject_headers` uses the active scope or explicit active span. Scope cleanup restores prior context on success, exceptions and cancellation. Both SDKs reject outbound context from completed spans and avoid treating completed inherited scopes as active parents for late tasks. Manual local IDs remain supported; outbound injection requires valid wire IDs.

Validation includes shared wire vectors consumed by both languages, real TypeScript loopback HTTP with concurrent requests and recorded remote child spans, Python concurrent task scopes, explicit parent override, late inherited contexts and cancellation cleanup. Detached transaction children retain transaction flags/state even under a different ambient parent. Header collection stops at the second parent or over-budget state before constructing a combined string. Getter/iterator regressions assert no further input is consumed after those bounds.

Limits: host application code must pass headers to its HTTP client/server boundary. No automatic HTTP patching is installed. Flags are propagated but do not suppress recording; the original configured sampling requirement remains open. Baggage, complete original manual API syntax, framework instrumentation matrices, physical scan/retention bounds and hosted deployment acceptance remain open. No claim of full distributed-tracing or production-readiness completion is made.
