# LogFn ingestion and scalar log indexes

Implementation checkpoint, October 25, 2026. This does not establish full WatchFn production readiness.

WatchFn attaches to the actual LogFn sink registration API. Registrations observe existing and future children, detach on stop, resume on restart and wait for admitted writes. Explicit removal unregisters future observation; callers must flush buffering producer sinks before manual removal. Storage errors are retained by both producer flush and WatchFn flush. Conversion failures occur before WatchFn admission and are reported by LogFn flush.

Structured JSON messages receive the existing LogFn default redactor before being stored as text or properties. Canonical log fields cannot be replaced by structured-message routing fields. Index policy is copied and validated; scalar equality uses typed SHA-256 keys shared with Python. Residual query predicates always recheck payloads. Memory storage owns detached log copies and removes index membership on eviction. Shared database adapters atomically persist payload and index rows; the legacy insertEvent bridge rejects indexed writes.

Existing physical schemas require the nullable event `logIndexFields` column and the `watchfn_log_index` table returned by getWatchFnSchema, including its lookup and event indexes. Apply migrations before attaching writers. Existing rows without coverage and rows with a different field policy remain query candidates. With all writers stopped, backfillLogIndexes processes bounded atomic pages until nextCursor is null. Retention deletes payload and secondary entries together. Index equality queries cap metadata at 10,000 rows and 16 MiB, individual fetched payloads at 64 KiB and total fetched payloads at 16 MiB; exceeding a cap fails explicitly. General query paths still have their previously documented physical-scan limits.

Validation: 357 TypeScript source tests and typecheck pass. Native SQLite acceptance (`npm run test:log-index --workspace @watchfn/core`) uses real tables/indexes, verifies EXPLAIN SEARCH and exactly three payload SELECTs for 42 metadata rows, injects an index-write rollback, backfills bounded pages, retries and reopens the database. Log identity for retention, immutable memory copies, legacy bridge rejection, lone-surrogate rejection, input/normalized size limits and bounded backfill are covered. Normalized event and batch budgets are checked before admitting any attached batch, preventing successful ingestion of envelopes that indexed queries cannot read.

Python normal CI and seven freshly installed wheels pass 291 tests on Python 3.11.14. Canonical TypeScript log envelopes receive narrow validated mapping; unrelated custom envelope types remain rejected. A real SQLite REAL receipt column exposed a driver numeric representation mismatch, corrected by validating finite nonnegative integral safe receipt values. A killable subprocess exposed reentrant storage-callback logging deadlock; per-thread delivery guards now reject it before lock acquisition. Python owns no retention API; applications must delete secondary rows with externally removed payloads. See the Python integration receipt for commands, evidence and limits.
