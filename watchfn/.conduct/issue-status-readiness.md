# Bounded issue-status reads

`POST /issues/status` is a read-only companion to canonical bug intake. It uses the same configured Watch API-key authority as ingestion/query; it does not provide an ingestion-only key, per-app authorization, operator reconciliation or any mutation. The request is a strict `{app,reportId}` object capped at 4 KiB; invalid input returns 400/413, unauthorized input 401 before body parsing, absent records 404, and unavailable integration/storage 503. Successful no-store responses expose only app/report, target, state and verified linkage, with a 16 KiB serialized ceiling. Provider destination and URL checks remain enforced before linked status is returned.

`BrowserClient.readBugIssueStatus(reference,{signal})` performs one authenticated request without queue mutation or automatic retry. It derives `/mount/issues/status` only from an exact `/mount/ingest` URL with no query/hash; other ingestion routes require explicit `issueStatusEndpoint`. Relative URLs resolve against browser location. Existing dynamic headers/API keys are reused. The method caps streamed response bytes at 16 KiB, validates reference binding and state/link coherence, and accepts linked HTTPS GitHub/Linear issue URLs only for the returned target. It rejects redirects, malformed replies and dangerous links. Missing records return null; authorization/unavailability failures remain errors.

Timeout covers fetch and body consumption even if a custom fetch ignores AbortSignal. External abort and client close reject outstanding reads promptly; late responses are canceled/ignored. This bounds waiting and retained response bytes, not transport behavior under a noncompliant fetch implementation. The same full Watch key authorizes all routes and queries: use an authorized application-backend proxy if browser exposure is unsuitable.

Validation: four focused core HTTP tests cover strict/authenticated bounded requests, absence/pending/linked states, no-store responses, reference separation and disabled integration. Fifteen browser tests cover mounted endpoint derivation, explicit override, refreshed authentication, absence/errors, forged or unsafe receipts, byte limits, timeout, close and ignored-signal cancellation. Full browser suite 30 tests and its CJS/ESM/IIFE/declaration build pass; core 170 tests, source typecheck and dual-format/declaration build pass. Hosted providers and the broader original readiness gates remain open.

Fresh browser/CatchFn tarball consumers additionally validate public status types and polling in ESM and CommonJS with strict Node16/NodeNext declaration emission; the integrated native Chrome fixture validates the default mounted status route and visible delayed issue link. See CatchFn `issue-link-readiness.md`.
