# Stored log pattern discovery

Validated checkpoint against original SPEC section7; broader log-pattern scope remains open. The old TypeScript detectPatterns implementation returned an empty array for every stored event and even while stopped. Two real stored-event regressions failed against that implementation before changes.

Discovery now uses stored canonical log rows and the existing query time-window semantics. It finds deterministic templates by replacing standalone ASCII decimal/exponent numbers and UUIDs with typed variable tokens while preserving literals and ASCII identifier digits. ASCII whitespace is normalized. Literal '<' and backslash characters are escaped in the display template, and stable IDs hash field plus structured tokens so literal placeholder text cannot collide with inferred variables. Fields remain separate; counts are per event per field. Results include full counts, earliest/latest timestamps and at most three deterministic original samples. Templates are deterministic summaries, not inferred executable regular expressions or alert definitions.

The requested window is counted completely or fails explicitly. Candidate event count10000, total payload16MiB, individual event64KiB, field16KiB, groups10000 and returned patterns1000 are bounded. The TypeScript path requires streaming storage and rejects the legacy collect-all bridge. Provider query planning can still perform physical work beyond yielded candidates; these limits do not prove server IO/latency guarantees. Python storage retains its own existing scan limits. Default fields are message and default minimum occurrences5. Up to8 distinct validated fields are accepted.
