# Deployment comparison checkpoint

`watch.compareDeploymentMetrics` now computes stored before/after samples instead of returning fixed zero increases. It requires one unambiguous `deployment.completed` timestamp for the supplied deploymentId. Record that ID with the event; the SPEC example now includes it. Multiple copies with the same timestamp are tolerated, but distinct timestamps for the same ID are ambiguous and rejected.

Before and after windows are disjoint half-open intervals around deployment time. Default metrics are `api.request` and `api.error`, matching the SPEC, and latency reads finite nonnegative `duration` values. Applications using the HTTP adapter's `http.request` event can configure requestMetric, errorMetric and durationField; status codes are not silently interpreted as separate error events. All filters/segmentation should be encoded in the chosen event stream: environment-specific filtering is not added in this checkpoint.

The result includes absolute bounds, window completeness, request/error/latency sample counts and `{before, after, delta, increase}` per metric. Error rate is error-event count divided by request-event count; latency is the sample mean. Increase is relative percent. Missing samples return null; incomplete after windows never produce a relative-change conclusion. A zero baseline with positive after value has an undefined relative percentage and returns null (the absolute delta remains available). Zero-to-zero returns zero. Consumers must check completeness, sample counts and null values before rollback decisions.

Five integration tests use real WatchFn storage to verify boundary exclusion, percent changes, missing/ambiguous deployment IDs, invalid durations, incomplete windows, window-boundary crossings during queries, zero baselines and alternate metric/field names. The observation timestamp is captured before reading metric samples, so a slow query cannot turn a partial snapshot into a complete-window claim. Source typecheck passes. The helper does not wait for a future observation window, take an atomic cross-metric database snapshot, deduplicate producer events, infer deployment identity, or implement the still-pending HostFn integration. Live rollout/rollback acceptance remains open.

Validation checkpoint:full core suite passed before the final additional boundary-crossing regression; all five comparison tests pass afterwards. Source typecheck and ESM/CommonJS/declaration builds pass. No hosted deployment or rollback was performed.
