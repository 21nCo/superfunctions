# Memory stream partitioning

The original partition API failed on Memory: both new public routing and held-partition retention tests rejected configuration as unsupported. This checkpoint adds real in-instance policy and routing, independent group/partition cursors, and current-receipt barriers. Policy is immutable after configuration or legacy publication/group creation, including after all payloads are trimmed.

Configured partition consumers use the existing DeliveryLease for active-callback renewal and abort signaling. A separate pending-receipt expiry models the storage ownership boundary: failed renewal or a callback returning without acknowledgment cannot remove the partition barrier early. Renewal requires the retained payload and current live receipt. Explicit current settlement releases it; expiry permits recovery and stale receipt operations do nothing. Pending/retry registries keep only identities/partition/offset and retrieve payloads from retained history. Active callbacks retain their delivered snapshots.

Seven new tests cover stable Unicode routing, policy mismatch/ranges, global history/replay, independent group progress and reopening consumers, held trim/current acknowledgment, unchanged 90ms renewal and expiry, no post-trim renewal, stale settlement, retry ordering and unsubscribe cleanup. Fake monotonic clocks test the exact original lease duration without widening it. Existing unsupported-adapter coverage now uses an adapter proxy that explicitly lacks configuration support, preserving that contract independently of Memory gaining support.

Initial baseline: 2 expected failures. Corrected focused suite: 19 pass; source/test types pass. Final full source suite passed 187 tests; the no-service invocation skipped 93 existing native cases plus one separately prepared Redis partition baseline. Source and test typechecks passed. ESM/CJS/declaration build passed. Fresh six-tarball normal install/ci and strict Node16/NodeNext declarations passed. Actual installed Memory partition routing, simultaneous independent partition progress and current-ACK release passed through both ESM and CJS on Node 20.0.0, 20.20.0 and 22.23.3. Production audit remained zero. The consumer was removed by its `finally` cleanup. No native service is required or claimed for Memory.

A separate Redis first-policy test reproduced its unsupported API against an owned local Redis process; it is not part of the Memory implementation. Owned PID 27516 stopped and its private `flow-redis-partition-l6vy0fc6` directory was removed/read back absent. Redis implementation and acceptance remain the next slice.

This is process-local storage, not cross-process durability. Legacy unpartitioned Memory visibilityTimeout support, Redis/Python partition parity and original performance targets remain open. No throughput or total physical-memory guarantee is inferred.

The later `memory-stream-receipt-readiness.md` checkpoint adds the previously missing legacy visibility expiry and returned-receipt unsubscribe/cleanup signaling, with baseline failures and installed acceptance.
