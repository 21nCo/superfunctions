# Redis stream partitioning

The initial independent-client policy test failed before implementation: `StreamImpl.publish` rejected configured partitioning because Redis lacked `configureStream`. The owned Redis process (PID 27516) stopped and its private temporary data directory was removed. No provider/account resources were used.

The implementation preserves the single authoritative global Redis Stream and its original IDs/range/replay behavior. Configured streams have immutable versioned routing policy and sparse per-partition ID-only Streams. No payload is copied into those indices. Logical consumer groups store their initial cutoff, independent partition progress, and receipt/expiry barriers separate from retained payloads. Legacy streams keep the existing XREADGROUP path and cannot be silently repartitioned after publication/group creation, even after trimming.

Publication, group initialization, claims, renewal, settlement and index/history trimming execute through the adapter's existing cached Lua boundary; transport ambiguity does not replay mutations. Each claim examines at most 64 populated partitions, advances a shared group scan cursor, and claims only available local capacity. There is no allocation proportional to a potentially large configured count. A current barrier blocks its partition until explicit authorized settlement or Redis-clock expiry. Expired owners recover their retained message before its same-partition successor; trim removes payload/index entries without deleting the barrier. Renewal requires retained payload and the exact unexpired receipt. Stale settlement cannot clear a successor.

Retention traverses populated indices in one Lua call so global history and sparse index cleanup are not interleaved with claims. Its work scales with touched partitions. Group statistics inspect retained ID entries and group cursors; no stream throughput or large-cardinality latency guarantee follows from correctness tests. Ordinary Redis script serialization is not a generic rollback guarantee for host resource exhaustion or externally corrupted key types. Old writers must be drained before enabling partitioned streams because older binaries do not create indices/barriers.

The shared DeliveryLease gains a stop-renewal mode that retains expiry observation after a callback returns without acknowledgment. A reproduced initialization race also showed an already-expired claim was only rejected by a later timer, allowing a handler microtask first. Construction now rejects an already-expired acquisition synchronously. This does not relax lease durations or permit revival after loss.
