# Returned manual stream callback expiry

The original P0 stream contract requires consumer-group load balancing and message acknowledgment. A manual callback can return before acknowledging; the receipt remains valid only until its configured visibility deadline. It must not permanently occupy a consumer slot after storage would allow redelivery.

A native regression used one consumer with maxInFlight=1 and a 300ms visibility timeout. Its first callback returned without settlement. The second attempt held its callback so the test could prove the first signal aborted, stale ACK/NACK did not settle its successor, and current ACK reduced lag to zero. Before correction, PostgreSQL legacy and configured streams plus legacy Redis each failed to redeliver within two seconds; configured Redis already passed. No fabricated storage timestamp or additional consumer was used. Both owned servers stopped and their private data directory was removed after the failing run.

The correction retains the existing DeliveryLease expiry observer after a callback returns with a current pending receipt, while stopping further renewal. Settlement and unsubscribe still stop all timers. The unchanged ownership-loss callback releases local capacity; subsequent polling must independently obtain a new backend-authorized receipt. Callback completion cannot revive an expired lease, extend duration, or make a stale receipt current. Delayed automatic commits use the same pending path and must fit the remaining visibility period.

The complete native Redis 8.10.2/PostgreSQL 16.13 suites passed all 104 tests in 31.04 seconds, including the four manual-expiry scenarios that previously produced three failures. Fresh six-tarball normal install/ci, strict Node16/NodeNext declarations, Node 20.0.0/20.20.0/22.23.3 ESM/CJS consumers and actual installed PG/Redis legacy/configured manual-expiry checks passed; production audit reported zero findings.
