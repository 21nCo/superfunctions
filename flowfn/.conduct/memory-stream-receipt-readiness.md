# Memory consumer receipt expiry and cleanup

The original stream acknowledgment and consumer-group lifecycle contract applies to unpartitioned Memory streams too. Before this correction, only configured partition streams created receipt timers. Also, returned callbacks were removed from the active-callback map; unsubscribe/cleanup stopped their pending lease timers without aborting their delivered signal.

Five fake-clock baseline cases produced four failures: legacy manual redelivery, legacy active-handler renewal followed by expiry on return, and returned-receipt unsubscribe/cleanup signaling for both legacy and configured streams. Configured manual expiry already passed. The correction uses the existing Memory lease/token/deadline path for every group delivery. It does not change unpartitioned routing or add partition barriers to legacy streams. Receipt expiry releases local capacity and retries only retained IDs; active callbacks renew while their lease is current. Exact-token checks fence stale settlement. Unsubscribe and cleanup explicitly abort the pending receipt lease before removing its timer, covering callbacks that already returned.

A separate retention regression confirms that trimming a manually held legacy payload does not resurrect it on expiry, and a subsequent publication remains deliverable. Timer assertions verify settlement, unsubscribe and adapter cleanup leave no owned receipt timers.

Validation on October 25, 2026: twelve focused lease/partition cases passed after the initial correction; the complete source suite passed 194 tests with 104 native-provider cases gated off. The final additional trim regression passed together with all six receipt tests. Source/test TypeScript checks and core build passed. The fresh six-tarball consumer used normal install and npm ci, strict Node16/NodeNext declarations, and actual installed legacy/configured Memory receipt expiry, stale settlement and unsubscribe signal checks in ESM/CJS on Node 20.0.0, 20.20.0 and 22.23.3. Production audit returned zero findings; see `memory-stream-receipt-installed-20261025.jsonl`. Its temporary consumer was removed in finally, with no external services or owned processes left. PostgreSQL/Redis runtime source is unchanged from the previous 104-test native checkpoint. Memory remains process-local; this does not establish durable memory storage, Python partition support, or original throughput/deployment gates.
