## Executive Summary

Replace the existing `generate-types` and `generate-migration` CLI commands with a single unified `generate` command that produces both adapter-specific ORM schema definitions (Drizzle `pgTable`/`mysqlTable`/`sqliteTable`) and client TypeScript types from the DataFn schema. This makes the DataFn schema the **single source of truth** — eliminating dual-schema maintenance and removing DataFn's custom migration system in favor of ORM-native tooling (`drizzle-kit`).

Additionally, refactor the server-side relation mutation code to query join tables through the ORM adapter (normal `adapter.create`/`findOne`/`update`/`delete`) instead of `adapter.internal` CRUD, since join tables will now exist in the generated ORM schema.

## Key Features

### Single Source of Truth
```bash
# One command generates everything
$ datafn generate --adapter drizzle --database postgres
✓ Schema written to: ./datafn-schema.drizzle.ts
✓ Types written to: ./datafn-types.ts
```

### Generated Drizzle Schema
```typescript
// datafn-schema.drizzle.ts — Generated by @datafn/cli. DO NOT EDIT.
import { pgTable, text, boolean, numeric, bigint, jsonb, index } from "drizzle-orm/pg-core";

export const todos = pgTable("todos", {
  id: text("id").primaryKey(),
  text: text("text").notNull(),
  completed: boolean("completed").notNull().default(false),
  priority: numeric("priority"),
  createdAt: bigint("created_at", { mode: "number" }).notNull(),
}, (table) => [
  index("todos_completed_idx").on(table.completed),
]);
```

### ORM-Native Migrations
```bash
# DataFn exits migration business — use your ORM's tools
drizzle-kit generate    # diff generated schema against DB
drizzle-kit migrate     # apply in production
```
