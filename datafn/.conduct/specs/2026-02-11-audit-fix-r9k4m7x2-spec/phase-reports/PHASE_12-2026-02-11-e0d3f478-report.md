## Notes

### Design Decisions

1. **AbortSignal Implementation**: Signal is extracted from query object in the HTTP transport rather than being passed as a separate parameter. This maintains the existing API surface while supporting the new functionality.

2. **Error Handling**: AbortError is converted to DFQL_ABORTED in the transport layer's `post()` method, ensuring consistent error envelopes regardless of where the abort occurs.

3. **Backward Compatibility**: Both features maintain full backward compatibility:
   - `pullBatchSize` defaults to 200 (current behavior)
   - `signal` is optional and ignored when not provided

4. **Validation Range**: pullBatchSize range (10-10000) provides reasonable bounds:
   - Minimum 10: Prevents inefficient single-record pulls
   - Maximum 10000: Prevents oversized responses
