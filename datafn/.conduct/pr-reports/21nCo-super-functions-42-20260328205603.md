#### **Issue 1:** Avoid disposing shared signal instances in factory store *(ChatGPT Codex Connector)*
- **Severity:** Medium
- **Description:** Calling currentSignal?.dispose() here tears down the underlying DataFn signal for *all* consumers, not just this store subscription. Signals returned by client.table(...).signal(...) are deduplicated/cached, so two components using the same query can share one signal instance; when one factory store unsubscribes (or receives a client update), this dispose path can silently stop updates for the other still-mounted store. The factory overload should only remove its own subscription, not dispose shared signal objects.
