# SPV2 Permissions Migration Scaffold (v1 -> v2)

## Purpose
Provide an implementation scaffold for migrating from v1 per-resource permission tables (`__datafn_permissions_{resource}`) to SPV2 global principal tables while preserving compatibility and rollback safety.

This scaffold targets Phase 02 deliverables only (data-model/codegen/migration shape), not runtime cutover.

## Source and Target Models
- v1 source tables: `__datafn_permissions_{resource}`
  - Columns (expected): `__ns`, `id`, `resource_id`, `user_id`, `level`, `granted_by`, `granted_at`
- v2 target table: `__datafn_permissions_global`
  - Columns: `id`, `resource_type`, `resource_ns`, `resource_id`, `principal_id`, `level`, `grant_kind`, `source_ref`, `granted_by`, `granted_at`, `revoked_at`

## Migration Invariants
- Idempotent: re-running migration must not duplicate grants.
- Lossless: all active v1 grants are represented in v2.
- Canonical principal format: v1 `user_id` -> v2 `principal_id` as `user:{user_id}` when not already prefixed.
- Deterministic conflict handling: duplicate v1 rows with different levels for same tuple must fail migration with `CONFLICT`.

## Script Shape (TypeScript/Pseudocode)
```ts
export async function migratePermissionsV1ToSpv2(db: DBClient): Promise<void> {
  await db.transaction(async (tx) => {
    const v1Tables = await discoverV1PermissionTables(tx); // __datafn_permissions_{resource}

    for (const tableName of v1Tables) {
      const resourceType = tableName.replace("__datafn_permissions_", "");

      // 1) Read active v1 rows.
      const rows = await tx.query(`
        SELECT __ns, resource_id, user_id, level, granted_by, granted_at
        FROM ${safeIdent(tableName)}
      `);

      // 2) Canonicalize principal IDs and stage deterministic tuples.
      const staged = rows.map((row) => ({
        resourceType,
        resourceNs: row.__ns,
        resourceId: row.resource_id,
        principalId: row.user_id.includes(":") ? row.user_id : `user:${row.user_id}`,
        level: row.level,
        grantKind: "record",
        sourceRef: null,
        grantedBy: row.granted_by,
        grantedAt: row.granted_at,
      }));

      // 3) Reject conflicting duplicates (same tuple, different level).
      assertNoConflictingDuplicates(staged);

      // 4) Upsert into global table (idempotent).
      await bulkUpsertPermissionsGlobal(tx, staged);
    }
  });
}
```

## SQL Outline
```sql
-- Discover v1 permission tables
SELECT tablename
FROM pg_tables
WHERE tablename LIKE '__datafn_permissions_%'
  AND tablename <> '__datafn_permissions_global';

-- Canonical backfill pattern per resource table
INSERT INTO __datafn_permissions_global (
  id,
  resource_type,
  resource_ns,
  resource_id,
  principal_id,
  level,
  grant_kind,
  source_ref,
  granted_by,
  granted_at,
  revoked_at
)
SELECT
  CONCAT('v1_', $resource_type, '_', p.id),
  $resource_type,
  p.__ns,
  p.resource_id,
  CASE
    WHEN POSITION(':' IN p.user_id) > 0 THEN p.user_id
    ELSE CONCAT('user:', p.user_id)
  END,
  p.level,
  'record',
  NULL,
  p.granted_by,
  p.granted_at,
  NULL
FROM __datafn_permissions_${resource} p
ON CONFLICT (id) DO NOTHING;
```

## Conflict Detection Query Shape
```sql
-- Detect conflicting levels for same logical grant tuple before insert
SELECT
  resource_type,
  resource_ns,
  resource_id,
  principal_id,
  COUNT(DISTINCT level) AS level_count
FROM staged_v1_rows
GROUP BY resource_type, resource_ns, resource_id, principal_id
HAVING COUNT(DISTINCT level) > 1;
```

If any rows return, abort with conflict error and do not apply partial writes.

## Compatibility Scaffold
- Dual-read validation query shape:
  - Compare access decisions from v1 per-resource tables vs v2 global table for a sample actor/resource matrix.
  - Migration is considered valid only when decisions are equivalent.
- Dual-write window (bounded):
  - During cutover, writes should mirror into both v1 and v2 tables.
  - Keep this behind a feature flag to disable quickly during rollback.

## Rollback Scaffold
1. Disable v2 read path feature flag.
2. Keep v1 tables authoritative.
3. Optionally continue writing v2 for diagnostics, but do not block serving path on v2 state.
4. Re-run parity check between v1/v2 before retrying cutover.

## Verification Checklist (Dry Run)
1. Backfill row count in v2 equals sum of active v1 rows after canonical dedupe.
2. No conflicting duplicates remain unresolved.
3. Sampled access parity checks pass for record and scope access patterns.
4. Re-running migration produces zero net-new rows unless new v1 grants were added.

## Notes
- Scope grant and relation-inherited backfill semantics are introduced by SPV2 runtime paths in later phases; this scaffold only migrates v1 record grants.
- Table/index creation is generated by `datafn/cli` SPV2 codegen in this phase.
