## Summary

The built-in KV resource injected by `ensureBuiltinKv()` has no `permissions` property. After VAL-001 (deny-by-default, landed Feb 28) changed the default behavior to reject resources without a permissions policy, every KV query and mutation returns 403 FORBIDDEN unless the server is configured with `allowUnknownResources: true`. This is a high-severity bug because the KV store is a built-in feature that should always work — users should not need to know about an escape hatch to use a core library feature.

## Root Causes

### Root Cause: `ensureBuiltinKv()` does not include a `permissions` policy on the KV resource

**Location:** `datafn/core/src/kv.ts` lines 42–60

```typescript
const kvResource: DatafnResourceSchema = {
  name: KV_RESOURCE_NAME,
  version: 1,
  idPrefix: KV_RESOURCE_NAME,
  fields: [
    { name: "id", type: "string", required: true },
    { name: "value", type: "json", required: false },
  ],
  indices: ["id"],
  // NO permissions property
};
```

**Expected behavior:** The KV resource is a built-in system resource. It should always be accessible regardless of the server's authz configuration. It should include a permissive default permissions policy that whitelists its own fields.

**Actual behavior:** The resource has no `permissions` property. When `validateMutationAuthz()` or `validateQueryAuthz()` checks it, the deny-by-default path triggers:

```typescript
// datafn/server/src/validation/authz.ts lines 259-273
const policy = resource.permissions;
if (!policy) {
  if (!opts?.allowUnknownResources) {
    return {
      ok: false,
      code: "FORBIDDEN",
      message: `No authorization policy found for resource '${mutation.resource}'.`,
      path: "resource",
    };
  }
  return { ok: true };
}
```

**Impact:** The KV store — a core built-in feature — is completely blocked on production servers. The only workaround is `allowUnknownResources: true`, which disables authz for ALL resources without policies, defeating the purpose of deny-by-default.

**Timeline context:** This regression was introduced when VAL-001 (deny-by-default) was implemented in `2026-02-27-audit-fix-v7k3m9x4-spec` Phase 09 (Feb 28, 2026). The KV resource was added earlier (Feb 8) when the default was allow-all for resources without a policy. The VAL-001 change did not account for built-in system resources.

---

## Proposed Fix

Add a default permissive `permissions` policy to the KV resource definition in `ensureBuiltinKv()`:

**File:** `datafn/core/src/kv.ts`

```typescript
const kvResource: DatafnResourceSchema = {
  name: KV_RESOURCE_NAME,
  version: 1,
  idPrefix: KV_RESOURCE_NAME,
  fields: [
    { name: "id", type: "string", required: true },
    { name: "value", type: "json", required: false },
  ],
  indices: ["id"],
  permissions: {
    read:  { fields: ["id", "value"] },
    write: { fields: ["id", "value"] },
  },
};
```

This ensures:
- KV works out of the box regardless of `allowUnknownResources` setting.
- The deny-by-default model remains intact for user-defined resources.
- No security regression — the KV resource only exposes its own two fields.
