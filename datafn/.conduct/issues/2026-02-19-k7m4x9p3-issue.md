## User-Reported Issue

> POST to `http://localhost:3001/datafn/query` with body `{"resource":"todos","version":1,"sort":["-createdAt"]}` returns 400 Bad Request:
> ```json
> {
>   "ok": false,
>   "error": {
>     "code": "DFQL_UNKNOWN_FIELD",
>     "message": "Unknown field: sort[0]",
>     "details": { "path": "sort[0]" }
>   }
> }
> ```

## Summary

The DFQL sort `-field` prefix shorthand for descending order (e.g., `"-createdAt"`) is documented in `datafn/core/README.md` and used extensively in the example todo app, but was never implemented in either the server-side validation, the server-side sort parser, or the client-side offline query processor. The server validator interprets `"-createdAt"` as a literal field name (including the `-`), which doesn't exist in the schema, causing a `DFQL_UNKNOWN_FIELD` rejection. This breaks the example app's primary query on page load.

## Observed Errors/Symptoms

1. **HTTP 400 on `/datafn/query`** with error code `DFQL_UNKNOWN_FIELD` and message `"Unknown field: sort[0]"`
2. The todo app's main queries all fail on startup since every signal uses `sort: ["-createdAt"]`
3. No todos are displayed to the user; the app appears broken

## Root Causes

### RC-1: Server validation treats `-` prefix as part of field name

**Location**: `datafn/server/src/validation/query.ts` lines 185–197

**Current code**:
```typescript
// Parse sort field (can be "fieldName" or "fieldName:asc/desc")
const parts = sortItem.split(":");
const fieldName = parts[0];
// ...
if (!fieldNames.has(fieldName)) {
  return vErr("DFQL_UNKNOWN_FIELD", `Unknown field: sort[${i}]`, `sort[${i}]`);
}
```

**Expected behavior**: The validator should strip a leading `-` before looking up the field name in the schema.

**Actual behavior**: `"-createdAt".split(":")` → `["-createdAt"]`, `fieldName = "-createdAt"`, which is not in `fieldNames` (only `"createdAt"` is), so validation fails.

**Impact**: Any query using `-field` sort format is rejected at the validation layer before it reaches execution.

### RC-2: Server sort parser does not handle `-` prefix

**Location**: `datafn/server/src/execution/query/sort.ts` lines 14–26

**Current code**:
```typescript
/**
 * Parse sort terms from string format
 * Formats: "field", "field:asc", "field:desc"
 */
export function parseSortTerms(sort: string[] | undefined): SortTerm[] {
  // ...
  return sort.map((term) => {
    const parts = term.split(":");
    const field = parts[0];
    const direction = (parts[1] as "asc" | "desc") || "asc";
    return { field, direction };
  });
}
```

**Expected behavior**: `"-createdAt"` should parse to `{ field: "createdAt", direction: "desc" }`.

**Actual behavior**: Splits by `:` and gets `field = "-createdAt"`, `direction = "asc"` (default). Even if RC-1 were bypassed, the sort would be applied to a non-existent field with the wrong direction.

### RC-3: Client offline query processor does not handle `-` prefix

**Location**: `datafn/client/src/offline/query.ts` lines 67–77

**Current code**:
```typescript
const sort = query.sort as string[];
records.sort((a, b) => {
  for (const term of sort) {
    const [field, dir] = term.split(":");
    const va = a[field] as any;
    const vb = b[field] as any;
    if (va < vb) return dir === "desc" ? 1 : -1;
    if (va > vb) return dir === "desc" ? -1 : 1;
  }
  return 0;
});
```

**Expected behavior**: `"-createdAt"` should sort by `createdAt` descending in offline mode.

**Actual behavior**: `field = "-createdAt"`, which doesn't exist on records → `va` and `vb` are always `undefined` → no sorting occurs. Offline queries silently return unsorted results.

## Spec/Intent Gap Analysis

This bug traces to a documentation-vs-intent divergence during the DFQL design phase:

### What the intent says (authoritative)

**`datafn/.conduct/intent/dfql.intent.md`** (lines 295–316) defines sort as:
- `"field"` → ascending
- `"field:asc"` / `"field:desc"`
- `{ "field": "fieldName", "direction": "asc" | "desc" }`

**No `-` prefix format is mentioned in the intent document.**

**`datafn/.conduct/intent/query-sample.json`** uses `"field:asc/desc"` format exclusively across all 13 sample queries (e.g., `"updatedAt:desc"`, `"id:asc"`, `"priority:desc"`). No sample uses the `-` prefix.

### What the README says (divergent)

**`datafn/core/README.md`** (lines 299, 360) introduces the `-` prefix format:
```
sort?: DfqlSort;  // Ordering (e.g. ["-createdAt", "name"])
// e.g. ["name", "-createdAt"]  → name ASC, createdAt DESC (prefix "-" = descending)
```

This shorthand was added to the public-facing documentation but was never reflected back into the intent document or the implementation.

### What happened

1. The **intent** (`dfql.intent.md`) and **sample** (`query-sample.json`) were written with only `field:asc/desc` format
2. The **implementation** (validation, sort parser, offline processor) followed the intent faithfully
3. The **README** (`core/README.md`) documented an additional `-field` shorthand — likely inspired by MongoDB-style conventions — without updating the intent or filing a spec to implement it
4. The **example app** (`todo-app/client/src/App.svelte`) was written against the README, not the intent or implementation
5. No spec in `datafn/.conduct/specs/` covers DFQL query sort implementation or the `-field` format:
   - `2026-02-12-fix-r8k4m2x9-spec` — Internal table resolution (unrelated)
   - `2026-02-14-change-k7m9x4p2-spec` — CLI TypeScript schema support (unrelated)
   - `2026-02-15-change-m8k3x7p4-spec` — Drizzle codegen (unrelated)
   - `2026-02-16-new-k9m7x3p5-spec` — Schema index validation (unrelated)
6. No audit in `datafn/.conduct/audits/` covers DFQL query sort validation

The gap was never caught because the DFQL query/sort execution layer was implemented as part of the initial `SF-7 - Datafn init` commit (`2d1a0bf`) without a dedicated spec or audit for the query validation path.

## Proposed Fixes

### Option A: Implement `-field` prefix support (recommended)

Add `-` prefix handling to all three code paths:

1. **Server validation** (`datafn/server/src/validation/query.ts`): Before looking up the field name, check for leading `-` and strip it
2. **Server sort parser** (`datafn/server/src/execution/query/sort.ts`): In `parseSortTerms()`, detect `-` prefix and map to `{ field, direction: "desc" }`
3. **Client offline processor** (`datafn/client/src/offline/query.ts`): Same `-` prefix detection in the sort comparator
4. **Cursor validation** (same file as #1): The cursor tie-breaker check also splits by `:` only — needs the same treatment

### Option B: Fix the README and example app

Change the README to remove the `-field` format and update the example app to use `"createdAt:desc"` instead of `"-createdAt"`. Simpler but less user-friendly — the `-` prefix is a well-known convention (MongoDB, many REST APIs).

## Notes

- The `DfqlSort` type (`string[]`) is format-agnostic and doesn't constrain the string format, so no type changes are needed regardless of which fix option is chosen.
- The object format `{ "field": "fieldName", "direction": "asc" | "desc" }` documented in the intent is also not implemented in the current codebase — only string forms are supported. This is a separate gap but lower priority since no code uses it.
