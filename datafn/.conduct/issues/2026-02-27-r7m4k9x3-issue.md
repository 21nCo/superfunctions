## Summary

**Severity: Critical** — Two bugs prevent the todo-app example (and any datafn app without `authContextProvider`) from functioning. Bug 1 blocks all write operations. Bug 2 causes intermittent failures on first client connection when multiple pull requests arrive simultaneously.

---

## Observed Errors / Symptoms


## Root Causes

### RC-1: Server only wraps adapter with __ns injection when authContextProvider is present

**Location:** `datafn/server/src/server.ts:215`

**Current code:**
```ts
if (db && config.authContextProvider && config.rowLevelNamespace !== false) {
```

**Expected behavior:** The adapter should be wrapped with namespace injection whenever `multiTenant` is not `false` in the schema (i.e., whenever the generated Drizzle schema has `__ns` columns), regardless of whether `authContextProvider` is present. When no auth provider exists, the default `"datafn"` namespace should be used.

**Actual behavior:** Without `authContextProvider`, the condition is false, so the adapter is never wrapped. The raw adapter is used for all CRUD operations, and `namespace` passed by push/query/clone handlers is ignored by the Drizzle adapter (it only destructures `{ model, data, select }` at `packages/db/src/adapters/drizzle/index.ts:155`).

**Impact:** Every write operation fails with a NOT NULL constraint violation on `__ns` because:
1. Codegen generates `__ns TEXT NOT NULL` by default (`schema.multiTenant !== false` at `datafn/cli/src/drizzle-codegen.ts:35`)
2. Server passes `namespace: "datafn"` to all db calls
3. But the adapter never injects `__ns` into the data because wrapping was skipped

**Evidence:** The todo-app has no `authContextProvider` in its server config (`datafn/examples/todo-app/server/src/index.ts:11-24`), but the generated schema has `__ns: text("__ns").notNull()` on all tables (`datafn/examples/todo-app/server/src/datafn-schema.drizzle.ts:6,17,25,39`).

### RC-2: ensureTable has a TOCTOU race on the in-memory guard

**Location:** `packages/db/src/adapters/drizzle/internal.ts:74-90`

**Current code:**
```ts
async ensureTable(name: string, columns: InternalColumnDef[]): Promise<void> {
  if (ensuredTables.has(name)) return;           // line 79 — check

  // ... build DDL ...
  const ddl = `CREATE TABLE IF NOT EXISTS ${name} (...)`;
  await executeRaw(drizzleSql.raw(ddl));          // line 88 — async gap
  ensuredTables.add(name);                        // line 89 — set
},
```

**Expected behavior:** Concurrent calls to `ensureTable` for the same table should not fail.

**Actual behavior:** Multiple concurrent async calls pass the `has()` check (line 79) before any of them reaches `add()` (line 89). All of them then execute `CREATE TABLE IF NOT EXISTS` concurrently. On PostgreSQL, this causes a `pg_type_typname_nsp_index` unique constraint violation because PostgreSQL's `CREATE TABLE IF NOT EXISTS` first attempts to create a composite row type, and concurrent type creation races on the `pg_type` catalog.

**Impact:** First client connection often fires multiple `/datafn/pull` requests simultaneously. Each calls `ensureInternalTable("__datafn_changes", ...)`. The race causes all but one to fail with `duplicate key violates unique constraint`.

**Evidence:** Server logs show 4-5 pull requests arriving within ~100ms of each other, all triggering the same `ensureTable` call before the first completes.

## Proposed Fixes

### Fix for RC-1: Wrap adapter based on schema multiTenant flag, not just authContextProvider

In `datafn/server/src/server.ts`, change the auto-wrap condition to also wrap when the schema has `multiTenant !== false` (which matches the codegen condition). The `extractNamespace` function already falls back to `"datafn"` when no auth provider exists.

```ts
// Wrap when multiTenant is active (matches codegen __ns generation condition)
const schemaMultiTenant = validatedSchema.multiTenant !== false;
if (db && schemaMultiTenant && config.rowLevelNamespace !== false) {
```

This ensures the adapter always injects `__ns` when the DB schema expects it, using the default `"datafn"` namespace for apps without auth.

### Fix for RC-2: Add a per-table promise lock to ensureTable

Replace the TOCTOU `has/add` pattern with a promise-based once guard:

```ts
const ensurePromises = new Map<string, Promise<void>>();

async ensureTable(name: string, columns: InternalColumnDef[]): Promise<void> {
  if (ensurePromises.has(name)) return ensurePromises.get(name);

  const promise = (async () => {
    const ddl = `CREATE TABLE IF NOT EXISTS ${name} (...)`;
    await executeRaw(drizzleSql.raw(ddl));
  })();

  ensurePromises.set(name, promise);
  return promise;
}
```

This ensures only one DDL statement executes per table name, and all concurrent callers await the same promise.

## Notes

- The codegen default (`multiTenant !== false`) was intentionally changed to make namespace isolation the default. The server auto-wrap logic was not updated to match this change.
- The `ensureTable` race is PostgreSQL-specific; SQLite's `CREATE TABLE IF NOT EXISTS` is atomic within a single connection.
- The spec (`2026-02-26-new-k7r4m9x2-spec`) originally designed auto-wrap gated on `authContextProvider`. The codegen default inversion happened after the spec was executed, creating the mismatch.
