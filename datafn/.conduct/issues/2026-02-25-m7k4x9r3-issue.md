## Summary

**Severity: High** — Breaks all many-many relation operations (relate) when join rows have no metadata, which is the common case (e.g. linking a todo to a tag/category). The push endpoint returns a 500-class error and the relation is never persisted.

## Root Causes

### RC-1: `executeRelate` passes empty `update` object to adapter upsert for metadata-free join rows

**Location:** [datafn/server/src/execution/mutation/relations.ts:164](datafn/server/src/execution/mutation/relations.ts#L164)

**Current code:**
```ts
update: Object.keys(item.metadata).length > 0 ? item.metadata : {},
```

When a many-many relation has no metadata (the overwhelmingly common case — just linking two records), `item.metadata` is `{}`, so `update` is passed as `{}`.

**Expected behavior:** The upsert should succeed as an idempotent "insert if not exists" operation when there is nothing to update.

**Actual behavior:** The empty `update: {}` is forwarded to the Drizzle adapter, which unconditionally passes it to `onConflictDoUpdate({ set: {} })`.

**Impact:** Every many-many relate operation without metadata fails with a 500 error. This blocks the entire relation feature in the todo-app example and any real application using tags, categories, or other many-many links.

---

### RC-2: Drizzle adapter `upsert()` does not handle empty update objects

**Location:** [packages/db/src/adapters/drizzle/index.ts:283-286](packages/db/src/adapters/drizzle/index.ts#L283-L286)

**Current code:**
```ts
const q = db
  .insert(tbl)
  .values(create as any)
  .onConflictDoUpdate({ target: keys as any, set: update as any });
```

The Drizzle adapter always uses `.onConflictDoUpdate()` regardless of whether `update` is empty. Drizzle's internal `mapUpdateSet` helper (in drizzle-orm) throws `"No values to set"` when the `set` object has zero keys, because `ON CONFLICT DO UPDATE SET` with no columns is not valid SQL.

**Expected behavior:** When `update` is empty, the adapter should use `.onConflictDoNothing()` instead, which generates valid SQL: `INSERT ... ON CONFLICT DO NOTHING`.

**Actual behavior:** `.onConflictDoUpdate({ set: {} })` is called, Drizzle throws before the query ever reaches the database.

**Impact:** Same as RC-1 — this is the immediate throw site. Any caller passing an empty `update` to the Drizzle adapter's upsert will crash.

**Evidence:** The stack trace shows the error originating inside drizzle-orm's `mapUpdateSet` utility, confirming the empty-set path is not supported by Drizzle.

## Proposed Fixes

### Fix A (Recommended): Guard in Drizzle adapter `upsert()`

In `packages/db/src/adapters/drizzle/index.ts`, check if `update` is empty before choosing the conflict strategy:

```ts
const hasUpdate = update && Object.keys(update).length > 0;

const q = hasUpdate
  ? db.insert(tbl).values(create as any)
      .onConflictDoUpdate({ target: keys as any, set: update as any })
  : db.insert(tbl).values(create as any)
      .onConflictDoNothing({ target: keys as any });
```

This is the correct fix location because:
1. It protects all callers, not just `executeRelate`
2. `ON CONFLICT DO NOTHING` is the semantically correct SQL for "insert if missing, skip if exists"
3. The same issue likely applies to the MySQL path (`onDuplicateKeyUpdate` with empty `set`)

### Fix B (Belt-and-suspenders): Also fix the caller in `executeRelate`

In `datafn/server/src/execution/mutation/relations.ts:164`, avoid passing empty update entirely. Either omit the `update` field or set a no-op value. However, Fix A alone is sufficient and more robust.

## Notes

- The issue affects PostgreSQL (confirmed via stack trace showing `pg-core`). SQLite would likely have the same issue since both use `onConflictDoUpdate`.
- The MySQL path at line 269 (`onDuplicateKeyUpdate({ set: update })`) may have an equivalent failure with an empty `set` — should be verified.
- This is a regression-prone area: any future upsert caller that passes an empty update will hit the same crash. Fix A (adapter-level guard) prevents this class of bug entirely.
