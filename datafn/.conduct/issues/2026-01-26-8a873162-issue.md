## Summary

This is a **feature request** to add configurable ID generation strategy support to `createDatafnClient`. Currently, ID generation is hardcoded to use `crypto.randomUUID()` with a fallback. The requested feature would allow users to provide a custom ID generator function via the client configuration, enabling support for UUID v7, ULID, or other ID generation strategies without adding dependencies to the DataFn client package. This is a **Medium** priority enhancement that improves flexibility while maintaining zero dependencies.

---

## Observed Errors/Symptoms

**Current Behavior**:
- ID generation is hardcoded in `table.ts` using `generateId()` function
- No way to customize ID generation strategy
- Users who want UUID v7, ULID, or other strategies must modify the package or work around the limitation

**Expected Behavior**:
- `createDatafnClient` should accept an optional `generateId` function in its configuration
- If provided, the custom function should be used for ID generation
- If not provided, `crypto.randomUUID()` should be used as the default (current behavior)
- This allows users to use external packages like `uuidv7` or `ulid` without adding them as dependencies to `@datafn/client`

## Root Causes

### Issue 1: Hardcoded ID Generation Function

**Location**: `superfunctions/datafn/client/src/tables/table.ts:44-51`

**Current Code**:
```typescript
/**
 * Generate a unique ID for insert operations
 */
function generateId(): string {
  // Use crypto.randomUUID() if available, otherwise fallback to timestamp + random
  if (typeof crypto !== "undefined" && crypto.randomUUID) {
    return crypto.randomUUID();
  }
  // Fallback for environments without crypto.randomUUID
  return `${Date.now()}-${Math.random().toString(36).slice(2, 11)}`;
}
```

**Expected Behavior**:
- The ID generator should be configurable via client configuration
- Should accept a function `() => string` that generates IDs
- Should default to `crypto.randomUUID()` if not provided

**Actual Behavior**:

- Users cannot inject custom ID generation logic

**Impact**:
- Prevents users from using alternative ID generation strategies (UUID v7, ULID, etc.)

- Limits flexibility for applications with specific ID requirements

**Evidence**:

## Proposed Fixes

### Fix 1: Add generateId to DatafnClientConfig

**Location**: `superfunctions/datafn/client/src/client.ts:66-86`

Add optional `generateId` property to the configuration interface:

```typescript
export interface DatafnClientConfig<S extends DatafnSchema> {
  schema: S;
  sync?: DatafnSyncConfig;
  plugins?: DatafnPlugin[];
  clientId: string;
  storage?: DatafnStorageAdapter;
  getTimestamp?: () => number;
  /**
   * Optional ID generator function for insert operations.
   * If not provided, defaults to crypto.randomUUID().
   * Allows users to use custom ID strategies (UUID v7, ULID, etc.)
   * without adding dependencies to @datafn/client.
   */
  generateId?: () => string;
}
```

Modify `TableRegistry` constructor to accept and store the ID generator:

## Notes

**Assumptions**:
- The ID generator function should be synchronous and return a string
- The function should be pure (no side effects) for deterministic behavior
- Users are responsible for ensuring their custom ID generators produce unique IDs
- The default `crypto.randomUUID()` behavior should be preserved for backward compatibility

**Design Considerations**:
- This approach keeps the package dependency-free while allowing flexibility
- Users can install and use `uuidv7`, `ulid`, or any other ID generation library
- The function signature `() => string` is simple and flexible
- No breaking changes to existing API

**Limitations**:
- The ID generator is set at client creation time and cannot be changed per-table
- All tables in a client instance will use the same ID generator
- If a user wants different ID strategies per table, they would need to create separate clients

**Additional Context**:
- Similar patterns exist in other parts of the codebase (e.g., `getTimestamp` is already configurable)
- The `flowfn` package has a similar ID generation strategy system that could serve as reference
- This feature aligns with the goal of keeping `@datafn/client` lightweight and dependency-free
