## User-Reported Issue Description

The TypeScript type definition for `DatafnServerConfig` does not include the `rest` flag, even though:
1. The implementation code checks for `config.rest` (using `(config as any).rest`)
2. Tests use `@ts-ignore` to bypass TypeScript errors when passing `rest: true`
3. There's a comment in the code acknowledging this needs to be fixed

The `rest` flag should be added to the interface as an optional boolean property to enable REST endpoint generation.

## Summary

The `DatafnServerConfig` TypeScript interface is missing the `rest?: boolean` property, even though the implementation supports it. This forces developers to use type assertions (`as any`) or `@ts-ignore` comments when enabling REST endpoint generation. The fix is straightforward: add `rest?: boolean` to the interface definition. **Severity: Medium** (type safety issue, degrades developer experience but doesn't break runtime functionality).

## Proposed Fixes

### Fix 1: Add `rest` property to DatafnServerConfig interface

**Location**: `server/src/server.ts`, line 62 (after `getServerTime`)

**Change**:
Add the following property to the `DatafnServerConfig` interface:

```typescript
  /** Optional flag to enable REST endpoint generation (default: false)
   * When true, generates REST wrappers:
   * - GET /datafn/resources/:resource (query wrapper)
   * - POST /datafn/resources/:resource (insert/merge wrapper)
   * - PATCH /datafn/resources/:resource/:id (merge wrapper)
   * - DELETE /datafn/resources/:resource/:id (delete wrapper)
   */
  rest?: boolean;
```

**Additional Changes**:
1. Remove the type assertion `(config as any).rest` on line 297, replacing it with `config.rest`
2. Remove `@ts-ignore` comments from test file `server/__tests__/rest.test.ts` (lines 29 and 91)

**Rationale**:
- Makes the type system accurately reflect runtime behavior
- Improves developer experience with proper autocomplete and type checking
- Aligns with spec documentation that mentions `rest?: boolean`
- Removes need for workarounds in tests and usage code
