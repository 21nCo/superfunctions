## Summary

DataFn's `dfql/search.mdx` documents how to **write** search queries (prefix, fuzzy, fieldBoosts, source modes) but not how to **set up** the search infrastructure that powers them. The `searchProvider` config field is absent from the client config reference, the `createClientSearchPlugin` function is undocumented, the built-in plugin overview links to a non-existent page, and the SearchFn→DataFn integration guide only covers server-side setup. A developer reading DataFn docs cannot discover or configure client-side search. Severity: **Medium** — search works in code and the todo-app example demonstrates it, but the documentation path is broken.

## Observed Symptoms

1. Developer reads `dfql/search.mdx` line 6: "DataFn search is provider-backed and local-first when a `searchProvider` is configured on the client." — but no link or explanation of how to configure it.
2. Developer checks `reference/client/config.mdx` — `searchProvider` field is not listed despite being a valid config option.
3. Developer reads `documentation/plugins/overview.mdx` line 152 — "Client Search" links to `/docs/documentation/plugins/custom-plugins` which is a page about writing custom plugins, not about using the built-in client search plugin.
4. Developer searches SearchFn integration docs — finds `searchfn/docs/integrations/datafn.mdx` but it only shows server-side `createDatafnServer({ search: provider })`, not client-side `createDatafnClient({ searchProvider })`.

## Root Causes

### RC-1: `searchProvider` field missing from client config reference

**Location:** `datafn/docs/content/docs/reference/client/config.mdx`, lines 10-32

**Current documentation lists:**
- `schema`, `clientId`, `storage`, `namespace`, `sync`, `plugins`, `generateId`

**Missing from docs — actual code** (`datafn/client/src/client.ts`, lines 216-219):
```typescript
/**
 * Optional search provider for client-side search query routing.

searchProvider?: SearchProvider;
```

**Impact:** Developers cannot discover the `searchProvider` config option from reference docs. The field is used at client initialization (line 516-526) to call `searchProvider.initialize()` with resource/searchFields mappings, at search routing (lines 805, 1125, 1145) for local search execution, and passed to SyncEngine (line 634) for offline mutation indexing.

### RC-2: No documentation for `createClientSearchPlugin` or `ClientSearchConfig`

**Location:** No doc page exists for this.

**What exists in code** (`datafn/client/src/plugins/clientSearch.ts`):

Function signature (line 60):
```typescript
export function createClientSearchPlugin(options?: ClientSearchConfig): DatafnPlugin
```

Config interface (lines 17-29):
```typescript
export interface ClientSearchConfig {
  boost?: Record<string, number>;        // Legacy MiniSearch-only, deprecated with searchProvider
  storage?: DatafnStorageAdapter;
  searchProvider?: SearchProvider;        // Preferred provider-backed search
}
```

The plugin handles:
- `afterSync` hook (lines 86-93): rebuilds provider indices or legacy MiniSearch indices
- `afterMutation` hook (lines 104-114): incremental index updates via `searchProvider.updateIndices()`
- `beforeQuery` hook (lines 143-169): intercepts search queries and routes to `searchProvider.search()`

**Impact:** Developers who want to use the plugin-based search integration pattern (as opposed to top-level `searchProvider` config) have no documentation for it. The two approaches (plugin vs config) are also never compared.

### RC-4: SearchProvider interface not documented anywhere in DataFn docs

**Location:** No doc page exists.

**What exists in code** (`datafn/core/src/search-provider.ts`):
```typescript
export interface SearchProvider {
  readonly name: string;
  search(params: {
    resource: string;
    query: string;
    type?: "fullText" | "semantic";
    fields?: string[];
    limit?: number;
    prefix?: boolean;
    fuzzy?: boolean | number;
    fieldBoosts?: Record<string, number>;
    signal?: AbortSignal;
  }): Promise<string[]>;
  searchAll?(params: {
    query: string;
    resources?: string[];
    fields?: string[];
    limit?: number;
    limitPerResource?: number;
    prefix?: boolean;
    fuzzy?: boolean | number;
    fieldBoosts?: Record<string, number>;
    signal?: AbortSignal;
  }): Promise<Array<{ resource: string; id: string; score: number }>>;
  updateIndices(params: {
    resource: string;
    records: Record<string, unknown>[];
    operation: "upsert" | "delete";
  }): Promise<void>;
  initialize?(config: {
    resources: Array<{ name: string; searchFields: string[] }>;
  }): Promise<void>;
  dispose?(): Promise<void>;
}
```

**Impact:** Developers wanting to implement a custom search provider (non-SearchFn) have no reference for the interface contract. Required vs optional methods, parameter semantics, and return types are all undiscoverable.

### RC-5: No cross-reference from DataFn docs to SearchFn integration guide

**Location:** `datafn/docs/content/docs/dfql/search.mdx` — no link to SearchFn.

**What exists:** SearchFn has a DataFn integration doc at `searchfn/docs/content/docs/integrations/datafn.mdx` that documents:

**What's missing:** This doc only covers server-side setup. Client-side `createDatafnClient({ searchProvider })` is not shown. And DataFn's own search docs never link to SearchFn's integration guide.

**Impact:** The two doc sites are islands — a developer reading DataFn search docs cannot find SearchFn, and a developer reading SearchFn integration docs only gets server setup.

### RC-6: No end-to-end search provider setup guide

**Location:** No doc page exists.

**What exists as working reference** (`datafn/examples/todo-app/client/src/lib/datafn.ts`, lines 98-133):
```typescript
// 1. Define resource search fields
const SEARCH_RESOURCE_FIELDS = { todos: ["text"], categories: ["name"] };

// 2. Configure search defaults
const SEARCH_DEFAULTS = { prefix: true, fuzzy: 0.2, fieldBoosts: { text: 2, name: 1 } };

// 3. Create provider from SearchFn IndexedDB adapter
const searchProvider = createSearchProvider(
  new IndexedDbAdapter({ dbName: "todo-app-search", defaults: SEARCH_DEFAULTS }),
  { resourceFields: SEARCH_RESOURCE_FIELDS },
);

// 4. Wire into client config
export const client = createDatafnClient({
  schema, clientId, namespace, storage, searchProvider, plugins: [auditPlugin], sync,
});
```

**Impact:** This pattern works but is only discoverable by reading the example app source code. No documentation walks through: (a) choosing an adapter, (b) creating a provider, (c) wiring it into the client, (d) verifying local search works.

## Proposed Fixes

### Fix 1: Add `searchProvider` to client config reference
Update `datafn/docs/content/docs/reference/client/config.mdx` to include the `searchProvider?: SearchProvider` field with type, description, and link to the SearchProvider interface reference.

### Fix 2: Create dedicated client search plugin documentation page
Create `datafn/docs/content/docs/documentation/plugins/client-search.mdx` covering:
- `createClientSearchPlugin(options?: ClientSearchConfig)` function
- `ClientSearchConfig` interface fields
- When to use plugin vs top-level `searchProvider` config
- Hook lifecycle (afterSync → rebuild indices, afterMutation → incremental update, beforeQuery → search routing)

### Fix 3: Fix plugin overview link
Update `datafn/docs/content/docs/documentation/plugins/overview.mdx` to link Client Search to the new `/docs/documentation/plugins/client-search` page.

### Fix 4: Document the SearchProvider interface
Add a reference section (either in `dfql/search.mdx` or a dedicated reference page) documenting the full `SearchProvider` interface contract:
- Required methods: `search()`, `updateIndices()`, `name`
- Optional methods: `searchAll()`, `initialize()`, `dispose()`
- Parameter types and return types for each method

### Fix 5: Add cross-references between DataFn and SearchFn docs
- In `dfql/search.mdx`: Add a "Setting Up a Search Provider" section that links to SearchFn's `@searchfn/datafn-provider` integration guide and shows the client-side wiring pattern.
- In SearchFn's `integrations/datafn.mdx`: Add client-side setup example alongside the existing server-side example.

### Fix 6: Add end-to-end search setup guide in search.mdx
Add a "Getting Started" or "Setup" section to `dfql/search.mdx` showing the complete flow:
1. Install `@searchfn/datafn-provider` and an adapter (e.g., `@searchfn/indexeddb-adapter`)
2. Define resource fields mapping
3. Create search provider with adapter and defaults
4. Pass `searchProvider` to `createDatafnClient()`
5. Verify with a search query using `source: "local"`
