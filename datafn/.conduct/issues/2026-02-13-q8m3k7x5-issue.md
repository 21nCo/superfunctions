## User-Reported Issue Description

> The DataFn CLI has a `generateTypes()` function in `codegen.ts` that generates TypeScript interfaces from a DFQL schema, but there is no CLI command to invoke it. The CLI only exposes `generate-migration`. Running `datafn generate-types` returns "Unknown command: generate-types". The intended workflow — DFQL schema JSON as source of truth, CLI generates TypeScript types and migrations — is incomplete because the codegen step requires programmatic usage rather than CLI invocation.

## Summary

The `@datafn/cli` package implements two core capabilities:

1. **`generateTypes()`** in `datafn/cli/src/codegen.ts` — generates TypeScript interfaces, `Tables` mapping type, and `TypedClient` type from a DFQL schema.
2. **`generate-migration`** command in `datafn/cli/src/cli.ts` — generates database migrations from schema diffs.

Only `generate-migration` is wired as a CLI command. `generateTypes()` is exported from the library (`index.ts` line 1: `export { generateTypes } from "./codegen.js"`) but has no corresponding CLI command handler in `cli.ts`. The CLI's command dispatch (line 39–44) only matches `generate-migration`; any other command falls through to "Unknown command" error.

Additionally, both `generate-migration` and a future `generate-types` command only accept **JSON** schema files (`JSON.parse()` at line 52). TypeScript schema files (like `datafn/examples/todo-app/server/src/schema.ts`) cannot be consumed directly, which limits the CLI's usability in projects where the schema is authored in TypeScript.

## Observed Errors / Symptoms

**Running the missing command:**

```bash
$ datafn generate-types --schema ./schema.json --output ./src/types.ts
Unknown command: generate-types
```

**Workaround required:** Users must import `generateTypes` programmatically:

```typescript
import { generateTypes } from "@datafn/cli";
const output = generateTypes(schema);
```

This breaks the intended CLI-driven workflow where `datafn` is the single tool for both codegen and migration generation.

## Root Causes

### RC-1: `generate-types` command handler missing from CLI entry point

**Location**: `datafn/cli/src/cli.ts`, lines 39–44

**Current code:**

```typescript
if (command === 'generate-migration') {
  generateMigration();
} else {
  console.error(`Unknown command: ${command}`);
  printHelp();
  process.exit(1);
}
```

**Expected behaviour**: CLI should also handle `generate-types` (or `codegen`) command, calling `generateTypes()` from `./codegen.js` and writing the output to a file.

**Actual behaviour**: Only `generate-migration` is handled. All other commands fall through to the error path.

**Impact**: The codegen capability specified in CLI-CODEGEN-001 (from specs `2026-01-23-audit-fix-change-spec` and `2026-01-19-change-spec`) is implemented as a library function but not as a CLI command, breaking the intended developer workflow.

## Proposed Fixes

### Fix 1: Wire `generate-types` command in CLI (Primary)

Add a `generate-types` command to `cli.ts` that:

1. Accepts `--schema <path>` (JSON schema file) and `--output <path>` (output `.ts` file, default `./datafn-types.ts`)
2. Reads and parses the schema JSON
3. Calls `generateTypes(schema)` from `./codegen.js`
4. Writes the generated TypeScript to the output path

```typescript
import { generateTypes } from './codegen.js';

// In command dispatch:
if (command === 'generate-migration') {
  generateMigration();
} else if (command === 'generate-types') {
  generateTypesCommand();
} else {
  console.error(`Unknown command: ${command}`);
  printHelp();
  process.exit(1);
}

function generateTypesCommand() {
  if (!values.schema) {
    console.error('Error: --schema <path> is required for generate-types');
    process.exit(1);
  }
  const schema = JSON.parse(readFileSync(resolve(values.schema), 'utf-8'));
  const output = generateTypes(schema);
  const outputPath = resolve(values.output || './datafn-types.ts');
  writeFileSync(outputPath, output);
  console.log(`Types written to: ${outputPath}`);
}
```

### Fix 2: Update help text

Add `generate-types` to the `Commands` section and its specific options to `printHelp()`.

### Fix 3 (Future enhancement): Support TypeScript schema loading

Add optional `.ts` file loading via dynamic `import()` for schema files. This is a separate enhancement that could use `jiti`, `tsx`, or Node's native `--experimental-strip-types` loader. Not blocking for the initial fix since JSON schema files work.
