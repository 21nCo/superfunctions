## Handler Architecture

Each DataFn route is backed by a handler module in `datafn/handlers/`. All handlers follow the same pattern:

1. Parse the incoming request payload.
2. Validate the payload against the schema.
3. Execute the operation against the database adapter.
4. Return a DataFn envelope response.

## Handler Modules

### query.py

Handles `POST /datafn/query`. Accepts a DFQL query object with `resource`, `select`, `filter`, `sort`, `limit`, and `cursor`. Executes against the adapter's `find_many` method and returns matching records in an envelope.

```python
# Internal signature
async def handle_query(ctx, payload, config) -> dict:
    # 1. Validate resource exists in schema
    # 2. Validate filters and select fields
    # 3. Execute query via adapter.find_many()
    # 4. Return {"ok": True, "result": {"records": [...]}}
```

### mutation.py

Handles `POST /datafn/mutation`. Accepts DFQL mutations (`insert`, `merge`, `delete`) with idempotency support.

```python
async def handle_mutation(ctx, payload, config) -> dict:
    # 1. Validate mutation structure
    # 2. Check idempotency (skip if already applied)
    # 3. Execute via adapter.create/update/delete
    # 4. Return {"ok": True, "result": {...}}
```

### transact.py

Handles `POST /datafn/transact`. Executes multiple query and mutation steps within a single database transaction.

```python
async def handle_transact(ctx, payload, config) -> dict:
    # 1. Validate transaction steps
    # 2. Open adapter.transaction() context
    # 3. Execute each step sequentially
    # 4. Commit or rollback
    # 5. Return {"ok": True, "result": {"steps": [...]}}
```

### sync.py

Handles all sync endpoints:

| Function | Route | Description |
|---|---|---|
| `handle_seed` | `POST /datafn/seed` | Bulk insert seed data. |
| `handle_clone` | `POST /datafn/clone` | Paginated full-resource clone. |
| `handle_pull` | `POST /datafn/pull` | Incremental changes since a cursor. |
| `handle_push` | `POST /datafn/push` | Apply client-side mutations with change tracking. |

## Supporting Modules

### validation.py

Validates incoming payloads against the schema. Checks resource names, field names, field types, and structural constraints. Returns envelope errors on validation failure.

### idempotency.py

Tracks mutation IDs to prevent duplicate application. When a mutation with a known ID arrives, the previously stored result is returned without re-execution.

### change_tracking.py

Records mutations as change entries for the sync protocol. Each change is assigned a monotonic sequence number used by `pull` to deliver incremental updates.

## Envelope Format

All handlers return the same envelope format used by the TypeScript server:

```python
# Success
{"ok": True, "result": {...}}

# Error
{"ok": False, "error": {"code": "DFQL_INVALID", "message": "...", "details": {"path": "$"}}}
```

Error codes match the TypeScript implementation: `SCHEMA_INVALID`, `DFQL_INVALID`, `DFQL_UNKNOWN_RESOURCE`, `DFQL_UNKNOWN_FIELD`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `LIMIT_EXCEEDED`, `INTERNAL`.
