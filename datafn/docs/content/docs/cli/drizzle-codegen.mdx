## Overview

The `generateDrizzleSchema(schema, dialect)` function produces a complete Drizzle ORM schema file from a DataFn schema. It validates the schema, ensures the built-in `kv` and [`datafnTimezoneChange`](/docs/dfql/temporal#timezone-change-registry) resources exist, and generates table definitions with column types, indices, foreign keys, and join tables.

```typescript
import { generateDrizzleSchema } from "@datafn/cli";

const code = generateDrizzleSchema(mySchema, "postgres");
// Write `code` to a .ts file
```

## Dialect Support

| Dialect | Table Constructor | Import Path |
|---|---|---|
| `postgres` | `pgTable` | `drizzle-orm/pg-core` |
| `mysql` | `mysqlTable` | `drizzle-orm/mysql-core` |
| `sqlite` | `sqliteTable` | `drizzle-orm/sqlite-core` |

## Column Type Mapping

| Schema Type | PostgreSQL | MySQL | SQLite |
|---|---|---|---|
| `string` | `text()` | `text()` | `text()` |
| `number` | `numeric()` | `int()` | `integer()` |
| `boolean` | `boolean()` | `boolean()` | `datafnBoolean()` (`integer` column) |
| `date` | `bigint({ mode: "number" })` | `bigint({ mode: "number" })` | `integer()` |
| `json` | `jsonb()` | `json()` | `text({ mode: "json" })` |
| `object` | `jsonb()` | `json()` | `text({ mode: "json" })` |
| `array` | `jsonb()` | `json()` | `text({ mode: "json" })` |
| `file` | `text()` | `text()` | `text()` |

### SQLite column modes

SQLite drivers (better-sqlite3, libSQL, Cloudflare D1) bind only numbers, strings, bigints, buffers and `null`, so the generated columns convert DataFn values at the driver boundary:

- `boolean` fields use `datafnBoolean`, a custom type the generated file defines. It stores `true`/`false` as `1`/`0` and reads them back as booleans. Any other value, such as an encrypted envelope from `@datafn/client` end-to-end encryption (`e2ee`), is stored as JSON text and read back unchanged.
- `object`, `array` and `json` fields use `text({ mode: "json" })`: they store JSON text and read back parsed. A default on one of these fields is emitted as its JSON text (`.default(sql.raw("'\"open\"'"))` for `default: "open"`), so rows that `drizzle-kit` migrations fill with the default also parse.

`@datafn/cli` 0.1.1 and earlier emitted plain `integer` and `text` columns. To upgrade, regenerate the schema. The SQL column types are unchanged, so `drizzle-kit generate` produces no migration unless a JSON field has a default. Boolean columns need no data change.

JSON columns do. The old plain `text` column returned whatever string was stored, so a stored `123`, `true` or `null` was the string `"123"`, `"true"` or `"null"`. Read in `json` mode, the same text would become a number, a boolean or `null`. Before you deploy, encode every stored value as a JSON string so `json` mode reads back exactly the strings the old schema returned:

```sql
UPDATE "kv" SET "value" = json_quote("value") WHERE "value" IS NOT NULL;
```

Repeat for each `object`, `array` and `json` column, in every table. Do not decide per row with `json_valid`: a string that happens to be valid JSON would change type. If your application stored serialized JSON in a column itself and parsed it after reading, and you now want DataFn to return the parsed values, convert that column with `json("column")` instead; that statement fails on any row that is not valid JSON.

## Namespace Column

When `schema.namespaced` is `true` (the default), every table includes an `__ns` column for namespace isolation:

```typescript
export const todos = pgTable("todos", {
  __ns: text("__ns").notNull(),
  completed: boolean("completed").notNull(),
  id: text("id").primaryKey(),
  title: text("title").notNull(),
}, (table) => [
  index("idx_todos___ns").on(table.__ns),
]);
```

Set `namespaced: false` in your schema to omit the `__ns` column.

## Index Generation

Each table may include:

- **Namespace index** -- `idx_{table}___ns` when namespace isolation is enabled.
- **Base indices** -- one index per field listed in `indices.base`.
- **Relation FK indices** -- `{table}_{fk_column}_rel_idx` for each generated foreign-key column (see below). Htree relations also index the path column.
- **Join table unique index** -- `{joinTable}_{from}_{to}_idx` for many-many relations.
- **Join table directional indices** -- `{joinTable}_{from}_idx` and `{joinTable}_{to}_idx` for efficient traversal in either direction.

## Join Tables

For `many-many` relations, a join table is generated with:

- The `from` and `to` columns (default names: `from` and `to`, overridable via `joinColumns`).
- An `id` column as the primary key.
- Any `metadata` fields from the relation schema.
- A unique index on `(from, to)`.
- Directional indices on `from` and on `to`.

The join table name defaults to `__datafn_join_{from}_{relation}` unless `joinTable` is specified.

For [polymorphic](/docs/dfql/schema/relations#polymorphic-relations) many-many relations (array `from`/`to`), the join table also gets `fromResource` / `toResource` discriminator columns, and the unique and directional indices include them:

```typescript
fromResource: text("from_resource").notNull(),
toResource: text("to_resource").notNull(),
// uniqueIndex("resource_items_from_to_idx").on(fromResource, from, toResource, to)
// index("resource_items_from_idx").on(fromResource, from)
// index("resource_items_to_idx").on(toResource, to)
```

## Relation Foreign Keys

When a relation (or the schema) uses [`integrity: "database"`](/docs/dfql/schema/relations#relation-integrity), codegen emits real foreign-key columns, indices, and constraints for FK-backed relations (`many-one`, `one-many`, `htree`). The FK column is generated on the holding resource if it is not already declared:

| Relation type | Default FK column | Extra columns |
| --- | --- | --- |
| `many-one` | `fkField` or `{relation}Id` | `{relation}Resource` when `to` is polymorphic |
| `one-many` | `fkField` or `inverse` or `{from}Id` | `{...}Resource` when `from` is polymorphic |
| `htree` | `fkField` or `inverse` or `parentId` | `pathField` (default `parentPath`); `{parent}Resource` when polymorphic |

`onDelete` policies map to Drizzle `ON DELETE` actions on resource foreign keys:

| `onDelete` policy | Drizzle action |
| --- | --- |
| `cascade` | `.onDelete("cascade")` |
| `restrict` | `.onDelete("restrict")` |
| `setNull` / `detach` | `.onDelete("set null")` |
| _(absent)_ | no `.onDelete` clause |

Example (namespaced, `onDelete: { to: "setNull" }`):

```typescript
index("task_project_id_rel_idx").on(table.__ns, table.projectId),
foreignKey({
  columns: [table.__ns, table.projectId],
  foreignColumns: [project.__ns, project.id],
}).onDelete("set null"),
```

Foreign-key **constraints** are not emitted for polymorphic join tables (which use discriminator columns instead). Join-table FKs are emitted only when integrity is `"database"` and the endpoint is non-polymorphic; their `onDelete` mapping is `restrict` → `restrict`, and `cascade`/`detach`/`setNull` → `cascade`.

## Built-in Resources

Generated schemas always include the internal `__datafn_*` tables, the built-in `kv` table, and the [`datafnTimezoneChange`](/docs/dfql/temporal#timezone-change-registry) table (injected via `ensureBuiltinTemporal`). The temporal table's `number` columns mean minimal Postgres schemas now also import `numeric`.

## Example Output

```typescript
// Generated by @datafn/cli. DO NOT EDIT.
// Database: postgres
import { boolean, index, pgTable, text } from "drizzle-orm/pg-core";

export const todos = pgTable("todos", {
  __ns: text("__ns").notNull(),
  completed: boolean("completed").notNull(),
  id: text("id").primaryKey(),
  title: text("title").notNull(),
}, (table) => [
  index("idx_todos___ns").on(table.__ns),
]);

export const schema = { todos };
```

## Exports

All tables are exported as named constants. A `schema` object is exported that maps table variable names to their definitions, sorted alphabetically.
