## Summary

**Severity: High**

Four distinct but interrelated bugs prevent docsfn from functioning as a usable documentation framework out of the box. (1) The three-column layout (sidebar / main / TOC) has no CSS, causing the sidebar and TOC to scroll with the main content instead of being sticky. (2) Markdown tables are not recognized by the block parser and are silently swallowed into paragraph text. (3) Sidebar groups open by default due to inverted boolean semantics — the `collapsed` property should be replaced with `expanded` and groups should default to collapsed. (4) The TOC's IntersectionObserver uses `threshold: 1.0`, which almost never fires, so the active heading indicator doesn't work during scrolling.

---

## Observed Errors / Symptoms

1. **Sidebar scrolls with main content** — The left sidebar and right TOC scroll away as the user scrolls the page; they are not pinned to the viewport.
2. **Markdown tables not rendered** — Pipe-syntax markdown tables (`| col | col |`) appear as mangled paragraph text instead of `<table>` HTML.
3. **All sidebar groups expanded by default** — Every sidebar group is open when the page loads; users expect collapsed-by-default with only the active group auto-expanded.
4. **TOC shows no active indicator while scrolling** — The "On this page" links never highlight to reflect the current scroll position.

## Root Causes

### RC-1: No CSS for the three-column layout container

**Location:** `docsfn/svelte/src/theme.css` (entire file — no rules for layout classes), `docsfn/svelte/src/theme-base.css` (entire file — same), `docsfn/react/src/theme.css`, `docsfn/react/src/theme-base.css`

**Affected classes:** `.docsfn-layout`, `.docsfn-container`, `.docsfn-sidebar-col`, `.docsfn-main`, `.docsfn-toc-col`

**Current code** (`DocsLayout.svelte`, lines 52–101):

```svelte
<div class="docsfn-layout">
  <header class="docsfn-topbar">...</header>
  <div class="docsfn-container">
    <aside class="docsfn-sidebar-col">...</aside>
    <main class="docsfn-main">...</main>
    <aside class="docsfn-toc-col">...</aside>
  </div>
</div>
```

The component emits five structural class names. Neither `theme.css` nor `theme-base.css` defines **any** rules for these classes — no `display: grid/flex`, no `position: sticky`, no `height` constraints. The only layout scoped CSS in `DocsLayout.svelte` handles the mobile sidebar drawer (lines 103–155) via `<style>` block, but provides no desktop layout.

**Expected behavior:** `.docsfn-container` should be a grid/flex container with three columns. `.docsfn-sidebar-col` and `.docsfn-toc-col` should have `position: sticky; top: <topbar-height>; height: calc(100vh - <topbar-height>); overflow-y: auto` so they remain fixed while `.docsfn-main` scrolls.

**Actual behavior:** All three columns flow as block elements in a single scroll context. The sidebar viewport has `overflow-y: auto` and `max-height` (theme-base.css line 95–98), but the parent column has no sticky positioning, so the `overflow-y` never activates on desktop.

**Impact:** The fundamental documentation layout is broken — sidebar and TOC are unusable on any page longer than one viewport.

### RC-2: Block parser has no `table` block type — tables fall through to paragraph

**Location:** `docsfn/core/src/markdown.ts`

- `CompiledContentBlock` union (lines 9–55): No `table` variant exists.
- `isBlockStart()` (lines 189–201): Does not detect table syntax (lines starting with `|`).
- `parseBlocks()` paragraph fallback (lines 541–554): Unrecognized lines are joined into a single paragraph.

**Current code** (`isBlockStart`, lines 189–201):

```typescript
function isBlockStart(line: string): boolean {
  const trimmed = line.trim();
  return (
    trimmed.length === 0 ||
    HEADING_REGEX.test(trimmed) ||
    CODE_FENCE_REGEX.test(trimmed) ||
    TABS_START_REGEX.test(trimmed) ||
    CALLOUT_REGEX.test(trimmed) ||
    COMPONENT_SELF_CLOSING_REGEX.test(trimmed) ||
    COMPONENT_START_REGEX.test(trimmed) ||
    isListStart(line)
  );
}
```

**Current code** (paragraph fallback, lines 541–554):

```typescript
const paragraphLines: string[] = [];
while (index < lines.length && !isBlockStart(lines[index])) {
  paragraphLines.push(lines[index].trim());
  index += 1;
}
if (paragraphLines.length > 0) {
  const paragraphText = paragraphLines.join(" ").trim();
  blocks.push({
    type: "paragraph",
    text: paragraphText,
    html: renderInlineHtml(paragraphText),  // inline, not block!
  });
}
```

**Expected behavior:** Markdown tables (`| Header | Header |` / `|---|---|` / `| Cell | Cell |`) should be parsed as a `table` block type and rendered via `marked.parse()` (block-level) to produce `<table>` HTML.

**Actual behavior:** Table lines start with `|`, which doesn't match any `isBlockStart` pattern. All table lines are collected by the paragraph fallback, joined with spaces into a single string, and rendered via `renderInlineHtml()` (which calls `marked.parseInline()` — inline-only, no table support). The result is garbled text like `| Header | Header | |---| | Cell | Cell |`.

**Additionally:** Neither `theme.css` nor `theme-base.css` has any CSS rules for `table`, `th`, `td` elements within `.docsfn-content`, so even if tables were rendered, they would be unstyled.

**Impact:** Tables — a core GFM feature used extensively in documentation — are completely broken.

### RC-3: Sidebar groups default to expanded due to inverted boolean semantics

**Location:**
- `docsfn/core/src/types.ts`, line 94: `collapsed?: boolean`
- `docsfn/svelte/src/SidebarGroup.svelte`, line 29
- `docsfn/react/src/DocsSidebar.tsx`, line 69–70

**Current code** (`SidebarItem` type, `docsfn/core/src/types.ts` lines 89–95):

```typescript
export interface SidebarItem {
  type: "link" | "group" | "separator";
  text: string;
  link?: string;
  items?: SidebarItem[];
  collapsed?: boolean;
}
```

**Current code** (Svelte, `SidebarGroup.svelte` line 29):

```svelte
open={!defaultCollapsed && (item.collapsed === false || hasActiveChild)}
```

**Current code** (React, `DocsSidebar.tsx` lines 69–70):

```tsx
const defaultOpen =
  defaultCollapsed !== true && (item.collapsed === false || hasActiveChild);
```

**Analysis of the boolean logic:** When `item.collapsed` is `undefined` (the common case — not explicitly set in sidebar config):

- `item.collapsed === false` → `false` (undefined !== false)
- `hasActiveChild` → `true` only for the group containing the active page
- Result: `open = !false && (false || hasActiveChild)` → `open = hasActiveChild`

So groups without the active child **should** be closed. However, the issue is that `collapsed` is a double-negative API: `collapsed: false` means "open", `collapsed: undefined` means "use default", and `collapsed: true` means "force closed". This is confusing and inverted from what users expect.

**Expected behavior:** The property should be `expanded?: boolean` with groups defaulting to **collapsed**. Only the group containing the active page auto-expands. Setting `expanded: true` on a group keeps it always open.

**Actual behavior:** The `collapsed` property name creates double-negative confusion. The current logic means `collapsed: false` (explicitly "not collapsed" = expanded) OR `hasActiveChild` opens a group. If sidebar data generators set `collapsed: false` on all groups (which is natural since they want groups to be "not collapsed by default"), every group opens.

**Impact:** Documentation sites with many sections show an overwhelming, fully-expanded sidebar that defeats the purpose of hierarchical navigation.

### RC-4: TOC IntersectionObserver threshold of 1.0 prevents active indicator from firing

**Location:**
- `docsfn/svelte/src/DocsToc.svelte`, lines 25–40
- `docsfn/react/src/DocsToc.tsx`, lines 26–42

**Current code** (Svelte, `DocsToc.svelte` lines 25–40):

```typescript
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        const id = entry.target.getAttribute('id');
        if (id) {
          currentHash = `#${id}`;
        }
      }
    });
  },
  {
    rootMargin: '-80px 0px -80% 0px',
    threshold: 1.0,
  }
);
```

**Current code** (React, `DocsToc.tsx` lines 26–42) — identical logic:

```typescript
const observer = new IntersectionObserver(
  (entries) => { ... },
  {
    rootMargin: "-80px 0px -80% 0px",
    threshold: 1,
  }
);
```

**Expected behavior:** As the user scrolls, the TOC link corresponding to the currently visible section should be highlighted with the `.active` class (which correctly applies `color: var(--docsfn-color-primary)` per theme.css line 345–347).

**Actual behavior:** The observer almost never fires because:

1. **`threshold: 1.0`** requires the heading element to be **100% visible** within the root bounds.
2. **`rootMargin: '-80px 0px -80% 0px'`** shrinks the observation zone to a narrow band: top 20% of the viewport minus 80px from the top. This is roughly a 100–150px tall strip.
3. A heading element (typically `<h2>` or `<h3>`) must be **entirely** within this narrow strip for the callback to fire. If even 1px of the heading is outside, `isIntersecting` remains `false` at `threshold: 1.0`.
4. The observer only sets the active hash when `entry.isIntersecting === true` — it never tracks which heading was "last seen" when scrolling past, so rapid scrolling skips headings entirely.

**Fix:** Change `threshold` to `0` (fire when any part of the heading enters the zone) and implement a "last visible heading wins" strategy instead of "currently intersecting heading wins".

**Impact:** The TOC active indicator — a standard docs UX feature — never works in practice, making the TOC a static list rather than an interactive scroll spy.

## Proposed Fixes

### Fix for RC-1: Add three-column layout CSS to theme-base.css and theme.css

Add to **`theme-base.css`** (structural rules):

```css
.docsfn-layout {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}

.docsfn-container {
  display: grid;
  grid-template-columns: 16rem 1fr 14rem;
  flex: 1;
  max-width: 90rem;
  margin: 0 auto;
  width: 100%;
}

.docsfn-sidebar-col {
  position: sticky;
  top: 0;
  height: 100vh;
  overflow-y: auto;
  padding: 1rem;
}

.docsfn-main {
  min-width: 0;
  padding: 1.5rem 2rem;
}

.docsfn-toc-col {
  position: sticky;
  top: 0;
  height: 100vh;
  overflow-y: auto;
  padding: 1rem;
}

@media (max-width: 1279px) {
  .docsfn-container { grid-template-columns: 16rem 1fr; }
  .docsfn-toc-col { display: none; }
}

@media (max-width: 1023px) {
  .docsfn-container { grid-template-columns: 1fr; }
  .docsfn-sidebar-col { display: none; }
}
```

Add to **`theme.css`** (visual rules):

```css
.docsfn-sidebar-col {
  background: var(--docsfn-color-surface);
  border-right: 1px solid var(--docsfn-color-border);
}

.docsfn-toc-col {
  border-left: 1px solid var(--docsfn-color-border);
}
```

Apply equivalent rules to **React** `theme-base.css` and `theme.css`.

### Fix for RC-2: Add table block type to the markdown compiler

1. Add a `table` variant to `CompiledContentBlock`:
   ```typescript
   | { type: "table"; html: string }
   ```

2. Add a table detection regex and check in `isBlockStart()`:
   ```typescript
   const TABLE_ROW_REGEX = /^\|.+\|$/;
   // Add to isBlockStart:  TABLE_ROW_REGEX.test(trimmed)
   ```

3. Add a `parseTableBlock()` function that collects consecutive `|`-prefixed lines and renders them via `renderBlockHtml()` (which calls `marked.parse()` with GFM table support).

4. Add table rendering branches to `DocsContent.svelte` and `DocsContent.tsx`:
   ```svelte
   {:else if block.type === "table"}
     {@html block.html}
   ```

5. Add table styles to `theme-base.css` and `theme.css`:
   ```css
   .docsfn-content table { width: 100%; border-collapse: collapse; margin: 1rem 0; }
   .docsfn-content th, .docsfn-content td { padding: 0.5rem 0.75rem; border: 1px solid var(--docsfn-color-border); text-align: left; }
   .docsfn-content th { font-weight: 600; background: var(--docsfn-color-surface-raised); }
   ```

### Fix for RC-3: Rename `collapsed` to `expanded` and default to collapsed

1. In `docsfn/core/src/types.ts`, change `SidebarItem`:
   ```typescript
   export interface SidebarItem {
     type: "link" | "group" | "separator";
     text: string;
     link?: string;
     items?: SidebarItem[];
     expanded?: boolean;  // was: collapsed?: boolean
   }
   ```

2. Update Svelte (`SidebarGroup.svelte` line 29):
   ```svelte
   open={item.expanded === true || hasActiveChild}
   ```

3. Update React (`DocsSidebar.tsx` lines 69–70):
   ```tsx
   const defaultOpen = item.expanded === true || hasActiveChild;
   ```

4. Remove `defaultCollapsed` / `defaultCollapsedGroups` props — they become unnecessary since the default is now collapsed.

5. Update any sidebar data generators that set `collapsed: false` to instead set `expanded: true` only where perpetually-open groups are desired.

### Fix for RC-4: Fix IntersectionObserver threshold and tracking logic

1. Change `threshold` from `1.0` to `0`:
   ```typescript
   { rootMargin: '-80px 0px -80% 0px', threshold: 0 }
   ```

2. Track the topmost intersecting heading instead of the last one that fired:
   ```typescript
   const observer = new IntersectionObserver(
     (entries) => {
       for (const entry of entries) {
         if (entry.isIntersecting) {
           const id = entry.target.getAttribute('id');
           if (id) {
             currentHash = `#${id}`;
             break; // first intersecting = topmost visible
           }
         }
       }
     },
     { rootMargin: '-80px 0px -80% 0px', threshold: 0 }
   );
   ```

Apply the same fix to both Svelte (`DocsToc.svelte`) and React (`DocsToc.tsx`).
