# Summary
The soft-delete plugin is still an active, exported, tested, and documented feature in `datafn`, while capability-first lifecycle behavior (`trash`/`restore`) has been introduced and positioned as the primary model. This creates a documentation and product-surface inconsistency: plugin-based soft delete remains first-class despite current direction to remove legacy/migration-era dual paths. Severity: **Medium**.

# Observed Errors/Symptoms
- `@datafn/client` still exports `createSoftDeletePlugin` and `restore` from the public API.
- The plugin implementation actively transforms `delete` into `merge` and injects query filters.
- Tests explicitly verify the plugin still functions and emits no deprecation warning.
- Documentation still has a dedicated soft-delete plugin page and multiple cross-links/examples.
- Capabilities docs state `delete` remains hard delete, but soft-delete docs still teach plugin interception of delete.

# Proposed Fixes
1. Remove soft-delete plugin from client public API and delete `datafn/client/src/plugins/softDelete.ts` plus all imports/re-exports.

3. Remove plugin docs artifacts:
   - Delete `datafn/docs/content/docs/documentation/plugins/soft-delete.mdx`
   - Remove `soft-delete` from `datafn/docs/content/docs/documentation/plugins/meta.json`

5. Run full docs build and targeted client tests after cleanup to confirm no stale links/imports remain.
