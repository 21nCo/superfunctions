## 🔴 Critical Issues (4 grouped findings / 10 raw comments)

### `datafn/server/src/validation/authz.ts` - resource-scope authorization
**📁 File:** `datafn/server/src/validation/authz.ts`

#### Issue 1: Resource-scoped share/unshare can bypass owner verification *(CodeRabbit)*
- **Severity:** Critical
- **Location:** Lines 723-736
- **Description:** CodeRabbit flagged that `share` and `unshare` operations can return `{ ok: true }` for resource-scoped requests when `actorId` exists, without enforcing owner-level verification. The comment describes this as a privilege-escalation path because resource-scope grants can be created or removed without the record-owner check used for record scope.
- **Fix:** Require owner verification for resource-scoped `share` / `unshare` in both validation and execution paths, or explicitly disallow resource-scope grants until an alternate privilege model is implemented.

### `datafn/client/src/extension/subscriptionManager.ts` - subscription lifecycle race
**📁 File:** `datafn/client/src/extension/subscriptionManager.ts`

#### Issue 2: Subscription state can be lost while remote unsubscribe is still in flight *(Codex, cubic)*
- **Severity:** High
- **Location:** Lines 72, 96
- **Description:** Codex and cubic both reported that the manager deletes local subscription state before `unsubscribeRemote()` succeeds. If the remote unsubscribe fails, the branch loses the tracked `subscriptionId`, leaving an orphaned remote subscription that later cleanup cannot retry.
- **Fix:** Keep the map entry until remote unsubscribe completes successfully, or restore the entry on failure. Defer deletion until after the unsubscribe promise resolves.

#### Issue 3: Concurrent subscribers can reuse a subscription before the initial remote subscribe settles *(Codex)*
- **Severity:** High
- **Location:** Line 82
- **Description:** Codex reported that concurrent `registerSubscriber()` calls can treat an in-flight remote subscription as ready. If the first `subscribeRemote()` later fails, later callers can think they are subscribed even though no remote subscription exists.
- **Fix:** Track the in-flight subscribe promise and make subsequent subscribers await the same promise before treating the entry as active.

### `packages/python-core/superfunctions/oauth.py` - OAuth start policy enforcement
**📁 File:** `packages/python-core/superfunctions/oauth.py`

#### Issue 4: Redirect URI allowlist is not enforced before OAuth flow start *(Codex)*
- **Severity:** High
- **Location:** Line 296
- **Description:** Codex reported that `start()` forwards `input.redirect_uri` into state and the authorization URL without checking `allowlisted_redirect_uris`. That defeats the provider runtime allowlist and can permit unapproved callback destinations.
- **Fix:** Validate `input.redirect_uri` against the configured allowlist before storing state or building the authorization URL, and raise the expected `OAUTH_REDIRECT_DISALLOWED` error on mismatch.

### `filefn/python/filefn/server/dedup/service.py` - null-tenant dedup semantics
**📁 File:** `filefn/python/filefn/server/dedup/service.py`

#### Issue 5: Tenantless dedup query changed NULL semantics and used an unsupported operator *(Sourcery, Codex, Greptile, CodeRabbit, cubic)*
- **Severity:** Medium
- **Location:** Lines 72-76
- **Description:** Five tools reported the same underlying problem: the change from a NULL-style tenant match to `operator: 'is'` with an empty-string value can miss tenantless rows or fail entirely because the shared operator set expects `is-null` / `is-not-null`. Some tool comments later marked this as addressed in commits `eb062ca` or `2a118c9`.
- **Fix:** Use the shared null operator semantics consistently (`is-null` if the storage convention is NULL, or `eq ''` if empty string is truly canonical) and keep tenantless dedup behavior covered by tests.

#### Issue 6: Silent skip on malformed `fileId` can hide corrupted dedup rows *(CodeRabbit)*
- **Severity:** Medium
- **Location:** Line 88
- **Description:** CodeRabbit reported that silently `continue`-ing when `existing_version.fileId` is not a string masks contract violations in persisted dedup data and can cause missed duplicates.
- **Fix:** Fail fast with an explicit error or a clear validation path instead of silently skipping corrupted rows.

### `packages/python-core/superfunctions/oauth.py` - callback and failure-event handling
**📁 File:** `packages/python-core/superfunctions/oauth.py`

#### Issue 10: Callback flow misses state-expiry validation *(CodeRabbit)*
- **Severity:** Medium
- **Location:** Line 351
- **Description:** CodeRabbit reported that callback handling persists `expiresAt` in state records but does not check expiry before using the state, leaving expiry enforcement up to each state-store implementation.
- **Fix:** Validate the normalized state's expiry before provider comparison or token exchange and emit the corresponding OAuth failure event when expired.

#### Issue 11: Callback token exchange and identity resolution trust incomplete callback state *(CodeRabbit, cubic)*
- **Severity:** Medium
- **Location:** Lines 368-369
- **Description:** CodeRabbit reported that token exchange should use the state-bound `redirect_uri` rather than the callback payload, and cubic reported that `consumed.subject` is optional but dereferenced without a guard. Both findings point to insufficient validation of the consumed state record before using it for exchange and identity resolution.
- **Fix:** Use the redirect URI stored in consumed state, resolve/validate the stored subject before dereferencing it, and fail with a clear OAuth error when callback state is incomplete.

#### Issue 12: Failure events are mislabeled or missing for non-callback flows *(CodeRabbit, Codex, cubic)*
- **Severity:** Medium
- **Location:** Lines 303, 441, 460
- **Description:** Several tools reported that `_emit_failure()` always emits `oauth.flow.callback.failed`, which mislabels disconnect failures, and that `start()` lacks an equivalent failure emission path.
- **Fix:** Parameterize failure-event names by operation and emit `oauth.flow.start.failed` / `oauth.flow.disconnect.failed` as appropriate.
