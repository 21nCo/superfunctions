### `filefn/swift/Sources/FileFnWebViewBridgeHost/FileFnBridgePreviewSchemeHandler.swift`
**Tools:** `greptile-apps[bot]`, `coderabbitai[bot]`

**Locations:** lines `45-47`

**Issue:** `WKURLSchemeTask` cancellation is not tracked. If WebKit stops a task and the async work later calls `didReceive` or `didFinish` on that stopped task, the app can crash with a WebKit consistency exception.

**Suggested fix:** Track active tasks by `WKURLSchemeTask`, cancel them from `stop`, and check for cancellation before touching the scheme task callbacks.

**Suggested fix:** Scope request/event state to each bus instance and make the global receive entrypoint route messages to the correct instance instead of a shared singleton set.

## Medium Severity Issues

### `filefn/swift/Sources/FileFnClient/FileFnLogger.swift` and `filefn/swift/Sources/FileFnWebViewBridgeHost/FileFnBridgeProtocol.swift`
**Tools:** `cubic-dev-ai[bot]`, `coderabbitai[bot]`

**Locations:** `FileFnLogger.swift:82`, `FileFnBridgeProtocol.swift:386`

**Issue:** `file://` URLs with query parameters are sanitized in the wrong order, so the query gets redacted but the local filesystem path can still leak into logs or bridge-visible strings.

**Suggested fix:** Treat `file://` URLs as a special case before generic query redaction and return only the basename, optionally preserving that a query existed without exposing the path.

### `filefn/swift/Sources/FileFnWebViewBridgeHost/FileFnBridgeDispatcher.swift`
**Tools:** `chatgpt-codex-connector[bot]`, `cubic-dev-ai[bot]`, `coderabbitai[bot]`

**Locations:** lines `25`, `308`, `341`, `372`, `412`

**Issue:** Foreground upload bridge state is internally inconsistent. Reviewers called out two separate but related problems:
- `bytesExpected` starts at `0` and is not persisted correctly for foreground uploads, so `upload.status` can report `0/0` or reset final byte counts
- abort/cancel paths are not idempotent, so terminal uploads can be rewritten to `cancelled` and `upload.cancelled` can be emitted twice

**Suggested fix:** Make progress state mutable where needed, persist total bytes from progress events, preserve terminal byte counts, and guard cancellation so state and events change only once.

### `filefn/swift/Sources/FileFnSwiftUI/FileFnFileImporterLoader.swift`
**Tool:** `coderabbitai[bot]`

**Locations:** lines `19`, `39`

**Issue:** Two importer problems were flagged:
- security-scoped access is started on a normalized URL instead of the original picker URL, which can drop the sandbox extension token
- the importer reads the entire source file into `Data` and writes it back out, doubling peak memory for large files

**Suggested fix:** Start/stop security-scoped access on the original picker URL and copy or stream the file into the app-owned location instead of round-tripping through `Data`.

### `filefn/swift/Sources/FileFnClient/FileFnClient+Uploads.swift`
**Tool:** `cubic-dev-ai[bot]`

**Location:** line `154`

**Issue:** `uploadPart` converts `CancellationError` into a generic transport error, which breaks structured cancellation for callers and higher-level upload orchestration.

**Suggested fix:** Re-throw `CancellationError` unchanged and only wrap non-cancellation failures as transport errors.

### `filefn/swift/Sources/FileFnClient/Upload/FileFnFileSystemUploadStateStore.swift`
**Tool:** `cubic-dev-ai[bot]`

**Location:** line `63`

**Issue:** `uploadID` is used directly as a path component for snapshot files. A crafted ID containing path separators could escape the snapshot directory and target unexpected files.

**Suggested fix:** Validate or sanitize `uploadID` before using it in paths, or derive a filesystem-safe filename from a hash/encoding instead of raw input.

### `filefn/swift/Sources/FileFnWebViewBridgeHost/FileFnNativeAssetRegistry.swift`
**Tools:** `cubic-dev-ai[bot]`, `coderabbitai[bot]`

**Locations:** lines `37`, `67`

**Issue:** Preview URLs are built with `URL(string:)!` from configurable `previewScheme` and caller-controlled `assetHandle`. Invalid characters or malformed schemes can crash the app or produce ambiguous preview URLs.

**Suggested fix:** Construct preview URLs with `URLComponents` or another validated path builder and reject invalid scheme/handle inputs instead of force-unwrapping.

### `filefn/swift/Sources/FileFnWebViewBridgeHost/FileFnWKWebViewBridgeHost.swift`
**Tools:** `coderabbitai[bot]`, `cubic-dev-ai[bot]`

**Locations:** lines `52`, `92`, `114`

**Issue:** Two host lifecycle/threading issues were flagged:
- the dispatcher handshake boundary persists across host reuse, so a fresh page/webview can inherit a completed handshake
- response delivery reaches `WKWebView.evaluateJavaScript(...)` from a generic `Task`, which can run off-main and trigger WebKit threading problems

**Suggested fix:** Reset handshake state on detach/re-attach and force all WebView delivery work onto the main actor.

### `filefn/swift/Sources/FileFnClient/Upload/FileFnUploadPreprocessor.swift`
**Tool:** `cubic-dev-ai[bot]`

**Location:** line `96`

**Issue:** Prepared uploads validate that the source is a regular file, but do not verify that the declared `fileSize` still matches the file on disk. Chunk sizing and upload progress can drift if those diverge.

**Suggested fix:** Compare the declared size against the file’s actual size during validation and fail early when they do not match.
