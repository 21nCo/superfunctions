### **authfn/core/src/plugins/social-oauth.ts - Apple OAuth Token Verification**
**📁 File:** `authfn/core/src/plugins/social-oauth.ts`

#### **Issue 1:** Verify Apple `form_post` ID tokens before trusting claims *(Codex)*
- **Severity:** High
- **Location:** Line 1215
- **Description:** The Apple `response_mode=form_post` path decodes `id_token` claims without verifying JWT signature, issuer, or audience. A forged token with the observed nonce could link/create a forged identity.
- **Fix:** Use the same JWT verification and audience/issuer checks as the native Apple path before accepting form_post claims.

#### **Issue 2:** Verify Apple `form_post` tokens before trusting claims *(CodeRabbit AI)*
- **Severity:** High
- **Location:** Line 1228
- **Description:** CodeRabbit independently reported that the helper only decodes the JWT payload and checks nonce, leaving the form_post OAuth callback open to forged ID token claims.
- **Fix:** Verify token signature and Apple issuer/audience before resolving the profile.

### **authfn/core/src/core/regions.ts - Region Lookup Correctness**
**📁 File:** `authfn/core/src/core/regions.ts`

#### **Issue 6:** Treat existing lookup records as idempotent, not automatic conflicts *(CodeRabbit AI)*
- **Severity:** High
- **Location:** Line 406
- **Description:** `putIfAbsent()` returns an existing record on repeated registrations. Throwing unconditionally can make retry/replay paths fail even when the existing record already matches the same user/region.

- **Location:** Line 374
- **Description:** Cubic reported the same retry/idempotency failure: repeat registrations can fail and desynchronize local/global state.
