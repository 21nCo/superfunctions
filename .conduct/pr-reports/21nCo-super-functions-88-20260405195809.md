This PR adds a new `hostfn/docs` workspace and changes `hostfn/cli` deployment bundling for npm workspaces. Review activity came from Codex, cubic, Greptile, Qodo, Sourcery, CodeRabbit, Socket, and Qodo summary bots. The highest-signal issues are a deploy-time regression around lifecycle scripts, a docs component correctness bug in Mermaid rendering, and a lockfile generation correctness problem in workspace bundling. The rest of the queue is mostly documentation-accuracy cleanup plus bot summaries and dependency alerts.

## Critical Issues

### 1. Unconditional `--ignore-scripts` can break valid deployments
- **Tool:** Codex
- **Severity:** P1
- **File:** `hostfn/cli/src/commands/deploy.ts`
- **Issue:** The deploy flow now appends `--ignore-scripts` to npm install paths unconditionally. That disables legitimate lifecycle hooks like `postinstall`, which some production dependencies use to fetch or build platform binaries.
- **Impact:** Services that previously deployed correctly can now fail at build time or runtime on the target host.
- **Suggested fix:** Gate `--ignore-scripts` to the workspace-bundle edge case that motivated it, or make it configurable.

### 2. Mermaid render cache key is incorrect
- **Tool:** cubic
- **Severity:** P1
- **File:** `hostfn/docs/components/mdx/mermaid.tsx`
- **Issue:** cubic identified that the render cache key omits `id`, but `mermaid.render(...)` uses that `id` to generate internal element identifiers and bindings.
- **Impact:** Repeated diagrams with the same chart/theme pair can reuse cached SVG with duplicate IDs and broken interactivity/bindings.
- **Suggested fix:** Include `id` in the cache key, or cache only inputs that are actually safe to share across render instances.

## Medium Severity Issues

### 1. Local workspace deployments can drop bundled build output
- **Tool:** Codex
- **Severity:** P2
- **File:** `hostfn/cli/src/commands/deploy.ts`
- **Issue:** The local copy filter still excludes any path containing `dist`, which can remove compiled artifacts inside `__workspace__/.../dist`.
- **Impact:** Local-mode deployments can miss required JS or type output from bundled workspace packages.
- **Suggested fix:** Anchor the `dist` exclusion so it only targets the service root `dist`, not workspace package outputs.

### 2. Generated bundle lockfile can pin the wrong dependency version
- **Tool:** Qodo
- **Severity:** P2
- **File:** `hostfn/cli/src/core/workspace.ts`
- **Issue:** `generateLockfile()` looks up direct dependency versions using only root-level `node_modules/<name>` entries from the monorepo lockfile.
- **Impact:** In a monorepo with multiple versions of the same dependency, the generated bundle lockfile can pin an incompatible version instead of the one resolved by the target workspace.
- **Suggested fix:** Prefer workspace-scoped lockfile entries for the target service path, and only pin versions that satisfy the declared semver range.

### 3. Root docs contain multiple implementation mismatches
- **Tool:** cubic
- **Severity:** Mostly P2
- **Files:** Multiple `hostfn/docs/content/docs/**/*.mdx`
- **Issue:** cubic identified a broad batch of docs that describe behavior the CLI does not currently implement.
- **Representative examples:**
  - `hostfn/docs/content/docs/documentation/advanced/backups.mdx`
    - rollback does not reinstall dependencies
  - `hostfn/docs/content/docs/documentation/concepts/configuration.mdx`
    - only `nodejs` is currently supported as a runtime
    - `health.timeout` is not actually enforced as documented
  - `hostfn/docs/content/docs/reference/config-schema.mdx`
    - `env.required` is not merely a warning path
  - `hostfn/docs/content/docs/documentation/advanced/rollback.mdx`
    - rollback does not restore `package.json`
  - `hostfn/docs/content/docs/documentation/advanced/ssh.mdx`
    - `hostfn deploy ... --password` is not a real CLI flag
  - `hostfn/docs/content/docs/cli/init.mdx`
    - runtime detection is overstated
  - `hostfn/docs/content/docs/documentation/server-management/domains.mdx`
    - per-service domain support is overstated
  - `hostfn/docs/content/docs/documentation/advanced/troubleshooting.mdx`
    - remote deploys still require `rsync`
  - `hostfn/docs/content/docs/documentation/advanced/health-checks.mdx`
    - `health.interval` units are documented incorrectly
  - `hostfn/docs/content/docs/documentation/deployment/single-service.mdx`
    - `.env` can affect port, and PM2 instance behavior is misdescribed
  - `hostfn/docs/content/docs/documentation/deployment/ci-cd.mdx`
    - path-change example can skip valid deployments
- **Impact:** The new docs package risks shipping a lot of inaccurate operational guidance on first release.
- **Suggested fix:** Treat this as a docs-truth pass before merge. The code paths and the docs should be reconciled one page at a time.
