## Priority Action Items

1. Fix the mutation scheduling semantics in `datafn/client/src/mutate.ts` so `schedulePush()` is non-fatal after the durable local write has succeeded.
2. Fix Swift runtime correctness issues in the bridge/sync layer:
   - `DatafnWKWebViewBridgeHost.swift` main-thread enforcement
   - `DatafnServerSyncEngine.swift` startup/reset behavior
   - `DatafnServerSyncEngine.swift` clone replacement behavior
   - `DatafnServerSyncEngine.swift` inner `result.ok` validation
3. Fix the host/runtime contract mismatches:
   - exact `remoteProfile` validation
   - correct CloudKit `databaseScope` forwarding
   - emit `health.changed` search metadata updates
4. Close the `icloud` behavior gaps:
   - reject remote-only resources in batched queries
   - document the `icloud` + `isRemoteOnly` constraint clearly
5. Clean up packaging/runtime edges before merge:
   - `datafn/swift-bridge` built entrypoint
   - wildcard dependency versions
   - public import paths instead of monorepo source imports

## Testing Recommendations

- Add regression coverage proving `mutate()` remains successful when push scheduling fails after the local write has already committed.
- Add explicit negative-path tests for sync responses where outer transport succeeds but inner `result.ok` is false.
- Add clone snapshot tests proving stale local rows are removed when clone results represent full replacement state.
- Add bridge tests that verify `evaluateJavaScript(...)` always runs on `MainActor`.
- Add `icloud` batch-query tests covering remote-only resources.
- Add native search lifecycle tests for search metadata event emission and for bridge readiness gating during search-provider startup.
- Add packaging or smoke tests for the published `datafn/swift-bridge` entrypoint rather than only source-in-repo imports.

## Summary

The automated review signal on PR `#53` is materially non-empty. The most important risks are in the native sync and bridge layers, where a few issues can cause false mutation failures, broken retry/recovery behavior, stale clone state, and handshake/runtime mismatches. There is also a second tier of medium-risk work around `icloud` parity, search initialization, packaging correctness, and queue handling.

Recommended merge posture: **do not merge until the critical issues are triaged and either fixed or explicitly waived with code-level justification**.
