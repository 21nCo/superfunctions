# Immutable evidence payload boundaries

Original requirements EVID-001 and SPEC evidence semantics/invariants require immutable evidence and stable rereads. The shared memory adapter retains nested object references. CompFn previously passed caller-owned payloads into that adapter and returned its stored payload object directly from create/get/list. A public API reproduction changed stored evidence by mutating either the original input or the create response, without any evidence update method. Mutating scoping payloads could therefore change readiness while retaining the same evidence identity.

CompFn now serializes payloads once before the first asynchronous control lookup, checks the existing UTF-8 payload limit, parses a detached snapshot, and persists that snapshot. Serialized values must remain objects and satisfy the existing scoping status rule. Returned payloads are detached at the common row-to-evidence boundary, covering create/get/list and downstream auditor-pack responses. Shared storage code, schema, timestamps, evidence IDs and external artifacts are unchanged.

Validation on Node 20.20.0:

- Six focused tests pass with actual shared memory and native better-sqlite3/Drizzle adapters. They cover input mutation, create/get/list/export result mutation, nested arrays, readiness preservation, SQLite close/reopen, pending control lookup on both providers, once-only serialization, exact UTF-8 byte limits and invalid serialized scoping values.
- Before the change, the initial three-case source fixture failed its memory-alias and pending-lookup cases; ordinary SQLite response isolation already passed. `/tmp/compfn-immutability-before.log` also contains an unrelated workspace-selection no-test error from the admin package; final commands target the core package directly with `npm --prefix compfn`.
- `npm --prefix compfn test`: 129 tests pass across 16 files, including evidence, readiness, export, native persistent CLI and failure-envelope coverage. `/tmp/compfn-immutability-all.log`.
- `npm --prefix compfn run build` and `npm --prefix compfn run typecheck`: core and CLI pass. Logs `/tmp/compfn-immutability-build.log`, `/tmp/compfn-immutability-types.log`. Focused log: `/tmp/compfn-immutability-focused.log`.

Migration: mutation of returned payloads remains allowed for caller-local use but no longer changes storage. Create a new evidence record for new facts. JSON-normalized payloads replace incidental memory-only preservation of functions, prototypes or undefined object properties; this matches the specified serialized JSON boundary. Existing evidence is not rewritten, past mutations cannot be recovered, and previously issued object aliases held across an in-process upgrade are not retroactively revoked. External `artifactRef` object immutability is not established here. No live security/provider endpoint, cloud deployment or hosted CI result is claimed. Other original readiness requirements remain separate gates.
