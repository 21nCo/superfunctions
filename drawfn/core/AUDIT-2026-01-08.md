# Audit: drawfn vs SPEC.md

Date: 2026-01-08
Scope: Core library drawfn plus React/Svelte adapters.

Summary

- Broad feature coverage matches the spec: data model, Canvas2D renderer, tool set, basic exports, adapters scaffolded and built.
- Key gaps impacting UX and API semantics: rendering not scheduled during tool interactions; tools bypass history/events; missing marquee selection; wheel-zoom not anchored at cursor; rotation-aware hit testing/selection not implemented; tolerant scene parsing and Node preview hook missing.

1. Data Model (Spec §4)

- Implemented: All element types and Scene shape, including NodeElement and style options for freedraw. Evidence: src/types.ts.
- Notes:
  - Scene.version = 1 present; no tolerant/forward-compatible parsing path (load just assigns JSON).

2. Public API (Spec §5)

- Implemented: Drawfn options, scene CRUD, element z-order, tools, events map, camera helpers, undo/redo, exportPNG/SVG. Evidence: src/drawfn.ts, src/index.ts.
- Deviations:
  - Events: elementAdded/Updated/Removed are only emitted when using Drawfn.add/update/remove. Tool flows mutate scene directly, so no events fire for interactive edits.
  - Rendering loop: scheduleRender is not invoked after tool handlers, so interactive drawing/panning likely won’t repaint per move. (Tool handlers update scene; drawfn.handlePointerMove/Down/Up do not call scheduleRender.)
  - exportPNG/SVG ignore padding parameter; PNG exports full canvas, not element-bounded region.

3. Tools (Spec §6)

- Implemented: select, pan, pen, rectangle, ellipse, arrow, text (with DOM overlay), image (programmatic), node (programmatic). Evidence: src/tools/\*, tool-manager.ts.
- Deviations:
  - Select: no marquee selection; selection/resizing use axis-aligned boxes only; rotation handle sets rotation but overlay/handles are not rotation-aware.
  - Pan: implemented as dedicated tool; space-to-pan modality is not wired (no temporary tool on space key).
  - Text: supports initial placement/edit; no re-edit of existing text via selection path.
  - Image/Node: insertion is programmatic via setTool('image'|'node', opts) as expected.

4. Rendering (Spec §7)

- Implemented: camera transforms, grid, freedraw via perfect-freehand, text via overlay for editing and canvas for rendering, image lazy loading hook, node rounded tile. Evidence: src/renderer.ts.
- Deviations:
  - Selection visuals scale with zoom (lineWidth and handle size not normalized); spec asks for zoom-consistent UI handles.
  - Selection/hit testing do not respect rotation for bounds/handles.

5. Performance (Spec §8)

- Implemented: viewport culling, RAF-based debounced render mechanism.
- Gap: mechanism not triggered by tool interactions; needs scheduleRender after pointer handlers to benefit.

6. Persistence (Spec §9)

- Implemented: getScene/load round-trip for current version.
- Gap: no tolerant parsing or version upgrade path; no deterministic normalization beyond array order.

7. Nucleus Integration (Spec §10)

- Implemented: NodeElement, bookmark-style render with optional preview.
- Gaps: registerNodePreviewFetcher hook not implemented; no click → host navigation callback surfaced.

8. Framework Bindings (Spec §11)

- React: hook and components implemented and built. Evidence: drawfn-react/src/\*; dist present.
- Svelte: action/store/components implemented and built. Evidence: drawfn-svelte/src/\*; dist present.
- Gap: No demo apps included to validate “compile and run in a demo app”.

9. Input & Accessibility (Spec §12)

- Implemented: pointer events, keybindings for delete/undo/redo.
- Gaps: space-to-pan modality missing; wheel zoom anchored at cursor not implemented (zoom changes but camera is not adjusted to keep cursor stable).

10. Hit Testing & Transforms (Spec §13)

- Implemented: AABB hit tests; basic geometry helpers. Evidence: src/utils.ts.
- Gaps: rotation-aware OBB handling not present; freedraw hit-test tolerance not implemented.

11. Styling & Theming (Spec §14)

- Implemented: per-element stroke/fill/opacity; background grid/theme.

12. Packaging (Spec §15)

- Implemented: ESM+CJS outputs, .d.ts, single runtime dependency perfect-freehand, tsup build. Evidence: package.json, dist/\*.

13. Security/Sandbox (Spec §16)

- Implemented: optional getImageBitmap hook for image loading.

14. Acceptance Criteria (Spec §20)

- Import/export scene JSON deterministically: Partially met (basic round-trip; no tolerant parsing/normalization).
- Create/edit/delete all element types: Largely met; edit path lacks marquee selection and re-edit text; rotation editing minimal.
- Pan/zoom; selection + resize; undo/redo: Pan/zoom present but zoom-at-cursor missing; selection+resize present; undo/redo does not cover interactive edits (tools bypass history).
- PNG/SVG export: Implemented; padding ignored; PNG covers full canvas.
- React/Svelte adapters compile and run in a demo: Compile yes; no demo app in repo to verify “run”.
- Nucleus embedding with NodeElement bookmarks: Node element exists; integration callbacks missing.

Priority gaps and recommendations

1. Wire rendering to tool interactions

- After toolManager.handlePointerDown/Move/Up in drawfn.ts, call scheduleRender() so interactive edits repaint.
- Alternatively, expose a drawfn.requestRender() and call it from ToolManager after each handler.

2. Route tool mutations through Drawfn API

- Tools should call drawfn.add/update/remove instead of mutating scene arrays directly so events/history fire.
- Or provide ToolContext from Drawfn with safe mutators that record history, emit events, and schedule renders.

3. History coverage for transforms

- On drag begin/end (select/pen/shape tools), snapshot history (recordHistory) to make transforms undoable. Add a commit() at pointerup.

4. Events fidelity

- Emit elementUpdated during interactive drags/resizes/rotations. Adapters currently listen for element\* events to reflect scene changes.

5. Zoom at cursor

- In handleWheel, adjust camera.x/y to keep the canvas point under the cursor invariant when changing zoom.

6. Selection UI and hit testing

- Normalize selection handle sizes by 1/zoom for constant on-screen size.
- Implement rotation-aware selection bounds and hit testing; for freedraw, add polygon hit-test with tolerance.

7. Marquee selection

- Add drag-rect selection in SelectTool with Shift to add/remove.

8. Tolerant scene parsing

- load(): validate version, provide upgrade path; ignore unknown fields; clamp values to sensible ranges.

9. Nucleus integration API

- Implement registerNodePreviewFetcher(nodeId => preview) and click handlers exposing nodeId for host navigation.

10. Exports

- Respect padding parameter; consider exporting element-bounded region (compute bbox) when requested.

11. Adapters

- React/Svelte: wire onSceneChange also to historyChanged and cameraChanged or emit a generic “sceneChanged” when any mutator runs. Provide small demo apps to satisfy acceptance criteria.

Notable files/evidence

- Event/hook gaps: src/drawfn.ts (on()/emit(), handlePointerMove/Down/Up don’t schedule render or emit elementUpdated during drags).
- Tools mutate scene directly: e.g., src/tools/pen-tool.ts (pushes element; no history/events), src/tools/select-tool.ts (mutates x/y/w/h/rotation).
- Zoom behavior: src/drawfn.ts (handleWheel computes point but does not re-center camera).
- Selection visuals: src/renderer.ts (renderSelectionBox uses fixed sizes in scene units).
- Adapters rely on element\* events: drawfn-react/src/use-drawfn.ts, drawfn-svelte/src/drawfn-action.ts.

- Data model: Pass
