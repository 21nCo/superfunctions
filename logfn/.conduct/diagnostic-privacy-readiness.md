# Lifecycle diagnostic privacy

Shutdown hooks, browser visibility flush hooks and background HTTP delivery previously printed raw rejected errors directly to console.error, outside the terminal logger redaction policy. Those paths now emit fixed failure messages without arbitrary error objects, transport URLs or server-controlled status text. Explicit flush/close callers still receive the original failure, and logger error callbacks retain their existing policy. No delivery success is fabricated.

Four regression cases failed before the change, exposing raw shutdown, visibility, network and server-status contents. Afterward 12 focused lifecycle tests and all246 core tests pass, along with strict types and the build. `node logfn/scripts/diagnostic-privacy-acceptance.mjs` runs the built public export against actual owned child processes and a loopback HTTP server: SIGTERM and SIGINT each exit1 after failing flush with only a fixed diagnostic; a503 response with secret-bearing status text produces no raw console disclosure, remains queued and delivers on the second request. Both children exit and the HTTP server closes.

Receipts: `/tmp/log-diagnostic-before.log`, `/tmp/log-diagnostic-focused.log`, `/tmp/log-diagnostic-full.log`, `/tmp/log-diagnostic-acceptance.log`. Browser visibility uses EventTarget fixtures, not a new native-browser acceptance run. Python source was inspected: its background HTTP diagnostic already emits only the exception type, and no Python changes were needed. This checkpoint does not complete the broader browser/runtime/deployment requirements.
