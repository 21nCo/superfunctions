title: Request Authorization
description: The authorize callback — how to write one, how to test it.

`createSearchFnServer` requires an `authorize` callback or an explicit `allowUnauthenticated: true` opt-in. Reserve the opt-in for local demos or deployments where an upstream service authorizes every operation. The callback receives the context, action, parsed payload, original request, and validated resource names.

Define `authorizeSearchRequest` in your application using one of the policies below.

```typescript
import { authorizeSearchRequest } from "./search-authorization.js";

const sf = await createSearchFnServer({
  adapter,
  authorize: authorizeSearchRequest,
});
```

When `authorize` returns `false`, the server responds with a `FORBIDDEN` envelope and the adapter is never touched.

## Actions

| Action | Called for | Typical policy |
| --- | --- | --- |
| `status` | `GET /searchfn/status` | Allow all (or whitelist health-check IPs) |
| `search` | `POST /searchfn/search` | Authenticated users |
| `searchAll` | `POST /searchfn/search-all` | Authenticated users |
| `index` | `POST /searchfn/index` | Admin / service accounts |
| `remove` | `POST /searchfn/remove` | Admin / service accounts |
| `clear` | `POST /searchfn/clear` | Admin only |

## Worked example: role-based

```typescript
async function authorize(_ctx, action, _payload, request) {
  const session = await getSession(request);
  if (!session) return action === "status";

  switch (action) {
    case "status":
    case "search":
    case "searchAll":
      return true;
    case "index":
    case "remove":
      return session.user.role === "editor" || session.user.role === "admin";
    case "clear":
      return session.user.role === "admin";
  }
  return false;
}
```

## Worked example: per-resource ACL

```typescript
async function authorize(_ctx, action, _payload, request, resources) {
  const session = await getSession(request);
  if (!session) return false;
  if (action === "status") return false;

  for (const r of resources) {
    if (!(await userCanAccess(session.user, r, action))) return false;
  }
  return true;
}
```

The same policy checks every effective target for single-resource operations and `searchAll`. With authorization configured, `/search-all` requires a non-empty list of `resources`. Single-resource routes accept `resource`. The server rejects requests containing a scope field that the route does not use.

## Worked example: rate limiting

```typescript
import { Ratelimit } from "@upstash/ratelimit";

const limiter = new Ratelimit({
  redis,
  limiter: Ratelimit.slidingWindow(60, "1 m"), // 60 req/min per user
});

async function authorize(_ctx, action, _payload, request) {
  const session = await getSession(request);
  if (!session) return false;

  const { success } = await limiter.limit(session.user.id);
  if (!success) return false; // Returns FORBIDDEN; clients see rate limit as auth failure

  return true; // ... plus other rules
}
```

This limiter counts requests that pass body parsing and resource validation. Apply a request-wide limiter before `router.handle` to also count rejected requests.

## Request and context

```typescript
const sf = await createSearchFnServer({
  adapter,
  context: async (request) => ({ session: await getSession(request) }),
  authorize: (ctx, action) => action === "status" || ctx.session?.user.role === "admin",
});
```

The optional `context` factory runs before the policy and can load verified identity from request headers or cookies. Its result is passed directly to the policy as `ctx`. The router's middleware and custom routes receive the route parameters, parsed URL and query parameters from the HTTP router. Without a factory, the policy also receives this router context. Read POST body fields from `payload` because the server has already read the request body. `status` receives `null` and an empty resource list.

## Failure modes

- **`authorize` returns `false`** → `FORBIDDEN` (403).
- **`context` or `authorize` throws** → the server logs `authorization.error`, emits `searchfn.authorization.failed`, and returns `FORBIDDEN` (403). The response and event omit the underlying error details.
- **A POST uses a non-JSON media type** → `UNSUPPORTED_MEDIA_TYPE` (415) before authorization. Send `Content-Type: application/json`.

Treat `authorize` like any other async function — handle your own errors.

## Testing

```typescript
import { createSearchFnServer } from "@searchfn/server";
import { MemoryAdapter } from "@searchfn/adapter-memory";

const adapter = new MemoryAdapter();
const sf = await createSearchFnServer({
  adapter,
  authorize: async (ctx, action) => action === "search",
});

const res = await sf.router.handle(new Request("http://test/searchfn/index", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ resource: "docs", documents: [{ id: "doc-1", fields: { title: "Sample" } }] }),
}));
expect(res.status).toBe(403);
```

Inject the request directly into `router.handle` — no HTTP server needed.

## What to log on denial

```typescript
observability: {
  logger: {
    warn: (message, context) => {
      if (message === "authorization.denied") {
        audit({ operation: context?.operation, adapter: context?.adapter, at: Date.now() });
      }
    },
  },
},
```

Patterns like "100 denied search requests from one IP in 1 minute" are signals for a security alert.
