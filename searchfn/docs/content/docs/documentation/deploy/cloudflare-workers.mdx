Cloudflare Workers is V8 isolates, not Node. The adapter choices narrow significantly.

## What works on Workers

- **`@searchfn/adapter-sqlite`** — SQLite FTS5 search inside a [D1](https://developers.cloudflare.com/d1/) database through the `fromD1(env.DB)` binding. No external service. See [SQLite on D1](#sqlite-on-d1).
- **`@searchfn/adapter-postgres`** — Postgres full-text search through [Hyperdrive](https://developers.cloudflare.com/hyperdrive/) with an injected driver: `fromPostgresJs(sql)` or `fromPg(pool)`. See [Postgres through Hyperdrive](#postgres-through-hyperdrive).
- **`@searchfn/adapter-meilisearch`** — talks to Meili over HTTP. Works on Workers.
- **`@searchfn/adapter-elasticsearch`** / **`@searchfn/adapter-opensearch`** — same; HTTP-based.

## What doesn't work

- **`@searchfn/adapter-memory`** — RAM is reset between requests.
- **`@searchfn/adapter-indexeddb`** — no IndexedDB on Workers.
- **`@searchfn/adapter-postgres` with `connectionString`** — the adapter-owned `pg` Pool lives across requests, which Workers do not allow. Inject a per-request driver instead (below).

## Setup

```typescript
// worker.ts
import { createSearchFnServer } from "@searchfn/server";
import { MeilisearchAdapter } from "@searchfn/adapter-meilisearch";

interface Env {
  MEILI_URL: string;
  MEILI_API_KEY: string;
}

let sf: Awaited<ReturnType<typeof createSearchFnServer>> | null = null;

async function getServer(env: Env) {
  if (sf) return sf;
  const adapter = new MeilisearchAdapter({
      host: env.MEILI_URL,
      apiKey: env.MEILI_API_KEY,
    });
  sf = await createSearchFnServer({
    adapter,
    basePath: "/searchfn",
  });
  await adapter.initialize({
    resources: [{ name: "articles", searchFields: ["title", "body"] }],
  });
  return sf;
}

export default {
  async fetch(request: Request, env: Env) {
    const server = await getServer(env);
    return server.router.handle(request);
  },
};
```

`wrangler.toml`:

```toml
name = "searchfn-worker"
main = "worker.ts"
compatibility_date = "2026-03-01"

[vars]
MEILI_URL = "https://search.example.com"
# MEILI_API_KEY set via `wrangler secret put`
```

## SQLite on D1

`@searchfn/adapter-sqlite` keeps the index in FTS5 tables in a D1 database, so search needs no service outside Cloudflare.

```typescript
// worker.ts
import { createSearchFnServer } from "@searchfn/server";
import { SqliteAdapter, fromD1 } from "@searchfn/adapter-sqlite";

interface Env {
  SEARCH_DB: D1Database;
}

let sf: Awaited<ReturnType<typeof createSearchFnServer>> | null = null;

async function getServer(env: Env) {
  if (sf) return sf;
  const adapter = new SqliteAdapter({ driver: fromD1(env.SEARCH_DB) });
  // Idempotent: creates the tables on first run and is a no-op afterwards.
  await adapter.initialize({
    resources: [{ name: "articles", searchFields: ["title", "body"] }],
  });
  sf = await createSearchFnServer({
    adapter,
    basePath: "/searchfn",
    // Without authorize, anyone can call /searchfn/index, /remove and /clear.
    // This Worker serves reads only; index from your own authenticated code with adapter.index().
    authorize: (_ctx, action) => action === "status" || action === "search" || action === "searchAll",
  });
  return sf;
}

export default {
  async fetch(request: Request, env: Env) {
    const server = await getServer(env);
    return server.router.handle(request);
  },
};
```

`wrangler.toml`:

```toml
name = "searchfn-worker"
main = "worker.ts"
compatibility_date = "2026-03-01"

[[d1_databases]]
binding = "SEARCH_DB"
database_name = "search"
database_id = "<your-d1-database-id>"
```

With `@datafn/server`, pass `createSearchProvider(new SqliteAdapter({ driver: fromD1(env.DB) }))` as `searchProvider`; the index can share the database that holds your DataFn data.

Notes:

- Fuzzy search is not available; the adapter ignores `fuzzy` and logs a warning. Use `prefix: true` for search-as-you-type.
- Every write is one `db.batch()` (one transaction). Large `index()` calls are split into transactions of `maxBatchSize` documents (default 500), and each statement binds a single parameter, well under D1's per-statement limit.
- `wrangler dev` and `@cloudflare/vitest-pool-workers` run the same code against a local D1 database.

See the [SQLite adapter reference](/docs/reference/adapters/sqlite) for query behavior and storage.

## Postgres through Hyperdrive

`@searchfn/adapter-postgres` runs every statement through an injected driver. On Workers, open a client on the [Hyperdrive](https://developers.cloudflare.com/hyperdrive/) connection string and pass it to the adapter: `fromPostgresJs(sql)` for postgres.js, or `fromPg(pool)` for a `pg` Pool. The adapter loads `pg` itself only for the `connectionString` option, so a Worker that injects postgres.js does not use `pg`.

```typescript
// worker.ts
import postgres from "postgres";
import { PostgresAdapter, fromPostgresJs } from "@searchfn/adapter-postgres";

interface Env {
  HYPERDRIVE: Hyperdrive;
}

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    // Workers cannot reuse a connection across requests: create the client per request.
    const sql = postgres(env.HYPERDRIVE.connectionString, { max: 5, fetch_types: false });
    const adapter = new PostgresAdapter({ driver: fromPostgresJs(sql), schema: "public" });
    try {
      const query = new URL(request.url).searchParams.get("q") ?? "";
      const hits = await adapter.searchAll({ query, resources: ["memos", "notes"], prefix: true });
      return Response.json(hits);
    } finally {
      ctx.waitUntil(sql.end());
    }
  },
};
```

`wrangler.toml`:

```toml
name = "searchfn-worker"
main = "worker.ts"
compatibility_date = "2026-03-01"
compatibility_flags = ["nodejs_compat"]

[[hyperdrive]]
binding = "HYPERDRIVE"
id = "<your-hyperdrive-config-id>"
```

With `pg`, create the Pool per request in the same way and end it with `ctx.waitUntil(pool.end())`:

```typescript
import { Pool } from "pg";
import { PostgresAdapter, fromPg } from "@searchfn/adapter-postgres";

const pool = new Pool({ connectionString: env.HYPERDRIVE.connectionString, max: 5 });
const adapter = new PostgresAdapter({ driver: fromPg(pool) });
```

Notes:

- `nodejs_compat` is required: postgres.js and `pg` need it on Workers, and the adapter imports `node:crypto`.
- `fromPostgresJs` runs every statement as a prepared statement, as Hyperdrive recommends for postgres.js. Do not create the client with `prepare: false`.
- Run `initialize()` once from a deploy script or an authenticated admin route, not on every request: it issues `CREATE TABLE IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS` statements. `search()`, `index()`, `remove()` and `clear()` work on an adapter that was not initialized in the same request.
- A per-request adapter has no declared resources, so pass `resources` to `searchAll()`.
- `index()` deletes and re-inserts each batch inside `sql.begin()`, so a failed batch rolls back.
- `index()` with `fromPg` runs each batch in `BEGIN` / `COMMIT` on one pooled client.
- The adapter never ends the client. Call `ctx.waitUntil(sql.end())` (or `pool.end()`) yourself.
- Set timeouts on the client (for example postgres.js `idle_timeout` and `connect_timeout`); `queryTimeoutMs` applies only to `connectionString`.
- The adapter encodes its array parameters as Postgres array literals, so `fetch_types: false` (the setting Cloudflare recommends for Hyperdrive) works.

The package's tests run the shared adapter contract with postgres.js and `pg` inside workerd through a local Hyperdrive binding (Miniflare connects straight to a Postgres 16 server). They do not exercise a live Hyperdrive configuration.

See the [Postgres adapter reference](/docs/reference/adapters/postgres) for drivers and options.

## Caveats

- Worker invocations are short. If `initialize()` takes more than a few seconds, the first invocation after a deploy may time out. Mitigation: hit `/searchfn/status` from a warmer cron after deploy.
- Workers share the global scope **within an isolate**, but isolates are recycled. Treat the `sf` cache as best-effort.
- Outbound HTTP from Workers has subrequest limits. With Meilisearch, one request typically issues one subrequest — fine.

## Durable Objects

For per-tenant isolation backed by Durable Objects:

```typescript
import { DurableObject } from "cloudflare:workers";

export class TenantSearch extends DurableObject {
  private sf: Awaited<ReturnType<typeof createSearchFnServer>> | null = null;

  async fetch(request: Request) {
    if (!this.sf) {
      const adapter = new MeilisearchAdapter({
          host: env.MEILI_URL,
          apiKey: env.MEILI_API_KEY,
          indexPrefix: `tenant-${this.ctx.id.toString()}_`,
        });
      this.sf = await createSearchFnServer({
        adapter,
        basePath: "/searchfn",
      });
    }
    return this.sf.router.handle({ /* ... */ });
  }
}
```

Each tenant gets a dedicated DO instance, which gets a dedicated Meilisearch index prefix.
