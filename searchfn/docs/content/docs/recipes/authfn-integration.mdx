---
title: AuthFn Integration
description: Wire SearchFn's authorize callback to AuthFn sessions and roles.
---

SearchFn's `authorize` callback is the gate between an HTTP request and the search engine. AuthFn provides the session model. Connecting them is a one-liner per action.

## Setup

```typescript
import { createSearchFnServer } from "@searchfn/server";
import { hasScopes } from "authfn";

const sf = await createSearchFnServer({
  adapter,
  basePath: "/searchfn",
  authorize: async (_ctx, action, _payload, request) => {
    if (action === "status") return true;
    const session = await auth.provider.authenticate(request);
    return !!session && canUseSearchAction(session, action);
  },
});
```

Use your configured AuthFn server as `auth` and implement `canUseSearchAction` with your application roles or permissions. The fourth argument is the original `Request`, including cookies and authorization headers.

## Per-resource authz

If different resources have different access rules:

```typescript
authorize: async (_ctx, action, _payload, request, resources) => {
  const session = await auth.provider.authenticate(request);
  if (!session || action === "status") return false;
  for (const resource of resources) {
    if (!(await canAccess(session, action, resource))) return false;
  }
  return true;
},
```

Define `canAccess` in your application. It must check the requested action for every resource.

## Per-tenant authz

When resource names encode tenant (`articles:tenant-1`):

```typescript
authorize: async (_ctx, action, _payload, request, resources) => {
  const session = await auth.provider.authenticate(request);
  if (!session || action === "status") return false;
  const tenantId = await lookupTenantForSession(session);
  if (!tenantId || !(await canUseSearchAction(session, action))) return false;
  const allowed = new Set(await getProvisionedSearchResources(tenantId));
  return resources.every((resource) => allowed.has(resource));
},
```

This pairs with the [multi-tenant pattern](/docs/recipes/multi-tenant).

## Service-to-service

For service accounts (background indexers, CI pipelines), pass a different credential:

```typescript
authorize: async (_ctx, action, _payload, request) => {
  if (action !== "index") return false;
  const session = await auth.provider.authenticate(request);
  return session?.type === "api-key" && hasScopes(session, "search:index", { registry: scopes });
},
```

Use the `scopes` registry from your AuthFn configuration, register `search:index`, and grant it to the indexer's key. Rotate service keys and store them in a secret manager.

## Logging denied requests

Log policy denials through `observability.logger`:

```typescript
const sf = await createSearchFnServer({
  adapter,
  authorize,
  observability: {
    logger: {
      warn: (msg, ctx) => {
        if (msg === "authorization.denied") log({ msg, operation: ctx?.operation });
      },
    },
  },
});
```

Track repeated denies per IP as a signal for an alert.

## Tests

Mock the AuthFn session in your test setup:

```typescript
vi.spyOn(auth.provider, "authenticate").mockResolvedValue(null);
const response = await sf.router.handle(new Request("https://test.example/searchfn/search", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ resource: "docs", query: "sample" }),
}));
expect(response.status).toBe(403);
```
