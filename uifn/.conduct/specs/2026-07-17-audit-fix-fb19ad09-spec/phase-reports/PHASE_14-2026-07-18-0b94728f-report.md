## Adapter boundary

The adapter kit now contains only these runtime modules:

- `conformance.ts` — lossless semantic trace schema, validation, normalization, comparison, parity orchestration, and structured failure codes;
- `merge-props.ts` — event/prop/ARIA/data/style translation and deterministic merge behavior;
- `refs.ts` — ref composition and element registration;
- `lifecycle.ts` — lifecycle cleanup scope;
- `ssr.ts` — SSR/client guards;
- `index.ts` — public exports.

Focus, portal, layer, positioning, presence, scroll-lock, primitive state, transition, and keyboard behavior are absent from adapter-kit. Browser ownership remains in `@uifn/dom`; primitive semantics remain in `@uifn/core`. The package no longer depends on `@uifn/dom`, and its package manifest and lockfile both declare only `@uifn/core` with Node `>=20 <25`.

The static verifier rejects:

- unexpected adapter runtime modules;
- primitive names and controller factories;
- key maps, reducers, local machines, or transition stores;
- direct document/window access or DOM-service factories;
- an adapter-kit dependency on `@uifn/dom`;
- stale lockfile dependencies or Node ranges.

Trace normalization only removes framework-generated identifier text and transaction version numbering while preserving identifier relationships. It does not normalize callback order, state, focus, ARIA, event outcomes, styles, form values, errors, timing-significant sequence, or cleanup.

## Production defects exposed and fixed

Actual public-tree comparison exposed runtime defects that synthetic controller-only checks had not found:

- The core state channel could recursively enqueue shallow-equal patches when DOM focus projection re-entered state publication. Shallow-equal state sends are now suppressed, with a dedicated reentrancy regression test.
- Menu, ContextMenu, Toolbar, and FloatingPanel declared repeated separators/resize handles but produced non-unique static part identities. They now use value-bearing parts with unique IDs and required edge/value semantics; controller-contract fixtures pass explicit values.
- React static-contract projection did not invoke function-valued repeated parts, which lost the Marquee item identity. React now projects callable static parts and merges user props through the core invariant merger.
- React portals did not expose the DOM platform's stable portal ownership marker. React now emits the same portal ID contract as Svelte and Solid.
- React's hidden checked inputs suppressed its controlled-field warning by adding a framework-only `readonly` attribute. It now uses a no-op change handler while the semantic trace records the live checked property.
- Svelte bindable callbacks could echo a controller's own newly committed value back as a controlled input update, changing last-change metadata and overlay phases. The bridge now suppresses state-equal bindable echoes without suppressing real external updates.
- Solid could render Tour's transient `transitioning` phase after the controller had returned to `open`. Tour now publishes an explicit completion transition that all reactive adapters observe.
- Svelte and Solid style translation mishandled camelCase CSS names and numeric units, producing missing or divergent positioning styles. Shared CSS translation now emits kebab-case names, correct `px` units, and a defined unitless-property set.
- Async positioning could be captured before Floating UI completed. All framework harnesses now settle the browser task queue before semantic checkpoints.
- Solid's packed source maps referenced excluded repository sources. Its published maps now embed source content, eliminating packed-consumer source-map diagnostics.
- Catalog/cardinality, controller-contract, portal, form, focus, callback, and cleanup traces were updated together; no comparator exclusion was added for any of these defects.

After these corrections, React/Svelte and React/Solid each achieve `61/61` exact semantic matches in both source and package modes.
