## Runtime defect fixed during continuation

The expanded React run exposed a core state-channel ordering defect. While the runtime was draining a subscriber notification, DOM presence could enqueue `opening` and then `open`. The second update was incorrectly suppressed because it matched the currently published state, even though the queued tail was `opening`. React could therefore remain visibly stuck at `data-state="opening"` after a zero-duration transition.

`createStateChannel()` now compares and merges re-entrant patches against the projected queue tail. A regression test proves FIFO publication of `open -> opening -> open` and proves that a later disjoint patch retains the queued phase. The focused React adapter test, all 160 core tests, and all 22 React tests pass after rebuilding core and DOM.

The semantic change made the prior reviewed golden stale. The explicit golden-acceptance ceremony first required exact consensus across React, Svelte, and Solid plus source/package equivalence. The refreshed golden then passed:

- 366/366 public-tree semantic comparisons;
