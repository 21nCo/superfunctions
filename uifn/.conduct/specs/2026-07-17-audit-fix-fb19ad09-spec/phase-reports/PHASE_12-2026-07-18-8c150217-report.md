## Reactive lifecycle and ownership

The shared `SveltePrimitiveBridge` provides the following lifecycle:

1. Build a deterministic inert preview projection for server rendering and initial component setup.
2. Activate one live controller on subscription and subscribe once.
3. Apply reactive inputs through `controller.update()`; callback identity changes use stable proxy delegates instead of controller recreation.
4. Re-project static contracts without creating a framework-owned state engine.
5. Register actual root/part elements and refresh only the public DOM bindings that own those elements.
6. Destroy subscriptions, controller, portals, form/reset integration, overlay/navigation/menu/roving/range services, and the acquired DOM platform synchronously.

The lifecycle fixture records controller generation, DOM generation, and DOM destroy count before and after a controlled-value rerender. The live controller remains generation `2`; the input update changes the public value without changing controller generation, DOM generation, or destroy count. This kills the controller-recreation defect and demonstrates that reactive updates do not duplicate services or effects.

The bridge obtains positioning, layer/focus policy, menu/navigation behavior, roving focus, range gestures, native form reset, portals, and platform resources only from `@uifn/dom`. The DOM ownership scan covers 677 production files with zero violations. Phase 9's cross-framework contract also passes after recognizing the new generated Svelte compound surface.
