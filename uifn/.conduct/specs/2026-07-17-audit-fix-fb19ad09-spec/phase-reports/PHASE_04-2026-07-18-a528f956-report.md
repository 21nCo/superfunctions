## Outcome

`@uifn/core` now has one reviewed public behavior shape for all 25 current controller factories. The public contract is independent of React, Svelte, Solid, browser globals, and private runtime declarations. It has immutable versioned snapshots, selector-aware subscriptions, reactive input synchronization, typed change metadata, guarded actions/part handlers, and synchronous idempotent teardown.

The phase is an intentional breaking cutover. Public machine/store APIs, duplicate `createX` behavior constructors, controller-adapter wrappers, process-global ID registries, wildcard primitive implementation paths, and public state paths were removed. Current repository consumers were migrated to controller factories; the package includes a human migration guide and a machine-readable removal manifest.

Part composition now follows the required event model: the user handler runs first, `preventDefault()` cancels generated behavior unless that handler is explicitly declared non-cancelable, and only declared semantic invariants are protected. Refs, classes, styles, safe attributes, arbitrary `data-*` values, and handlers compose without making the entire generated prop object immutable to consumer input.

Environment scope is explicit and structural. Root, document, window, active element, direction, writing mode, locale, time zone, preferences, deterministic IDs, clock/scheduler, query functions, diagnostics, and optional capabilities are injected. Core does not discover `document`, `window`, or `navigator`; Node 20, 22, and 24 execute packed interactions with all three browser globals configured to throw on read.

## Public interface frozen for downstream phases

### Controller facade

The DOM package and framework adapters consume:

```ts
interface UIFnController<
  TState,
  TActions extends object,
  TParts extends object,
  TInputs extends object = Record<string, never>,
  TEvent extends UIFnEvent = UIFnEvent,
> {
  readonly status: UIFnControllerStatus
  readonly state: Readonly<TState>
  readonly snapshot: Readonly<UIFnSnapshot<TState>>
  readonly actions: Readonly<TActions>
  readonly parts: Readonly<TParts>
  getState(): Readonly<TState>
  getSnapshot(): Readonly<UIFnSnapshot<TState>>
  update(inputs: Partial<TInputs>): void
  subscribe<TSelected = TState>(
    subscriber: UIFnSubscriber<TSelected, TEvent, TState>,
    options?: UIFnSubscribeOptions<TState, TSelected>,
  ): () => void
  destroy(): void
}
```

`UIFnSnapshot<TState>` is `{ version, status, state }`; the snapshot and state are detached and immutable. `UIFnChangeMeta<TEvent, TState>` contains `transactionId`, typed `event`, `source`, `reason`, optional input modality, previous/next snapshots, changed keys, optional requested value, and timestamp.

Subscriptions emit the current selected value immediately by default. `emitInitial: false` suppresses only that initial delivery. A selector plus equality comparator suppresses selector-equivalent updates. Reentrant notifications join a FIFO and never recursively interleave. A backend publication creates one new version and one metadata transaction; structurally equal publications are silent.

`destroy()` runs backend cleanup synchronously once, publishes terminal destroyed status internally, and makes subsequent actions, `update`, or generated part event handlers fail with `UIFN_CONTROLLER_DESTROYED`. Repeated `destroy()` and unsubscribe calls are no-ops.

Controlled actions request a value through the consumer callback but do not commit that controlled field. `controller.update()` applies the consumer's synchronized value as a separate `controlled-sync` transaction and does not echo the change callback. This was exercised for Accordion, Checkbox, Collapsible, Combobox, ContextMenu, Dialog, DropdownMenu, HoverCard, MenuBar, Popover, Progress, RadioGroup, Select, Slider, Switch, Tabs, Toast, Toggle, ToggleGroup, and Tooltip.

### Typed parts

The DOM package specializes native element props through:

```ts
type UIFnPartProps<
  TElement = unknown,
  TEvent extends UIFnPartEvent<TElement> = UIFnPartEvent<TElement>,
  TNativeProps extends object = object,
> = Omit<TNativeProps, keyof UIFnSemanticPartProps<TElement, TEvent>>
  & UIFnSemanticPartProps<TElement, TEvent>

interface UIFnPartController<TElement, TProps extends UIFnPartProps<any, any>> {
  readonly name: string
  getProps(userProps?: TProps): TProps
}
```

`UIFnPartEvent` structurally types event name, key, pointer type, related/current target, composition state, cancellation, and propagation. This keeps core DOM-free while React, Svelte, Solid, or `@uifn/dom` can bind concrete native element/event types. The compile-only fixture proves a button part accepts native `type` and `form`, exposes a typed `currentTarget`, and rejects anchor-only `href`.

Part merging owns these rules:

1. user handler first;
2. generated handler second only when the event is not canceled, unless explicitly non-cancelable;
3. declared required/invariant `role`, ID, tab index, hidden/disabled state, ARIA keys, data keys, and safe attribute keys retain generated values;
4. a conflicting declared invariant records `UIFN_PART_INVARIANT_OVERRIDDEN` deterministically;
5. undeclared ARIA/data/attributes remain consumer-overridable;
6. classes are deduplicated and joined, styles merge with consumer values last, and callback/object refs receive each element transition and final `null` once.

Every controller publishes a named anatomy-specific `parts` map. Parameterized parts such as accordion items, select options, tabs triggers, slider thumbs, and menu items require their semantic key before accepting user props.

### Environment and scope

`UIFnEnvironment` accepts:

- mode, `scopeId`, and hydration seed;
- root, owner-document, owner-window, and active-element resolvers;
- direction, writing mode, locale, time zone, reduced-motion, and forced-colors values or resolvers;
- scoped ID generator and initially issued IDs;
- deterministic `now` and scheduler operations;
- root-scoped query and ID lookup functions;
- warning, error, and trace sinks;
- a named capability map.

`UIFnResolvedEnvironment` exposes `getRoot`, `getOwnerDocument`, `getOwnerWindow`, `getActiveElement`, direction/writing-mode/locale/time-zone/preference getters, scoped query helpers, `getCapability`, failing `requireCapability`, and `child(scope)`. Passing an already-resolved environment returns the same root scope, so sibling controllers share one monotonically unique ID source. Independent roots and SSR requests retain independent counters. Missing required capabilities throw `UIFN_ENV_CAPABILITY_MISSING`.

`UIFnIdAllocator` provides `reserve`, `next`, `fromToken`, and sorted `snapshot` over an owned environment. No process-global ID counter or duplicate registry remains.

## Phase audit and repairs

The implementation audit found and repaired these issues before final evidence:

1. Progress controller teardown did not reach the model; teardown now forwards exactly once.
2. Controlled Toast requests committed before external synchronization; requests and `update` synchronization are now separate transactions.
3. A process-global ID compatibility path remained; all public global ID helpers and registries were deleted and consumers moved to owned environments/factories.
4. The React hook retained a fallback counter; supported React 18.3/19 now uses `React.useId`, with uniqueness coverage.
5. The broad controller test originally verified shape but did not invoke every controller's action path. It now runs a canonical semantic action on every interactive controller, catches unexpected notification counts, and covers post-destroy mutation for each factory.

The final scans found no current legacy path, no private model/state-channel declaration leak, no ambient browser global, and no process-global ID state. No deprecated alias or compatibility shim was added.
