# PHASE_17 — Executable Storybook and documentation

## Objective

Turn Storybook and documentation into complete, runnable public-consumer surfaces rather than metadata inventories.

## Entry

- Phase 16 package/source outputs are stable enough to consume without repository-private imports.

## Requirements

- `STORY-001`, `DOCS-001`.

## Work

1. Generate required story/docs inventories from the canonical catalog, then author live public-package stories for every primitive/anatomy/state/variant/framework/theme/direction/preference fixture.
2. Build and visit the actual Storybook; operate interaction stories and collect console/page/network/a11y/visual/semantic evidence. Detect static test doubles and missing story exports.
3. Author complete primitive, controller, framework compound, styling, source/package install, SSR/form/composition/accessibility/keyboard/touch/limitations/migration documentation.
4. Typecheck/build/run every code sample in clean framework consumers, crawl links/API names/version/support claims, and ban removed/legacy/private imports.
5. Keep product workflows in labeled examples, not reusable package APIs, and ensure examples use injected fake data/clients where required.

## Required evidence

- `TV-STORY-001-P/N`, `TV-DOCS-001-P/N`.
- Exact catalog-to-built-story/docs coverage, public import scan, runnable sample results, and failure artifacts for seeded missing/stale fixtures.
- No metadata-only verifier may mark this phase complete.

## Exit gate

Every stable capability is discoverable, live, operable, accurate, and runnable from public package/source APIs across all three frameworks.

## Do not

- Do not count generated story metadata as a rendered story.
- Do not publish unsupported or unverified compatibility/accessibility claims.

## Handoff

Phase report supplies the complete public scenario inventory and built URLs consumed by accessibility automation and manual scripts.
