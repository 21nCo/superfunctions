## High-level findings

1. **FAIL P0: Form and data-rich browser QA can pass by exercising injected generic probes instead of the actual uifn component.** The Workbench injects `formProbeHtml` and `dataProbeHtml` beside the component (`uifn/examples/react-workbench/src/main.tsx:99`, `uifn/examples/react-workbench/src/main.tsx:100`; equivalent patterns exist in Svelte, Vue, Solid, and Angular). The runner prefers `[data-uifn-workbench-form]` and `[data-uifn-data-probe]` (`uifn/examples/browser-qa/src/assertions/interaction.mjs:22`, `uifn/examples/browser-qa/src/runner.mjs:133`) so `TV-FORM-001` and `TV-DATA-001` can pass while the real control, form, table, calendar, command, or date-picker behavior is broken.
2. **FAIL P0: Overlay/collision QA does not verify the spec-required content geometry, trigger association, or select overlay coverage.** The runner checks only the route root box via `assertNoMajorClipping(page, selector)` (`uifn/examples/browser-qa/src/runner.mjs:75`), and that helper only compares the root bounding box to the viewport (`uifn/examples/browser-qa/src/assertions/geometry.mjs:25`). `verify:uifn-overlays -- --slug select` produced `UIFN_BROWSER_NO_ROUTES`, even though `select` has an overlay profile and the spec/Phase 04 explicitly require select overlay portions.
3. **FAIL P0: `verify:uifn-release` does not include the full required Workbench browser matrix.** Release integration runs `verify-uifn-browser.mjs --scope smoke` and `verify-uifn-overlays.mjs` (`scripts/verify-uifn-release.mjs:294`, `scripts/verify-uifn-release.mjs:296`) and declares Workbench browser coverage as only `smoke` and `overlays` (`scripts/verify-uifn-release.mjs:345`). The full `verify:uifn-workbench` matrix is not part of the release gate.
4. **FAIL P1: Visual QA is a nonblank screenshot-byte check, not baseline/text-overlap/drift validation.** `assertVisual` only captures a screenshot and marks it nonblank when byte length exceeds 1200 (`uifn/examples/browser-qa/src/assertions/visual.mjs:1`). That does not implement `TV-VISUAL-001` baseline drift, text overlap, major clipping beyond root box, or explicit baseline update flow.
5. **PARTIAL P1: Structured evidence exists, but focused filters and operational behavior are brittle.** `verify:uifn-examples` passed with 45 components, 14 patterns, 14 SF panels, 3 scenarios, and 748 routes. Targeted browser routes passed. However, the full `verify:uifn-overlays` run was silent and was interrupted after an extended wait; filtered profile matching omits secondary profiles because each contract has a single `qaProfile` (`uifn/examples/shared/src/component-inventory.ts:321`, `uifn/examples/shared/src/component-inventory.ts:333`) and `routeMatches` matches only that profile or geometry strings (`uifn/examples/browser-qa/src/filters.mjs:43`).

## Spec conflicts / spec gaps (explicit)

- No direct conflict was found between `INTENT_AUDIT.md`, `SPEC.md`, `REQUIREMENTS.md`, `TEST_VECTORS.md`, `PLAN.md`, and phases.
- Spec gap: the bundle requires multi-profile components to satisfy every applicable profile, but the contract shape has only one `qaProfile`. The implementation tries to encode multiple profiles in component definitions, then collapses them to the first profile in each QA contract. This creates drift between the specified profile matrix and the executable filters.
- Spec gap: `TV-SF-001` expects `liveNetworkCalls: 0`, but the spec does not require a concrete network interception mechanism. The implementation reports zero from metadata instead of measuring runtime calls.

## Cross-cutting audits (security/determinism/limits/errors/compat)

### Security/authz/validation boundaries

- Static offline scanning is present and passed for examples.
- SF panels use injected mock clients in app shells (`uifn/examples/react-workbench/src/main.tsx:42` and analogous framework files).
- Browser QA does not intercept `fetch`, `XMLHttpRequest`, `WebSocket`, or `sendBeacon` at runtime. As a result, `SEC-001` and `QA-009` are only partially proven.
- Evidence sanitization exists for local paths and secret-like keys (`uifn/examples/browser-qa/src/runner.mjs:32`), but failure screenshots/traces are not actually emitted for review.

### Determinism invariants

- Shared inventories and route generation are deterministic.
- Data-rich probes use deterministic rows.
- Timezone/locale determinism required for calendar/date-picker is not demonstrated by browser assertions. Date props are fixed (`uifn/examples/shared/src/workbench-model.ts:112`), but keyboard/min/max/disabled/locale/timezone behaviors are not asserted.

### Limits/caps

- Filters support framework/family/profile/slug/route/theme/viewport/max-routes.
- `maxRoutes` truncates route execution (`uifn/examples/browser-qa/src/runner.mjs:204`) but the release gate does not report missing shard coverage.
- The full overlay command was operationally too long/silent during this audit and was interrupted. A release gate should provide progress, sharding, and bounded runtime.

### Error handling + canonical envelopes

- Browser results use a stable JSON envelope with counts, checks, and failures.
- Failures include code, framework, route, slug, QA case ID, assertion type, and sanitized evidence.
- `verify:uifn-workbench` wraps examples and browser commands but embeds stdout/stderr arrays instead of normalizing child check counts into the main `UifnBrowserQaResult` schema.

### Compatibility/versioning/migrations

- Workbench packages are private, so pre-GA breaking changes are acceptable.
- QA contract schema version is fixed at `1`.
- Release gate dry-run lists the planned packages/checks and fails planned checks in dry-run mode, which is good. The actual release coverage is still incomplete for full Workbench browser requirements.

## Recommendations (ranked)

1. **Replace synthetic probes with component-owned assertions.** For each form/data-rich route, drive the actual rendered component DOM and assert the contract's expected value, ARIA state, callbacks, submitted form data, keyboard behavior, disabled/invalid behavior, and persistence. Keep probes only as explicit harness controls if they cannot satisfy component assertions.
2. **Model profiles as an array in contracts and fix profile filters.** `select` must appear in overlay runs; `resizable` and `sidebar` must appear in layout/data-rich runs; any multi-profile component must be included in every required profile gate.
3. **Implement real overlay assertions.** Locate trigger and content elements, open them through real pointer/keyboard interactions, assert `aria-controls`/association, content box visibility, clipping boundary, alignment tolerance, Escape, outside-click, tab/focus behavior, and every required edge case.
4. **Upgrade visual QA from nonblank screenshots to actual visual checks.** Persist or compare deterministic baselines keyed by framework/family/slug/route/state/theme/viewport, and add explicit blank, clipping, text-overlap, and drift failures with a controlled baseline update flow.
5. **Put the full Workbench browser matrix in `verify:uifn-release` before GA.** The release gate should call `verify:uifn-workbench` or equivalent sharded complete coverage, not only smoke plus overlays. Release evidence should include component, pattern, SF, framework, route, check, theme, viewport, and skipped/unsupported counts.
6. **Add runtime network interception for Workbench QA.** Count fetch/XHR/WebSocket/beacon attempts per route and fail nonzero live calls unless a contract explicitly declares an unsupported/offline-safe exception.
7. **Add progress/sharding output for long browser gates.** The full overlay run should not sit silent for minutes. Emit framework/route progress and shard summaries so release failures are diagnosable.
