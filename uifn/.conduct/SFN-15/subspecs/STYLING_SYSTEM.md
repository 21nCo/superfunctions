# Sub-spec: Styling System

## Purpose

Define a public styling system that is semantic-token-first, CSS-variable runtime-first, Tailwind-compatible, framework-neutral, accessible, and adoptable outside any one product.

## Package Split

The styling system MUST use four public packages:

- `@uifn/tokens`: token schema, validation, token transforms, OKLCH utilities.
- `@uifn/theme`: runtime CSS variable mounting, theme context, scoped themes, media preference sync.
- `@uifn/theme-tailwind`: Tailwind preset/plugin generation from tokens and recipe metadata.
- `@uifn/recipes`: typed component and surface recipes with multi-target output.

## Public Token Language

Public tokens MUST be semantic:

```txt
color.surface.canvas
color.surface.raised
color.surface.sunken
color.surface.overlay
color.text.primary
color.text.secondary
color.text.muted
color.text.disabled
color.border.subtle
color.border.default
color.border.strong
color.accent.solid
color.accent.subtle
color.accent.contrast
color.danger.solid
color.warning.solid
color.success.solid
radius.sm
radius.md
radius.lg
density.compact
density.comfortable
motion.duration.fast
motion.easing.standard
```

Cryptic aliases such as `bgs1`, `fgs1`, `aps1`, or `ccs1` MUST NOT be the public API. Implementations MAY generate internal aliases.

## Theme Format

Theme files MUST be W3C Design Tokens-style JSON:

```json
{
  "$schema": "https://uifn.dev/schemas/tokens.schema.json",
  "schemaVersion": 1,
  "name": "uifn-light",
  "mode": "light",
  "tokens": {
    "color": {
      "surface": {
        "canvas": { "$type": "color", "$value": "oklch(98% 0.01 250)" }
      }
    }
  }
}
```

## Required Themes

First-party themes:

- `uifn-light`
- `uifn-dark`
- `uifn-high-contrast-light`
- `uifn-high-contrast-dark`

Brand theme generation MUST be supported through a typed generator:

```ts
createBrandTheme({
  name: "acme",
  mode: "light",
  accent: "oklch(58% 0.18 245)",
  neutral: "oklch(70% 0.02 245)"
})
```

## Color and Contrast

- Generated ramps MUST use OKLCH.
- Foreground/background token pairs MUST meet WCAG AA by default.
- `accent.contrast`, `danger.contrast`, `warning.contrast`, and `success.contrast` MUST be computed per theme.
- Decorative exceptions MUST be explicit:

```json
{
  "$value": "oklch(80% 0.04 120)",
  "$extensions": { "uifn": { "decorativeOnly": true } }
}
```

## Surface Model

The public model MUST support semantic surfaces:

```ts
surface("canvas")
surface("raised")
surface("overlay")
```

It MUST also support numeric depth for layered UIs:

```ts
surface({ depth: 2 })
```

Recommended public component usage SHOULD prefer semantic surfaces:

```tsx
<Panel surface="raised" />
```

Numeric depth remains allowed:

```tsx
<Panel surfaceDepth={2} />
```

Depth MUST be range-checked.

## Hover and Active Effects

Hover effects MUST be explicit recipe options:

```ts
surfaceHover({ surface: "raised", effect: "tint" })
surfaceHover({ depth: 1, effect: "stripe" })
```

Allowed effects:

- `tint`
- `stripe`
- `border`
- `lift`
- `none`

Default effect: `tint`.

`stripe` MUST NOT be universal default styling.

## Recipe Output

Recipes MUST output:

```ts
{
  className: string;
  style: Record<string, string | number>;
  vars: Record<`--uifn-${string}`, string>;
  data: Record<string, string | boolean | number>;
}
```

Recipes MUST avoid dynamic Tailwind fragments. Generated classes MUST be statically discoverable or generated by the Tailwind plugin.

## Tailwind Integration

`@uifn/theme-tailwind` MUST:

- generate colors from CSS variables,
- generate utility classes for recipes,
- safelist only known static classes,
- support theme selectors,
- avoid requiring Tailwind at runtime.

## Component Styling Escape Hatches

Styled components MUST support:

```tsx
<Button unstyled />
<Button className="..." />
<Button styles={{ root: "...", icon: "..." }} />
<Button vars={{ "--uifn-button-radius": "8px" }} />
```

Equivalent APIs MUST be idiomatic per framework.
