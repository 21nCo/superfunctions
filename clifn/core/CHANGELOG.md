# Changelog

## 0.8.0

- Added `@clifn/core/completion`, also exported from the root (CLI-15, D11): `renderCompletion(spec, "bash")` returns `{ script, skipped }` for a hand-written `CompletionSpec`, completing subcommands to three levels, their aliases, each level's own and inherited flags (each flag name at a level follows one definition, the level's own or else the nearest ancestor's that passes down) and the choices of a flag that takes a value (`--flag value` and `--flag=value`); a value without choices is left to bash's default completion, and a flag whose value may be left out (`valueOptional`) does not read a following word that starts with `-`. Options may set `inherited: false` to stay off their level's subcommands, which keep their ancestor's definition of the name. The script stops completing flags and subcommands after a standalone `--`, compares the words before the cursor without their quotes and backslashes (evaluating nothing), uses only bash 3.2 constructs (no `mapfile`, associative arrays or `compopt`), joins the parts of a word bash splits at `:` and `=`, runs such as `::` included (blanks on `COMP_LINE` keep separate words apart), and shows no descriptions. Names (commands, aliases, flags without dashes, choices) follow `^[A-Za-z0-9][A-Za-z0-9:_-]*$`; others, repeated names and commands below the third level are left out and listed in `skipped` (a command left out lists its aliases, flags and subcommands too, with its reason unless the name is outside the grammar or a repeated flag spelling, and a command whose own name is outside the grammar is completed under its first usable alias). A program name outside the grammar or a malformed spec throws `CompletionError` with `CLIFN_COMPLETION_INVALID_SPEC`, any shell other than `bash` `CLIFN_COMPLETION_UNSUPPORTED_SHELL`.
- `completionInstructions(name, "bash", { command? })` returns the lines telling users where to save the script (bash-completion's user directory or `eval` from `~/.bashrc`); nothing writes files.
- No existing export, default or output changed. Consumer pins in `@extfn/cli`, `@plugfn/cli`, `@mailfn/cli`, `@devfn/cli` and `@devfn/config` move to `0.8.0` without changing their versions or behaviour.

## 0.7.0

- `loadConfig` accepts `policy: "data-only"` (CLI-34; type `ConfigLoaderPolicy`, also exported from the root) and `trustExecutableConfig`. Under the data-only policy discovery reads only `.json` candidates, so `config.json` wins over `config.ts` and no TS, JS, MJS or CJS candidate is imported; when only an executable candidate exists the error is the new code `CLIFN_CONFIG_UNTRUSTED`, naming the file. An explicit TS, JS, MJS or CJS `configPath` raises `CLIFN_CONFIG_UNTRUSTED` before it is checked or imported unless `trustExecutableConfig` is the boolean `true`, the host's explicit non-interactive trust signal (such as a `--trust-config` flag); discovery stays JSON-only with trust, and the loader never prompts. An unknown `policy` raises `CLIFN_CONFIG_INVALID` before any file is read. `configPath` and `trustExecutableConfig` are read once per call.
- `ConfigLoaderErrorCode` gains `CLIFN_CONFIG_UNTRUSTED`, raised only under the data-only policy.
- No existing default changed: without `policy`, or with `policy: "executable"`, discovery, explicit paths and errors are the same as 0.6.0. Consumer pins in `@extfn/cli`, `@plugfn/cli`, `@mailfn/cli`, `@devfn/cli` and `@devfn/config` move to `0.7.0` without changing their versions or behaviour.

## 0.6.0

- Added `@clifn/core/update-check`, also exported from the root (CLI-14, D10, D13): `startUpdateCheck({ name, currentVersion, appName, intervalMs?, timeoutMs?, registryUrl?, fetch?, now?, env?, terminal? })` starts a cached, non-blocking check of the npm registry's `latest` dist-tag and returns `{ notice(), discard() }`; `notice()` resolves `Update available: <current> → <latest> (npm i -g <name>)` or `null` and never waits past the remaining timeout (default 1,500 ms). It never throws. It is skipped in JSON mode, on a non-interactive terminal, when `CI`, `NO_UPDATE_NOTIFIER` or `<APP>_NO_UPDATE_CHECK` is set, and for a `currentVersion` outside the version grammar; a result cached within `intervalMs` (default 24 hours) is reused without a request, and a notice is given at most once per `intervalMs`: it is claimed when the check settles, inside the timeout, unless the cache read that settles it shows a delivery within `intervalMs` on the clock then, or another handle of the app in the process holds a claim; the claim is recorded as `notifiedAt` in one background write (kept across refreshes and error entries, the later delivery always kept), and the first `notice()` call gets it with no file access after any action length (unless the claim is `intervalMs` old by then), later calls `null`. A claim counts as the delivery, so a run that claims and never shows it uses up that interval's notice; the optional `discard()` (called by `runAction` in `quiet` and JSON mode) makes a check that has not settled claim nothing. Two processes whose claim reads both come before either claim is written may both give it (the last-rename-wins boundary). The registry comes from `registryUrl`, else an `https:` `npm_config_registry` / `NPM_CONFIG_REGISTRY`, else `https://registry.npmjs.org`. Errors, timeouts and unusable responses cache `{ checkedAt, error: true }` and give no notice. Versions are compared by SemVer 2.0.0 precedence and a prerelease `latest` never gives a notice. The cache is `<state>/update-check.json`, written through a unique temporary file and a rename; temporary files older than an hour are removed by the next write.
- `RunnerOptions.updateCheck` (optional): in text mode `runAction` writes the handle's notice as one stderr line after the action finishes, on success or failure, keeping the exit code; JSON mode and `quiet` never ask for it and call the handle's optional `discard()` at the start, so the check claims no notice.
- No existing export, default or output changed: without `updateCheck`, text mode, JSON-lines mode and document mode print the same bytes as 0.5.0. Consumer pins in `@extfn/cli`, `@plugfn/cli`, `@mailfn/cli`, `@devfn/cli` and `@devfn/config` move to `0.6.0` without changing their versions or behaviour.

## 0.5.0

- `runAction` accepts `jsonStyle: 'lines' | 'document'` (CLI-22, D8; type `RunnerJsonStyle`, also exported from the root). With `mode: 'json'` and `jsonStyle: 'document'`, stdout receives exactly one newline-terminated JSON document per run, `{"ok":true,"data":...}` or `{"ok":false,"error":{"code","message","details"?}}`, with `diagnostics` only when there are any. Every log level and a spinner's `succeed`/`fail` message is a JSON line on stderr (`quiet` and `verbose` apply), streamed child output goes to stderr unless the command passes its own writers, and `output.json()`/`output.table()` are collected: the last `json` value becomes `data` when the action returns none, absent or JSON-dropped data prints `null`, and a stderr warning names each unused call. Error codes and exit codes follow the CLI-12 classification; plain-object `details` of any realm are kept when they serialize to an object, and an unusable diagnostic (including a severity other than `error`, `warning` or `info`) is left out with a fixed stderr warning.
- `resolveRunnerOptions` now returns `jsonStyle: 'document'` with `mode: 'json'` for `--json`. Callers of `runAction` that leave `jsonStyle` out keep JSON lines, and text mode and JSON-lines mode print the same bytes as 0.4.0.
- Document redaction is key-based on the emitted structure: in `data`, error `details` and diagnostic `details`, every key matching the existing sensitive-key pattern, or `DOCKER_AUTH_CONFIG`, prints `"[REDACTED]"`, matched after each `toJSON` runs. Messages print as given, and a custom projection that renames a sensitive key or fills an unrelated key is the caller's to make safe. `redactValue` and the diagnostics formatters keep their pattern.
- Document bounds: one pass that follows `JSON.stringify` (each member, getter and `toJSON` read or run once, in native order), `"[Circular]"` for an object already being serialized and after 64 nested projections of one value for one member key, at most 512 nested levels, and a document of at most 2,097,152 characters (less only where the engine's maximum string length or a sixteenth of V8's heap limit is smaller; no heap flag or `NODE_OPTIONS` value raises it, so it fits a 32 MiB old generation in every configuration (a smaller old generation is not detected), and a larger result prints the bounded `CLIFN_RUNNER_FAILED` document; use JSON lines for output of that size); each kept diagnostic is held as one string of its text. A redacted value costs only its key and placeholder; work that prints nothing (redacted or left-out values, scans of text too long to print, details or diagnostics written and then left out, typed-array keys and numeric-string reads under a redacted key) has its own allowance of twice the document's characters plus a quarter of them for printed keys, each unit charged once, so a document that fits prints next to it in any member order; the typed-array keys and numeric-string reads of values that print are charged to a separate allowance of six units per document character, never to the allowance for work that prints nothing; every work charge goes through one table of the kind of work and its member's redaction, and each listed key costs 1 unit plus 1 per 64 characters; oversized arrays fail before their first item is read; escaped text is never built only to measure it. Data that does not fit or cannot be serialized prints a fixed `CLIFN_RUNNER_FAILED` document (exit 1); details, diagnostics and an over-long error message are left out or replaced while the code and exit code stand.
- Document hardening: the projection cut counts projections of one value per member key on the active path, so a finite sibling of the cut branch prints in full at any depth and member order, and a value branching back under several keys fails on the document bounds; a returned diagnostic that cannot be read is left out with a warning, keeping its siblings, data and exit code; streamed child output to a throwing stderr writer is dropped instead of escaping the child stream listener; an over-long code or message is never scanned by the code patterns; the text of a dropped diagnostic or details is charged to the work allowance, and text that does not fit is never counted, so an oversized member (such as a `JSON.rawJSON` value) charges only what was written before it; each key is matched against the sensitive-key pattern once, before its member is read (paid by its listing charge), so all the work of a member under a redacted key, its own projection included (a `Number` box's numeric string, a `Buffer` copied by Node's built-in `toJSON`), is charged to the allowance for work that prints nothing, and long printed keys no longer spend it; a bigint found too long to print is charged to that allowance, so diagnostics sharing an oversized bigint stop being read once it is spent, and its size check costs at most the characters left; a `Buffer` projected by Node's built-in `toJSON` is read in place, bounded like an array, and a receiver whose length cannot be bounded fails instead of being copied; own keys JSON skips (non-enumerable or symbol) are charged to the work allowance; `onDiagnostics` receives only the returned diagnostics that could be read; the fixed failure document for an unreadable result still warns for unused `json()`/`table()` calls; the stderr writer and a command's stream options are read once; an `Error`'s `name` used as the message is read once; typed arrays are bounded by their length before their keys are listed and bigints by size before conversion (never converted under a redacted key); a result whose getters throw prints the fixed `CLIFN_RUNNER_FAILED` document instead of being reported as the action's error; `onDiagnostics` is called once; each diagnostic is written once, when it is added or returned, and kept as its redacted text within bounds set by the document limit (text and work; the details of listed copies have their own allowance), so `ctx.diagnostics.list()` and `onDiagnostics` receive redacted copies as the document prints them rather than the objects given, and reading stops once nothing more can be kept; a diagnostic added while another is being written is dropped with a warning; the key lists of the objects open on the path are bounded together, so nested objects (or proxies sharing one key list) fail before their keys are listed once those lists pass a quarter of the document limit (at least 65,536 keys); each listed key is charged to the work allowance when it is listed, never given back, so listing one object again and again stops, and only one key list of an object is held; returned diagnostics are read only from an array (as `Array.isArray` sees it, through proxies and realms), by index: any other value, including a generator or other iterable and a string or `String` object (proxied or not), is one unreadable diagnostics list, and no iterator is opened; a bigint is converted by the primitive's own ToString, which never reads `BigInt.prototype`, so a `toString` replaced even before import cannot print an object, and the string encoder accepts only primitive strings; the fixed failure document and the runner's stderr warnings are fixed text, unaffected by an inherited `toJSON`; the output options are read once each, in the order JSON lines always read them; a thrown value's code, message and exit code are read before its `details`; serialization never asks a Proxy for its prototype; an object whose key list would take the open lists past their bound fails before any of its descriptors is read; log lines and spinner results that a throwing stderr writer rejects, or that fail while they are formatted, are dropped instead of replacing the document; the fixed failure document still warns for each diagnostic and `json()`/`table()` call it leaves out, including the `json()` value it replaced; a `JSON.rawJSON` value prints its raw text; stderr warnings are bounded (20 per kind and a summary) and a throwing stderr writer no longer changes the document or exit code. Redaction covers the stdout document; stderr log `details` print as given.
- Document coercion: an array length and a boxed `Number` or `String` run `Symbol.toPrimitive`, `valueOf` and `toString` once each in native order, and the result is bounded before it is converted: a numeric string longer than 1,024 characters fails as the fixed document (in data, also under a redacted key), leaves out error or diagnostic details, or makes a returned diagnostics list unreadable; a bigint from a `String` box is checked by size and never converted under a redacted key. A returned `String` object of any realm is one unreadable diagnostics list and is never iterated.

## 0.4.0

- Added `@clifn/core/terminal`, also exported from the root (D9): `resolveTerminal({ env?, stdin?, stdout?, stderr?, json? })` returns `{ color, interactive, ci }`, and `resolveRunnerOptions(flags, { env?, streams? })` turns parsed `json`, `quiet`, `verbose`, `color` (`true`, `false` or `'auto'`), `yes` and `nonInteractive` flags into runner options (`json` selects `mode: 'json'`, which prints JSON lines). Colour is resolved per stream: `stderrColor` (errors and the spinner) follows the terminal rules, and in text mode `color` (stdout) also needs a TTY stdout unless `--color` or `FORCE_COLOR` asks for it. `RunnerOptions` and `OutputOptions` accept an optional `stderrColor`, which defaults to `color`.
- `createPrompt({ ask?, output?, nonInteractive? })`: `nonInteractive: true` makes every prompt throw `PromptInputError` with code `CLIFN_PROMPT_NON_INTERACTIVE`; an options object that names `output` or `nonInteractive` writes the default asker's question to `output`, else stderr. `PromptInputError` takes an optional code; its code type stays `"CLIFN_PROMPT_INPUT_ERROR"` unless another code is passed.
- No existing export, default or output changed: text mode, JSON-lines mode, `createPrompt()`, `createPrompt({})`, `createPrompt({ ask })` and the `prompt` singleton print the same bytes to the same streams as before.

## 0.3.0

- Added `@clifn/core/paths` (CLI-13, D7), also exported from the root: `resolveAppPaths(appName, { platform?, env?, homedir? })` returns the config, state and cache directories (XDG on Linux and macOS, `%APPDATA%` / `%LOCALAPPDATA%` on Windows; relative or empty environment values fall back to the defaults), and `ensureAppDir(dir)` creates a missing directory with mode `0o700`. App names follow `^[a-z0-9][a-z0-9._-]{0,63}$`; anything else throws `InvalidAppNameError` (`CLIFN_INVALID_APP_NAME`). A non-absolute home directory throws `InvalidHomeDirectoryError` when a default directory needs it.
- `createCredentialStore` accepts `{ appName }` (`<config>/credentials`) or `{ path }`; `createProjectConfig` accepts `{ appName, fileName? }` (`<config>/config.json` by default), `{ cwd?, fileName }` or `{ path }`; `{ appName }` stores resolve for the current platform (`env` and `homedir` may be passed through). Only own properties of the options object are read (inherited keys are ignored), and an optional key set to `undefined` takes its default; malformed options (a selector set to `undefined` or a non-string, a key from another form, an unknown key, or a `platform` other than the current one) throw `InvalidStoreOptionsError` (`CLIFN_INVALID_STORE_OPTIONS`). On Windows a UNC value needs a real server and share, and device or extended-length (`\\.\`, `\\?\`) values are not used.
- On Windows an app name cannot end with `.` or be a device name (`con`, `nul.txt`, ...), so two names never share a directory. Object-form store targets must name a file (no empty path, root, trailing separator or NUL in `path`, `fileName` or `cwd`; environment values with a NUL fall back like relative ones; no drive in `fileName` after normalization; on Windows no `:`, control or `<>"|?*` character, device name or trailing dot or space in a file segment; a device name is matched after trailing ASCII spaces only, so `aux\u00a0.json` is a file), options are read from their own property descriptors before any getter runs, a malformed `platform` reports `CLIFN_INVALID_STORE_OPTIONS`, and loading the package no longer fails when the home or working directory is unavailable.
- No existing export, default or output changed: the string and no-argument forms keep their paths, including the Conduct defaults.

## 0.2.0

- Added the consumer compatibility baseline (CLI-11): `tests/consumer-contract.table.ts` lists every `@clifn/core` import that `@extfn/cli`, `@plugfn/cli`, `@mailfn/cli`, `@devfn/cli` and `@devfn/config` use; `consumer-contract.test.ts` checks each runtime symbol's kind from the built subpath, `consumer-contract.test-d.ts` checks the types and option shapes those consumers rely on, and `consumer-scan.test.ts` fails when a consumer imports a symbol or subpath the table does not list.
- Declared `engines.node` `>=20`. The runtime `ini` dependency moves from `^5.0.0` to `^4.1.3`, whose engines admit every Node 20 release; `ini` 5.0.0 only narrowed the engines range to `^18.17.0 || >=20.5.0` and ships the same code.
- Added a `typecheck` script; `test` now runs once (`vitest run`) and includes the type-level contract tests.
- No export, default or output changed.
