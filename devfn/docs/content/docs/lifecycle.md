---
title: Lifecycle and diagnostics
description: Start, inspect, stop, and recover one worktree instance.
---

`devfn up` plans resources in dependency order, reserves ports before mutation, starts selected native processes and Compose services, verifies readiness, registers proxy routes, and returns a machine-readable receipt. If an invocation fails, rollback targets resources created by that invocation. `status`, `logs`, and `doctor` expose live state and diagnostics; `down` stops only the exact worktree instance. `restart` validates the selected profile, registered domains, and replacement ports while the ready instance keeps running, then stops it and starts it again from the current working tree; a failed restart does not relaunch the previous processes. Status reports a ready instance as `degraded` when its declared startup inputs, Compose configuration, Caddy owner, or committed routes no longer match its receipt, and the next `up` replaces it.

There is no background daemon in version 0.1. Receipts, process logs, and generated runtime outputs live under the configured runtime directory (`.devfn/` by default). Configured `environmentOutputs[].path` files can live elsewhere within the repository. Machine-wide trust records, port registry, lifecycle locks, and proxy state instead use `$XDG_STATE_HOME/devfn`, falling back to `~/.local/state/devfn`. Account for both locations when inspecting or cleaning up state. Process ownership uses a PID birth signature where the host supplies one and judges each recorded process with its whole process group, so cleanup refuses a reused PID. When a live process's identity cannot be verified, teardown reports a cleanup error, leaves the receipt `degraded`, and keeps its leases and routes until a later `down` can verify or stop it. `devfn ports gc` reconciles leases and removes the routes of instances whose recorded owners are all verified dead, such as a deleted worktree.

Ordinary `down` does not delete persistent Docker volumes. It is also not a general reset command. Explicit configured environment outputs may have overwritten files that existed before adoption; inspect them before manual cleanup. The [core package](/docs/reference/core), [process supervisor](/docs/reference/processes), and [migration guide](/docs/reference/migration) describe lifecycle boundaries.
