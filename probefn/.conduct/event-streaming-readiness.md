# Streaming event reads

Event delta counting previously loaded and retained every event payload before counting. A 160,000-record fixture exceeded a 64 MiB V8 heap and aborted with the prior delta implementation. The same fixture now completes under that heap limit with all 160,000 errors counted.

The storage async iterator reads 64 KiB chunks, yields one parsed record at a time, preserves physical line numbers and numeric rollover order, and closes actual file handles on completion, early return and failure. Each segment scan is bounded to the size observed when reading starts; appends become visible on a subsequent scan. Missing anchors preserve existing caller behavior. Missing rollover indexes, ambiguous numeric aliases, a disappeared rollover, a truncated segment or invalid JSON fail explicitly rather than returning partial evidence. Errors identify the relative segment and line without including raw payloads.

A configurable maxRecordBytes bounds an encoded record (default 64 MiB, excluding newline); exceeding it raises E_STORAGE_CAP_EXCEEDED without truncation. The compatibility collector remains available. Action delta counts consume the iterator directly. Reports construct their required output index directly without a second temporary array of stored records.

Validation: Node 22 unified 135 tests across 30 files and strict TypeScript checks pass. Eleven new regressions cover UTF-8 crossing chunk boundaries, CRLF/blank/final lines, exact byte limits, malformed records, early file-handle closure, disappearance/truncation, append boundaries, missing/ambiguous rollover indexes and counting across rollover. All JSON values accepted by the existing sink writer remain readable. Existing storage-to-MCP/report provenance coverage passes. Run `npm run test:event-streaming --workspace=@probefn/workspace` for the actual constrained-heap acceptance; its temporary fixture is removed on success/failure.

Limits: directory enumeration retains the segment names, and each parsed record requires memory proportional to its bounded size. This is a live append-only scan, not a retained cross-file snapshot or protection against replacement. The compatibility collector and final report document still retain output-sized memory. The three MCP event tools subsequently gained bounded pages; see `mcp-event-pagination-readiness.md` for their cursor contract and validation. This does not fix durable per-run disk accounting, external browser artifact accounting, Firefox launch, Windows process ownership, packaging, hosted or performance/accessibility gates.
