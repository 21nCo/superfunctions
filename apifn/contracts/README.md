# @apifn/contracts

Versioned contracts shared by ApiFn SDK generators, agent tools, failure reporting and documentation:

- an **operation catalog** built from a reviewed OpenAPI document plus a companion manifest,
- a **release descriptor** for generated artifacts,
- a bounded, secret-free **client-failure event** envelope,
- JSON Schemas and shared JSON fixtures for all of the above.

OpenAPI stays the interoperable spec. The manifest adds the identity and policy that OpenAPI cannot carry reliably.

## Installation

```bash
npm install @apifn/contracts
```

## Entry points

| Import | Contents | Runtime |
| --- | --- | --- |
| `@apifn/contracts` | everything below; the catalog builder parses specs with `@apifn/core` | Node |
| `@apifn/contracts/failure-event` | `validateClientFailureEvent`, limits and types | any (no `@apifn/core`, no Node built-ins) |
| `@apifn/contracts/schemas/<name>.v1.schema.json` | JSON Schema 2020-12 for `manifest`, `operation-catalog`, `release-descriptor`, `client-failure-event` | data |
| `@apifn/contracts/fixtures/...` | shared fixtures (see below) | data |

## Building a catalog

```ts
import { buildOperationCatalog, canonicalJson } from "@apifn/contracts";

const { catalog, digest, diagnostics } = buildOperationCatalog(openapiJsonOrYaml, manifest);
if (!catalog) throw new Error(diagnostics.map((d) => `${d.code} ${d.pointer}: ${d.message}`).join("\n"));
writeFileSync("catalog.json", canonicalJson(catalog));
```

The spec may be a JSON/YAML string or an object, OpenAPI 3.0 or 3.1.0; text is read as `@apifn/core`'s `parseOpenAPI` reads it (JSON, else YAML), and the document goes through `parseOpenAPI`. OpenAPI 3.0 is upconverted to 3.1.0 here first, at Schema Object positions only (component, parameter, header and media-type schemas and their subschemas): `nullable: true` is dropped there and adds `"null"` to a string or array `type`. Positions are found by OpenAPI object context as the catalog resolves it, so an object reached through a Reference Object (a parameter behind `#/x-param`, a response behind another operation's member, a chain of up to 32 objects) is converted with the type of the referencing position, and the fields beside a Path Item `$ref` are read as Path Item fields. In OpenAPI 3.1 a Reference Object's own `description` overrides its target's for parameters, responses and security schemes, the first one along a reference chain winning; OpenAPI 3.0 ignores fields beside `$ref`, so a 3.0 document keeps the target's description. Literals (`default`, `const`, `enum`, `example`, `x-*` values, including unreferenced `x-*` members of the Paths, Responses and Callback maps) and map keys (`properties`, `patternProperties`, `$defs`, component names), including own `__proto__` keys, pass through byte for byte, so a 3.0 document gives the same catalog as its 3.1 form with any installed `@apifn/core` (whose own upconvert rewrites `nullable` everywhere, and in the published 0.0.3 loses `__proto__` keys). Catalog schemas are JSON Schema 2020-12, and exclusive bounds are read in the source document's dialect (taken from its `openapi` field before upconversion). In OpenAPI 3.0 they are booleans and are converted: `minimum: 0, exclusiveMinimum: true` becomes `exclusiveMinimum: 0` (the same for `maximum`), `exclusiveMinimum: false` keeps the inclusive bound and is otherwise dropped, and `true` without its bound is `INVALID_SPEC`. In OpenAPI 3.1 they are numbers and are copied verbatim. A numeric bound in a 3.0 document or a boolean one in a 3.1 document is `INVALID_SPEC` at the keyword, never reinterpreted. Identical inputs produce byte-identical `canonicalJson(catalog)` and the same `digest` (`sha256:<hex>` over those bytes). Canonical JSON sorts every object key, including integer-like keys, by UTF-16 code unit and has no whitespace (RFC 8785 ordering), so non-JavaScript consumers can reproduce digests. It rejects (throws on, and the builder reports as invalid input) data with no single JSON form: non-finite numbers, sparse array holes and lone surrogates in strings or member names. Reordering object keys in the spec or manifest changes nothing: a component schema reached from a credential field is emitted without literals, and that taint is settled over the whole reference graph before any component is emitted. Any error diagnostic returns a `null` catalog.

### Companion manifest

```json
{
  "manifestVersion": 1,
  "api": { "id": "example.projects", "version": "2026-10-01" },
  "serialization": { "mediaTypes": ["application/json", "application/problem+json"] },
  "provenance": { "source": "openapi.json", "revision": "af261f9", "exporter": "@apifn/core#generateOpenAPI" },
  "operations": [
    { "id": "projects.get", "method": "get", "path": "/projects/{projectId}", "name": "getProject" },
    { "id": "projects.list", "operationId": "listProjects", "agent": { "expose": true }, "executionPolicy": "policy.read-only" },
    { "id": "projects.delete", "operationId": "deleteProject", "deprecation": { "replacement": "projects.archive", "since": "2026-09-01" } },
    { "id": "projects.archive", "operationId": "archiveProject", "sdk": { "excludeTargets": ["python"] } }
  ]
}
```

- `id` is the stable operation identity. Bind it with `operationId`, or with `method` + `path` to survive operationId renames. `name` overrides the generated method/tool name; changing it never changes `id`.
- `sdk.include` (default `true`) and `agent.expose` (default `false`) are separate switches. Exposing an operation to agents requires an `executionPolicy` reference.
- HTTP method, schema presence and inclusion never grant authorization or idempotency. The catalog has no such fields. `security.alternatives` lists the credential combinations the API accepts (OR of ANDs, `[[]]` = anonymous); it grants nothing. A term's `scopes` are OAuth scopes for `oauth2` and `openIdConnect` schemes and role names for the others (OpenAPI 3.1 only; 3.0 requires none there).
- `serialization.mediaTypes` (default `["application/json"]`) lists what clients must support: JSON (`application/json`, `application/*+json`), `text/plain`, `application/octet-stream`, `application/x-www-form-urlencoded` and `multipart/form-data`.

### Catalog shape

`catalogVersion`, `api {id, version, title}`, `source {specDigest, manifestDigest, provenance}`, `serialization`, `servers`, `securitySchemes`, `operations[]` sorted by `id` (each `id` unique), and `schemas` (component schemas reachable from operations). Schema `$ref`s are emitted in one form, `#/components/schemas/<name>`, where the name has `~` written as `~0`, `/` as `~1` and `%` as `%25` (component `a/b` is emitted as `a~1b`, `a%b` as `a%25b`). To read one, apply RFC 6901 section 6: percent-decode the whole fragment, split it on `/`, then unescape `~1` to `/` and `~0` to `~`; the last segment is the key in `catalog.schemas`. `$dynamicRef` and `$recursiveRef` are references too: they must target `#/components/schemas/<name>` and their schemas are included. Discriminator mapping targets (a schema name or reference) are emitted in the same form, and the schemas they name are included. Literal `default`/`const`/`enum` data is copied with its keys verbatim, including keys that start with `x-`; a credential-like string in it is replaced whole like free text (reported as `CREDENTIAL_REDACTED`), so `enum: ["token=abc123"]` becomes `["[REDACTED]"]`. Property names in `required` and `dependentRequired` are checked like property names and copied verbatim, never redacted, so they always match `properties`. Operations merge path-level and operation-level parameters (operation wins). Path parameters follow path-template order. Parameters keep `style`, `explode` and `allowReserved`. Form and multipart contents keep their per-property `encoding` (`contentType`, `style`, `explode`, `allowReserved`); other contents have an empty `encoding`. Responses are classified as `success`, `error` (4xx/5xx) or `default`; an OpenAPI 3.1 operation without `responses` (optional in 3.1) has `responses: []`; `x-*` response, path and OAuth flow keys are extensions and are skipped. Servers keep their `variables`. `operation.servers` holds a path- or operation-level override, or `null` to use the catalog servers; an empty override array is kept as `[]`. A document without root `servers` yields `servers: []`, not the OpenAPI default `[{url: "/"}]`; consumers apply that default.

### Credentials

Catalogs never carry `example`/`examples` or `x-*` extensions. URLs lose all user info (with or without a scheme, with or without `//` after a special scheme, however many `@` they hold), credential-like query parameters and fragments. Server URLs also lose their whole query. Server variables are judged against the original template, before stripping: a variable that fills any user info, query or fragment of the template (`https://{user}:{pass}@host`, `?api_key={k}`, `#{k}`), or that the emitted URL no longer uses, keeps no values; its default becomes `[REDACTED]` and its `enum` is dropped, each reported as `CREDENTIAL_REDACTED`. Variable values are also judged together, in the template expanded with every default and then with each `enum` value in turn: user info lying wholly inside one value is cut out of it (`svc:pw@api.test` as `{authority}` becomes `api.test`, `https://svc:pw@api.test` as `{base}` becomes `https://api.test`); any other value that reaches the user info, query or fragment of the expansion (`{prefix}{suffix}` with `svc:pw` and `@host`, or a host value ending in `?api_key=`) hides every variable that reaches it in the same way. Last, every combination of declared values is expanded (a hidden variable at each of its raw values, the others at each value the catalog would publish), so one variable's scheme and another's user info are judged together (`{base}{authority}` with `base` enum `/`, `https://` and an `authority` enum value `svc:pw@host`); any variable that a combination puts into user info, a query or a fragment is hidden. Every judgement expands the whole URL, so each one (per default, per `enum` value, per combination) is charged before it runs to one budget of 4,000,000 expanded characters per document (servers are judged in a fixed order, paths sorted). When a judgement would exceed what is left of it, or any value or the template holds `@`, `?` or `#` and there are more than 4096 combinations, every variable of that server is hidden. Benign query parameters on OAuth and OpenID Connect URLs are kept.

Inside credential fields, literal `default`/`const`/`enum` values and unrecognized schema members are dropped. A credential field is one of these:

- a parameter with a credential-like name,
- a parameter at the `in` and `name` of a declared `apiKey` security scheme (header names match case-insensitively),
- a credential-named property,
- a `format: password` schema.

The rule also covers every subschema, applicator (`anyOf`, `items`, …) and component schema reached from such a field. A `default`, `const` or `enum`, or any member that is not a recognized schema keyword (it could hold a default under another name, as `fallback: {pin: "…"}` beside a password `pin` does), is also dropped when the instance it describes could hold a credential field's value: when its schema, or any schema for the same instance, reaches a credential field (a credential-named property or `format: password`, through any subschema or `$ref`). Schemas for the same instance are a schema's `allOf`, `anyOf`, `oneOf`, `not`, `if`/`then`/`else` and `dependentSchemas` members and `$ref` targets, transitively, so `{allOf: [{format: password}, {default: "…"}]}`, `{allOf: [{properties: {pin: {format: password}}}, {default: {pin: "…"}}]}` and a component whose own `allOf` holds a password member lose the literal, as does a component reached as such a member (`{allOf: [{format: password}, {$ref: "#/components/schemas/Literal"}]}` emits `Literal` without its literals). Schema members whose names, or nested keys, name or hold a credential are dropped everywhere, as are schema `pattern`s whose literal text holds one and literals holding, at any depth, an object whose name field names a credential next to a value field (`default: {name: "X-Api-Key", value: "…"}`, the structured form of the name/value text rule below). A credential field carries no `pattern` at all, because a pattern can spell the credential in any regex syntax (`^hunter2$`, `^(hunter2)$`, `^hunter2{1}$`). Credential-named server variables are replaced with `[REDACTED]`.

Free text copied into the catalog (descriptions, summaries, titles, tags, server and scheme descriptions, `bearerFormat`, and strings in literals) that holds a credential is replaced whole with `[REDACTED]`, so no part of a value survives however its end is read. Identifiers and map keys are copied verbatim into generated clients, so a credential in one (an `operationId`, path template, parameter, property, discriminator mapping, component, security scheme, flow or scope name, or a manifest identifier) is an `INVALID_SPEC` or `INVALID_MANIFEST` error, never redacted. In identifiers `:` is a namespace separator, so scopes such as `secrets:read` and error codes such as `password:too_short` are names; a segment after a credential-key namespace is still a credential when one of its words (split at `_`, `.`, `-`) is token-shaped (see below) or 16+ characters long, so `password:hunter2SEED99` and `api_key:AbCdEf123456Ghij` are rejected. These count as credentials:

- the whole value after a credential-named key followed by `:`, `=`, `=>` or `:=`, in any syntax: HTTP headers (`X-Api-Key: …`), JSON (`"Cookie":"…"`, also escaped at any depth, as `\"password\":\"…\"` or, stringified twice, `\\\"password\\\":\\\"…\\\"`), JS literals (`authorization: '…'`), query and connection strings (`client_secret=…`, `api%5Fkey=…`, `Pwd=…`) and prose (`Invalid API key: …`). The key is the last one or two words before the separator, tested with the same `isCredentialKey` used for field names (percent-decoded, separators ignored). The value is a quoted string (up to its closing quote, escaped at the same depth as the opening one; the text is decoded level by level, so a quote escaped deeper, such as `\\\"` inside `\"…\"`, does not close it, and a quote of a lower level that ends the outer string first redacts to the end of the line or past that quote, whichever is further; a letter, digit or one of `_$%+~*@-` right after the closing quote continues the value as an unquoted run, as shell and dotenv words do: `PASSWORD="<token>"abc`), a balanced `{…}` or `[…]`, an `Authorization`/`Cookie` header line with every scheme parameter, a YAML block (after `password:`, `password: |`, `password: >-` and the other block indicators, every following line indented deeper than the key's line; mixed tab and space indentation is redacted to the end of the text; a `#` comment after the key is judged as text of its own, so `password: # token=…` redacts the comment's value too; as in YAML, a `#` starts a comment only after a space or tab, so `Pwd=#…` and `password: |#…` are values), or, for any other value, a run to the end of its line. Whitespace never ends that run (`password: first second` and `password: <token> abc` are one value each). It ends earlier only at a delimiter of the surrounding syntax: the closing quote of a string holding the key (`"password: …"`), a comma or the closer of the `{…}`, `[…]` or XML tag holding the key (`{password: …, x: 1}`), `;` or `&` after `=`, `=>` or `:=` (`Pwd=…;`, `?password=…&x=1`), or a ` #` comment outside containers and strings. Strings and balanced `{…}`, `[…]` and `(…)` inside the run are part of it; an unbalanced one is redacted to the end of the text. Over-redacting the prose after a value is the accepted cost (`The API key: … was rejected` redacts to the end of the line). A value that cannot be delimited, such as an unterminated quote, is redacted to the end of the text. The value counts at any length and even when it reads as prose (`Authorization: missing`), unless all of it is placeholders such as `<token>`, `{{token}}`, `$TOKEN` or `[REDACTED]`. The value runs to its real delimiter even after a placeholder, so `<token>abc123`, `[REDACTED]abc123` and `{{token}}abc123` are credentials. Scheme words (`Bearer`, `Basic`, …) count as placeholders only in `Authorization` and `Cookie` headers, so `client_secret=Bearer` is a credential. XML elements named like a credential count too: the value runs from the end of the opening tag, attributes included, to the closing tag that matches it by nesting, with any nested markup, CDATA and comments (`<password type="string"><![CDATA[…]]></password>`). An opening tag of the same name nests one level deeper, and a closing tag inside a comment or CDATA section does not count, so `<password><password></password>…</password>` and `<password><![CDATA[</password>…]]></password>` are redacted whole; elements wholly inside a comment or CDATA section are still found. Where the structure cannot be trusted the value runs to the end of the text: an element left open (also by an unterminated comment or CDATA section), unless the tag is a bare placeholder (`<password>` followed by a space, punctuation, an escaped quote or the end) whose structure is not ambiguous; an element left open while a closing tag of its name closed a nested element or fell in a comment or CDATA section is ambiguous (`<password> <password></password>…`, `<token> <!-- </token> --> …`); or a closing tag with nothing of its name open, which reopens the first element of that name (`<password>a</password>…</password>`) or, with none, takes the text since the markup before it. Every attribute value of such an element is a credential too (`<password id="…" value="…"/>`),
- the value field (`value`, `values`, `val`, `content`, `data`, `default`, `example`, `examples`, each also with a `header`, `field`, `param` or `parameter` prefix and an optional `_` or `-`: `headerValue`, `paramDefault`, `field_example`, `parameter-data`) of a container whose name field (`name`, `key`, `header`, `field`, `param`, `parameter`, and `headerName`, `fieldName`, `paramName`, `parameterName`) holds a credential key, in either order. A quoted name is read like a structured one: up to its real closing delimiter on the same line (the same quote at the same escape level, so `"user's password"` and `"the \"API key\""` hold their inner quotes), then decoded at any escape depth (`"API\tkey"`, so a raw character and its escape such as `\u2028` read alike) and trimmed, so any words, whitespace and punctuation count (`" X-Api-Key "`, `"API\u00a0key"`, `"x-api-key/v2"`). A quoted credential name that ends in its separator (`header: "X-Api-Key:" …`, `key: "password=" …`) also holds the rest of its line as its value, unless a field ends right after its closing quote (the comma or closer of the container holding it, the end of the string holding it, or the next XML attribute), as in `{"name":"X-Api-Key:","value":"…"}`, where the value field holds it. Outside a container a comma, `;` or closer after the quote is part of the value (`header: "X-Api-Key:", …`), and the name's own `=` does not make `;` or `&` end it; a bare name is one or two words: `{"name":"X-Api-Key","value":"…"}`, `{key: 'client_secret', value: '…'}`, `<add key="password" value="…"/>`. A container is the innermost `{…}`, `[…]` or XML tag, else the string holding the fields (escaped JSON quoted whole); text outside every container and string is prose, not a container (`Set name=password; today value=Monday`). Strings are skipped: a delimiter inside `"…"`, `'…'`, `` `…` `` or a string quoted with escaped quotes at any depth (`\"…\"`) neither opens nor closes a container (`{"name":"password","note":"}","value":"…"}`). When the structure cannot be trusted (an unterminated or ambiguous quote, a closer that does not match the innermost open container, or a stray `}`, `]` or `>` with no open container, as an unquoted bracket in a regex, comment or prose leaves) the whole text is one container,
- the second element of a two-element list or tuple whose first element is a quoted credential key, as in header entries: an opening `[` or `(`, the key (spaces inside its quotes trimmed), a comma, the value, an optional trailing comma and the matching `]` or `)`: `[["X-Api-Key","…"]]`, `new Headers([['authorization', 'Bearer …']])`, `["X-Api-Key","…",]`, `dict_items([('client_secret', '…')])`, also escaped at any depth (`[\"client_secret\",\"…\"]`). An unquoted value runs to the comma or closer that ends it, whitespace included (`('client_secret', first second)`); a value that no comma or closer follows fails closed. A longer list (`["password","email","name"]`) is not a pair. Structured literals follow the same rule at any depth, keys trimmed alike (`default: [["X-Api-Key", "…"]]` is dropped); an `enum` lists values, so it is judged member by member and `enum: ["password", "otp"]` is kept,
- PEM private keys (`-----BEGIN … PRIVATE KEY-----`) through their `END` line, or to the end of the text when cut off,
- a standalone `Bearer`/`Basic` followed by a token-shaped word: 8+ characters with letters and digits, `+=_~`, or two lower-to-upper case changes. Plain words and version-like words are prose, so "Basic internationalization support", "Bearer authentication/authorization required" and "Basic HTTP/1.1" are kept,
- JWTs, provider keys (Stripe, GitHub classic and fine-grained `github_pat_`, Slack, AWS, Google) and URL user info. For the special schemes `http`, `https`, `ws`, `wss`, `ftp` and `file`, user info needs no `//`: as URL parsers do, any run of `/` or `\`, even none, starts the authority, so `https:svc:pw@host` and `https:\\svc:pw@host` lose `svc:pw` (in catalog URLs, free text and the catalog schema's server URL pattern). In these URLs, and in scheme-relative `//` ones, a `\` also ends the authority, as WHATWG URL parsers read it, so user info is only what precedes the last `@` before it: `https://u:pw@a.test\x@y` keeps host `a.test`. Where a `\` precedes an `@` that RFC 3986 parsers still read as user info (`https://api.test\users\@me`), the two kinds of parser disagree on the host, so a catalog URL is an error (`INVALID_SPEC`, or `INVALID_MANIFEST` for the provenance source), every server variable that contributes to what either parser reads as user info (from the start of the authority through the last `@` either one reads in it, as in `https://{h}{p}` with `p` at `\u@me`) is hidden, and free text redacts the whole authority; no different host is ever shown.

Every rule runs in time linear in the text: no pattern rescans a long word once per character, and no match scans past the span it consumes (a bracketed value, line or YAML block that several matches reach is scanned once).

The failure-event validator rejects exactly the text the catalog redacts. Every removal is reported as a `CREDENTIAL_REDACTED` warning. Diagnostics and failure-event issues all pass through one sanitizer: a pointer segment whose raw key holds a credential becomes `[REDACTED]`, judged before JSON Pointer escaping (otherwise a URL key's `//` would become `~1~1` and hide its user info), every author string quoted in a message (a key, name, reference, value or media type) is either unchanged or replaced whole with `"[REDACTED]"`, and messages are redacted as text. As a backstop, when the message, or a double-quoted segment of it judged on its own, holds a credential, everything from that segment's opening quote through the message's last quote becomes `"[REDACTED]"`. Parse failures report only a line and column, never source text. Authorization header parameters are ignored, as OpenAPI specifies.

### Diagnostics

| Code | Meaning |
| --- | --- |
| `INVALID_SPEC` | the document is neither a string nor an object (such as `null`), cannot be parsed or lacks `info`/`paths`, or is not plain JSON data (a cycle, getter that throws, class instance, more than 248 levels of nesting or 1,000,000 values); any OpenAPI member the catalog reads has the wrong type, such as an operation that is not an object (`get: null`), `responses: []`, `content: []`, `servers: {…}`, `tags: "x"`, `properties: []`, `required: "yes"` or a non-string description (a present value is never replaced by a default); a schema keyword has the wrong JSON type (`type` not one of the seven type names or a non-empty array of distinct ones, `enum` not an array, `multipleOf` not a number above 0, a numeric bound not a number, a length or count keyword not a non-negative integer, `pattern`, `format`, `title`, `description`, `$comment`, `contentMediaType` or `contentEncoding` not a string, `uniqueItems`, `readOnly`, `writeOnly`, `deprecated` or `nullable` not a boolean), checked before any credential rule reads it; a schema keyword breaks its JSON Schema 2020-12 constraint, so every published schema passes the 2020-12 meta-schema and compiles (in either dialect, at the keyword, before any credential rule, without its values): `required` or a `dependentRequired` list repeats a name; `allOf`, `anyOf`, `oneOf` or `prefixItems` is empty; `$anchor` or `$dynamicAnchor` is not an anchor name (`^[A-Za-z_][-A-Za-z0-9._]*$`); `$id` is not a string, `$schema` names anything but `https://json-schema.org/draft/2020-12/schema` (the only dialect the catalog publishes), or `$vocabulary` is not an object of booleans; a `pattern` or a `patternProperties` name is not an ECMA-262 regular expression in Unicode mode (the `u` flag 2020-12 validators compile it with, so `a\-b` is an error); `dependencies` or `$recursiveAnchor` is used (2020-12 replaces them with `dependentRequired`/`dependentSchemas` and `$dynamicAnchor`); `nullable` has no sibling `type`, or is `false` beside a type that includes `"null"`; `xml`, `externalDocs` or `discriminator` is not an object; a schema resource URI (an `$id` resolved against the enclosing one; `""` and `#` name the enclosing resource, or the document, again) is declared twice in the document, or an anchor name twice in one resource, reported at every declaration; a schema `enum` is empty or repeats a value (2020-12 only recommends a non-empty enum of distinct values, but OpenAPI 3.0 requires both and 2020-12 compilers reject an empty one, so the catalog rejects either in both dialects; values are compared as canonical JSON, so `{a: 1, b: 2}` repeats `{b: 2, a: 1}`), reported at the `enum` without its values and before any credential rule withholds it; a security scheme lacks a valid `type` or a member its type requires (as in OpenAPI 3.0/3.1: `apiKey` needs `name` and `in` of `query`, `header` or `cookie`; `http` needs `scheme`; `openIdConnect` needs `openIdConnectUrl`; `oauth2` needs `flows` with at least one of `implicit` (needs `authorizationUrl`), `password` and `clientCredentials` (need `tokenUrl`) and `authorizationCode` (needs both), each with `scopes`, possibly empty; any other flow name except an `x-*` extension is an error), or has a member OpenAPI defines only for another type (`in` or `name` outside `apiKey`, `scheme` or `bearerFormat` outside `http`, `openIdConnectUrl` outside `openIdConnect`, `flows` outside `oauth2`): such a member is reported, never dropped, since it usually means a mistyped scheme, and `operation-catalog.v1` and the `CatalogSecurityScheme` type allow each member only on its own type; a parameter is declared twice at one level (header names case-insensitively); an identifier or map key holds a credential; a path-template parameter is undeclared or a declared path parameter is not in the template; a parameter lacks a name or valid `in`; an object lacks a member OpenAPI marks REQUIRED, reported at `<object>/<member>` of the resolved object at any link of a reference chain: a Request Body Object without `content` (an empty `content` map is valid and is published as no media types), a Response Object without `description`, a Parameter or Header Object (response and form-part headers too, except `Content-Type`, which OpenAPI ignores there) with neither `schema` nor `content`, or a Discriminator Object without `propertyName`; a response key is not a status, range or `default`; an OpenAPI 3.0 operation has no `responses`, or a Responses Object (3.0 or 3.1) holds no status, range or `default` key (`x-*` extensions do not count), reported at `<operation>/responses` for every bound operation, whatever its `sdk` and `agent` settings; a path does not start with `/`; a path item read for operations has a field other than `summary`, `description` or `x-*` beside its `$ref`, at any link of a reference chain (OpenAPI leaves their merge with the referenced path item undefined and the catalog does not merge them: move them into the referenced path item; the 3.0 upconversion still reads them as Path Item fields); a schema `$id` has a non-empty fragment (`#tag`, `https://…/meta#tag`), which JSON Schema 2020-12 forbids (use `$anchor`); a path or server URL template has a nested, empty, stray or unclosed brace (OpenAPI has no escape for a literal brace); a server lacks a URL, a variable lacks a default, a variable's `enum` is empty or does not hold its `default` (reported at `<server>/variables/<name>/default` without the value), the published URL uses a placeholder that no variable declares, or the whole URL is credential-like (a server is never published as `[REDACTED]`); `security` is not an array, a requirement is not an object, or its scopes are not an array of strings (malformed requirements never become anonymous access), or an OpenAPI 3.0 requirement lists scopes for an `apiKey`, `http` or `mutualTLS` scheme (3.0 allows them for `oauth2` and `openIdConnect` only; 3.1 allows role names there, which are kept) |
| `INVALID_MANIFEST` | the manifest is not an object (such as `null`); any manifest object is not a plain JSON object (a class instance, or fields inherited from a prototype, which serialization would drop); manifest shape error, including unknown (misspelled) fields; a name derived from a long operationId exceeds 128 characters (set `name`) |
| `MISSING_OPERATION_ID` | a spec operation has no manifest binding |
| `DUPLICATE_OPERATION_ID` | a stable ID is repeated, an operation is bound twice, or an OpenAPI operationId repeats |
| `UNMATCHED_OPERATION_BINDING` | a binding matches no spec operation |
| `NAME_COLLISION` | two names collide case- and underscore-insensitively (e.g. `getUser` / `get_user`) |
| `UNRESOLVED_REF` | a `$ref` is missing (every schema reference emitted into the catalog is checked, including those reached through a parameter, body or response outside `components`), external (bundle first), cyclic, resolves to a value of the wrong type (such as `null` or a string), or a schema ref or discriminator mapping target that is not `#/components/schemas/<name>` (including pointers into a component); a schema reference inside a schema that declares a resource `$id` (other than `""` or `#`), which JSON Schema 2020-12 would resolve against that `$id` instead of the document (the diagnostic names the `$id` by its pointer); a reference read as RFC 6901 section 6 reads a URI fragment (the whole fragment is percent-decoded, then split on `/`, then `~1` and `~0` are unescaped, so `#/a/b%2Fc` is member `c` of `b` of `a` while `#/a/b~1c` is member `b/c`) that is malformed (a bad percent escape or a `~` not followed by `0` or `1`); every segment counts (`#//a` is member `a` of member `""`) and array indices have no leading zeros; emitted references are written so that this reading returns the component name (see Catalog shape); references are checked by OpenAPI context, so property, header and component names are never mistaken for keywords and literal schema data is never a reference |
| `UNKNOWN_SECURITY_SCHEME` | a security requirement names an undeclared scheme |
| `UNSUPPORTED_SERIALIZATION` | no supported media type remains (error; dropped alternatives are warnings); two media types that normalize to the same type are described differently; a parameter or form encoding uses `content` or an unsupported style (the message says whether listing the type in the manifest helps or only a spec change does); the manifest lists an unsupported media type; or multipart part headers or response headers are dropped (warning) |
| `UNKNOWN_REPLACEMENT` | a deprecation replacement is not another catalog operation |

## Release descriptors

```ts
const { descriptor } = createReleaseDescriptor({
  catalog,
  generator: { name: "@apifn/sdk-typescript", version: "0.1.0" },
  artifacts: [{ kind: "sdk", target: "typescript", package: { name: "@example/projects-sdk", version: "2026.10.1" } }],
});
```

These version axes stay separate: `descriptorVersion`, `api.version`, `specDigest`, `manifestDigest`, `catalogDigest`, `generator.version`, each artifact's package version, and `releaseId`. Each artifact lists the stable operation IDs it exposes: SDK targets honor `sdk.include` and `excludeTargets`; `agent-tools` artifacts honor `agent.expose`. Without an explicit `releaseId`, the descriptor derives `rel_<24 hex>` from its content.

## Client-failure events

`validateClientFailureEvent(input)` returns `{ ok: true, event }` (canonical, round-trippable) or `{ ok: false, issues }`; it never throws, and non-plain objects (Maps, Dates, class instances, functions), cycles and nesting deeper than 256 levels are `TYPE` issues. Its cost is bounded by the event size limit, not by the input: reading stops as soon as the event exceeds 8192 bytes (`TOO_LARGE`, before any key or value is scanned), after 1,000,000 values (an array's length is checked before it is read) or after 32 problems. It reads the input once into a plain-data snapshot and validates and returns exactly that snapshot, so a getter cannot change a value after it was checked. Events (`apifn.client-failure/v1`) carry `eventId`, `occurredAt`, `api`, `operation {id, name?, method?, pathTemplate?}`, `release {releaseId, catalogDigest?, sdk?}`, `failure {kind, httpStatus?, errorCode?, message?, retryable?, attempt?}`, and optional `runtime`, `correlation` and `attributes`. The validator rejects, rather than trims, any of these:

- unknown fields, including `Object.prototype` names such as `constructor` or `__proto__`,
- credential-bearing keys (`authorization`, `cookie`, `*token*`, `*secret*`, `*password*`, `*api_key*`, …, with `_`, `.` or `-` anywhere inside, as in `pass_word`) and keys that hold a credential; the schema's `propertyNames` pattern is generated from the same fragment list,
- an attribute that is the value field of another attribute naming a credential (`attributes: {name: "X-Api-Key", value: "…"}`), as the same pair is in `failure.message`,
- credential-like values; fields restricted to an identifier pattern (`errorCode`, IDs, versions, names) use the identifier rule, where `:` is a namespace separator (`token:expired` is a valid `errorCode`, `token=abc123` is not),
- path templates with query strings,
- `occurredAt` values that are not real UTC calendar dates and times (second `60` only at 23:59:60 on 30 June or 31 December, when leap seconds are inserted),
- fields over their UTF-8 byte limits (message 1024, attribute value 256, at most 32 attributes),
- events over 8192 bytes serialized.

## Verification

```bash
npx turbo run build typecheck test lint --filter=@apifn/contracts...
npm run build --workspace @apifn/contracts && npm run verify:packed --workspace @apifn/contracts
```

`verify:packed` packs the workspace, installs the tarball into a clean temp project outside the monorepo, and imports the ESM and CJS exports there. It also checks that the `failure-event` graph has no `@apifn/core` or Node built-ins. Set `UPDATE_FIXTURES=1` when running tests to regenerate committed fixtures after an intentional contract change.
